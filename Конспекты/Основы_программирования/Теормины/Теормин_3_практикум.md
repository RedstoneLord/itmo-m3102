# Теормин 3. Практикум, самопроверка и памятка к сдаче

Теория: [Теормин 3 — простыми словами](https://github.com/RedstoneLord/itmo-m3102/blob/master/Конспекты/Основы_программирования/Теормины/Теормин_3_простыми_словами.md). Здесь — 20 задач с отдельными решениями, интерактивные тесты и короткая памятка по всем 17 темам. Все языковые вопросы относятся к **C++20**, если явно не сказано другое.

**Как решать:** сначала определите, компилируется ли код. Если да — проверьте инициализацию, границы, время жизни и владение. Только для корректного кода вычисляйте результат. Для UB ответ «у меня напечаталось 7» не считается объяснением.

В задачах фрагменты внутри функции предполагают обычный контекст `main` и необходимые стандартные заголовки, указанные в теории. Не запускайте намеренно ошибочный код как способ доказать его правильность.

## Задачи: сначала попробуйте без ответов

### 1. Чья это память?

```cpp
int global = 7;

    static int calls;
    int local = 3;
    int* p = new int{9};
    const char* text = "hello";
    delete p;

```

### 2. Два имени или два объекта?

### 20. Кадр x86-64

Для учебной модели обычный near `call` выполнен при `RSP = 0x1000`. Затем функция исполнила:

```asm

mov  rbp, rsp
sub  rsp, 32
```

Все push/call здесь используют 8 байт. Чему равны RSP и RBP после пролога? Где лежат адрес возврата и сохранённый RBP? На какой адрес указывает `[rbp - 4]`? Есть ли аналогичный обязательный регистр вершины кучи?

## Решения задач

### 1. Два уровня описания

`global`, `zero`, `calls` имеют статическую длительность хранения: обычно `.data`, `.bss`, `.bss` соответственно. Имя `calls` локально, но его хранилище не исчезает при выходе. `local`, `p`, `text` — автоматические объекты, обычно стек или регистры. Объект int по адресу `p` — динамический; он уничтожен строкой `delete p`. Литерал `"hello"` имеет статическую длительность хранения и обычно лежит в `.rodata`. При выходе заканчивается жизнь автоматических объектов. Обязательных размещений в секциях или регистрах стандарт языка не задаёт.

### 2. Привязка не меняется

`r = b` присваивает `a` значение 2. Затем `*p += 3` меняет `a` на 5. После `p = &b` запись `*p = 8` меняет `b`. Итого: `a == 5`, `b == 8`, `r == 5`, `p == &b`. Объектов int два: `a` и `b`; ссылка не создаёт третий. Сам `p` — отдельный объект указательного типа.

### 3. Меняется цель, но не копировавшийся указатель

`value == 5`, а исходный `p` по-прежнему равен `&value`. Параметр — копия адреса: через него можно изменить общий объект, но `p = nullptr` меняет только эту копию. Тип `int*&` позволил бы изменить указатель вызывающего кода; сам по себе такой интерфейс не организует освобождение.

### 4. Проверяем до присваивания

```cpp
void* next = std::realloc(p, 100 * sizeof(int));
if (next == nullptr) {
    std::free(p);
    return 1;
}
p = static_cast<int*>(next);
std::free(p);
```

При отказе старый блок остаётся выделенным. В исходной версии его адрес затирался nullptr. При успехе дальше используем только возвращённый указатель и заново полученные от него адреса элементов. Даже совпадение числового адреса не разрешает использовать прежние указатели. Новая часть блока не инициализирована.

### 5. Правильная только последняя строка

Для `a` нужен `delete`, для `b` — `delete[]`, для `c` — `free`, для `d` — `delete[]`. Исходные четыре освобождения дают UB. Массив из одного элемента всё равно получен через массивную форму new. `delete e` для nullptr допустим. Отдельно: запрос `malloc(4)` не следует считать универсальным размером int — обычно нужно `sizeof(int)`.

### 6. Объект уничтожен, копия адреса осталась

После delete объект int закончил жизнь и его хранилище освобождено. `q` остался висячим; чтение `*q` — use-after-free и UB. Присваивание nullptr переменной `p` не меняет другую переменную `q`. Обещать конкретный вывод или обязательное падение нельзя.

### 7. Буфер есть, объекта уже нет

Буфер существует до конца своего блока. `Item` уже уничтожен, читать его поле нельзя. `delete p` недопустим: блок не выделен обычным new. `alignas(Item)` обеспечивает подходящий адрес начала хранилища. Чтобы снова использовать его как Item, нужно корректно создать следующий объект и работать с результатом нового placement new.

### 8. Вернуть значение

В конце вызова `local` уничтожается, результат-ссылка становится висячим. Корректная версия:

```cpp
std::string Name() {
    return std::string{"M3102"};
}
```

Это возвращает объект по значению. Для такого однотипного prvalue результат строится непосредственно на стороне результата по правилам C++17+.

### 9. Продление не передаётся по цепочке

Цель `a` жива до конца жизни локальной ссылки `a`. Временная строка `"B"` жива до конца полного выражения с вызовом `Echo`, то есть до точки с запятой во второй строке объявления. После неё `b` — висячая. Возвращённая ссылка не продлевает жизнь объекта повторно. Само наличие висячей ссылки ещё не означает, что уже выполнено чтение её цели; ошибка возникает при недопустимом использовании.

### 10. auto без & создаёт значение

`a` имеет тип `int`, `b` — `int&`. Итог: `a == 5`, `x == 7`, `b == 7`. Начальное чтение `r` берёт значение x; лишь явный `auto&` сохраняет ссылочную связь.

### 11. Не размер разницы, а категория преобразования

`F('x')` выбирает int, `F(2.0F)` — double, `F(2)` — int. Для char → int и float → double действуют promotions, а в третьем случае есть точное совпадение. `G(2.0)` неоднозначен: double → int и double → float — стандартные преобразования одинакового ранга, ни одно не выигрывает. Можно передать `2.0F` либо добавить перегрузку double, если она нужна интерфейсу.

### 12. Единственной лучшей функции нет

`Draw(1)` неоднозначен. Default-аргумент не делает вторую функцию менее подходящей. Можно оставить только `Draw(int, int = 0)`, либо убрать default у двухаргументной версии, либо развести разные действия по разным именам. Выбор определяется желаемым интерфейсом.

### 13. Различаем объявление функции и переменной

`a` — объект int без заданного значения, читать до присваивания нельзя. `b` — объект int с нулём. `c` — функция без аргументов, возвращающая int. `d` — объект int со значением 3. `e` — ошибка компиляции из-за narrowing. `v` содержит `{7, 7, 7}`, `w` — `{3, 7}`.

### 14. Обратный порядок выхода

Вывод: `+A+B-B+C-C-A`. Объект B уничтожается при выходе из вложенного блока, C и A — при выходе из main в обратном порядке. У полей класса порядок определяется **объявлениями полей**, а не перестановкой элементов списка инициализации конструктора.

### 15. Чтение управляет циклом

EOF не предсказывает успех следующего чтения. Кроме того, Process получает 16, даже если прочитано меньше: он обрабатывает лишние/старые байты. Правильная основа:

```cpp
std::size_t n;
while ((n = std::fread(buffer, 1, sizeof(buffer), file)) != 0) {
    Process(buffer, n);
}
bool failed = std::ferror(file) != 0;
if (std::fclose(file) != 0) failed = true;
```

Вызывающий код должен обработать `failed`. Если тело цикла пишет в другой файл, дополнительно проверяются запись и закрытие выходного файла.

### 16. Рисуем строки и считаем

Полезная строка: `5 * 3 = 15` байт. Stride: `((15 + 3) / 4) * 4 = 16`, padding: 1. Пиксели: `16 * 3 = 48` байт, минимальный файл: `54 + 48 = 102` байта.

Положительная высота задаёт bottom-up, значит верхняя строка имеет номер 2 в файле. Смещение `(2, 0)` — `54 + 2 * 16 + 2 * 3 = 92`. Красный: `00 00 FF`. При высоте `-3` верхняя строка первая, смещение — `54 + 0 * 16 + 2 * 3 = 60`.

### 17. Формат файла не зависит от компилятора

Компилятор может вставить padding, в частности после первого 16-битного поля, и получить sizeof не 14. Упаковка не решает endianness, поддержку вариантов DIB, проверку прочитанного размера и полей. Нужны явный разбор чисел little-endian и валидация. Содержимое файла нельзя считать корректным только потому, что оно поместилось в структуру.

### 18. Адрес не равен владению

Неявное копирование копирует `data_`: два объекта пытаются удалить один блок. По правилу нуля владение можно поручить vector. Не используйте для четырёх нулей запись `std::vector<int> data_{4, 0};`: она создаёт два элемента `{4, 0}`. Правильная версия:

```cpp
class Buffer {
public:
    Buffer() : data_(4, 0) {}
private:
    std::vector<int> data_;
};
```

Альтернатива для единственного владельца — `std::unique_ptr<int[]>` и запрет/отсутствие копирования. Если оставлен raw-указатель, можно явно написать `Buffer(const Buffer&) = delete;` и `Buffer& operator=(const Buffer&) = delete;`: тогда копирование отвергается компилятором. Для полноценного копирования нужно выделять собственный блок и копировать элементы с корректной обработкой ошибок.

### 19. Сначала предусловие, потом разыменование

После неудачного EXPECT тело теста продолжится и разыменует nullptr. Используйте ASSERT для обязательного предусловия и RAII для владения:

```cpp
TEST(ImageTest, FirstPixel) {
    std::unique_ptr<Image> image{LoadImage("sample.bmp")};
    ASSERT_NE(image, nullptr);
    EXPECT_EQ(image->Width(), 5);
}
```

Объект будет освобождён и при выходе из теста через ASSERT. Нужны `<memory>`, `<gtest/gtest.h>` и объявления Image/LoadImage. Для содержимого C-строк — `EXPECT_STREQ`, для значений std::string подходит `EXPECT_EQ`.

### 20. Считаем в hex

После call RSP = `0x0FF8`, там адрес возврата. После `push rbp` RSP = `0x0FF0`, там сохранён старый RBP. `mov rbp, rsp` задаёт RBP = `0x0FF0`. `sub rsp, 32` вычитает `0x20`, итоговый RSP = `0x0FD0`. `[rbp - 4]` обозначает память по `0x0FEC`. Адрес возврата лежит по `[rbp + 8]`, сохранённый RBP — по `[rbp]`. Универсального обязательного регистра вершины кучи нет.

Это арифметическая учебная модель. В настоящем вызове нужно также соблюдать выравнивание стека по ABI и другие соглашения платформы.

## Интерактивный тест: память и время жизни

Вопросы с несколькими правильными ответами требуют отметить все подходящие варианты. Пояснения раскрывают причину ответа, а не только называют его.

```quiz

- [ ] Это обязательно одна ячейка RAM :: Отображения задаются для каждого адресного пространства.
- [ ] Такой адрес запрещён второму процессу :: Повторение адресов между процессами допустимо.

? Какие утверждения о памяти процесса верны?
- [x] Потоки одного процесса делят адресное пространство
- [x] У каждого потока собственные регистры и стек вызовов
```

## Памятка: что суметь объяснить за 30–60 секунд
