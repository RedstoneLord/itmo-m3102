# Осенний LiveCoding: приёмы C++ для самостоятельной подготовки

## Что изучать и как пользоваться конспектом

Здесь собраны приёмы для двух осенних заданий: **подсчёт частотных слов** и **Wordle**. Начнём с синтаксиса классов и владения памятью, затем свяжем C-строки, структуры, аргументы командной строки, файловый ввод, выделение слов, подсчёт и интерактивный ввод.

Читайте объяснения, прослеживайте примеры и выполняйте упражнения самостоятельно. Блоки с пометкой **«Полный пример»** можно компилировать отдельно. Остальной код — объявления или фрагменты, показывающие отдельный приём. Итоговые программы и полная реализация вектора остаются упражнениями.

Это русская альтернатива конспекту `Техники_для_осеннего_LiveCoding.md`, расположенному в этой же папке.

| Задание | К чему подготовиться |
|---|---|

В обоих заданиях запрещены стандартные контейнеры, `std::string` и `std::string_view`. Запрет не распространяется на всю стандартную библиотеку: здесь пригодятся функции из `<cstdio>`, `<cstring>` и `<cstdlib>`. Проверяйте ограничения именно того задания, которое получили.

## 1. Массивы, указатели, ссылки и const

### Массив и указатель

```cpp
int values[3] = {10, 20, 30};
int* pointer = values;

pointer[1] = 99; // теперь values[1] равно 99
```

`values` — массив из трёх целых чисел. `pointer` — отдельная переменная, хранящая адрес первого числа. Второй массив при этом не создаётся.

| Выражение | Что означает |
|---|---|
| `&values[0]` | Адрес первого элемента |
| `*pointer` | Элемент по адресу, который хранится в `pointer` |
| `pointer[i]` | Элемент со смещением `i` от этого адреса |
| `pointer + 1` | Адрес следующего целого числа, а не следующего байта |
| `nullptr` | Значение указателя, который не указывает на объект |

Для массива из трёх элементов допустимы индексы `0`, `1` и `2`. Адрес сразу после массива можно сформировать для обхода, но читать или записывать элемент по этому адресу нельзя.

### Ссылки и передача параметров

```cpp
int number = 5;
int& alias = number;
alias = 8; // изменяет number
```

Ссылка — другое имя существующего объекта. Её нужно сразу инициализировать; позднее нельзя перенаправить её на другой объект. Присваивание через ссылку изменяет исходный объект.

```cpp
void inspect(const int& value); // читает исходный объект
void modify(int& value);        // может изменить исходный объект
void receiveCopy(int value);    // получает отдельное целое число
```

Небольшие целые числа обычно удобно передавать по значению. Для структур и классов, владеющих памятью, ссылки позволяют избежать копирования и показать, разрешено ли изменение.

### К чему относится const

```cpp
const int* readable = &number; // нельзя менять number через readable
int* const fixed = &number;    // нельзя менять адрес в fixed
```

Первый указатель можно перенаправить. Через второй можно изменять число, на которое он указывает. Запись `const int* const` объединяет оба ограничения.

### sizeof и массивы в параметрах функций

```cpp
char text[] = "hello";
char* p = text;

// sizeof(text) равно 6: пять букв и завершающий ноль.
// sizeof(p) — размер указателя, а не длина строки.
```

В обычном параметре функции запись `char buffer[]` преобразуется в `char* buffer`. Функция не получает вместимость исходного массива автоматически:

```cpp
void fill(char* buffer, std::size_t capacity);
```

`std::size_t` из `<cstddef>` — беззнаковый тип для размеров. Следите за смешиванием знаковых и беззнаковых чисел: вычитание единицы из беззнакового нуля даёт большое значение.

:::warning
Указатель или ссылка пригодны для доступа только пока существует объект, на который они ссылаются. Нельзя возвращать адрес локальной переменной или пользоваться адресами внутри массива после удаления либо замены его памяти.
:::

**Практика:** напишите функцию обмена двух целых чисел через ссылки. Затем — функцию заполнения массива, получающую его вместимость отдельным параметром.

## 2. Объявление класса и его методов

### Поля и доступ

Класс объявляет состояние каждого объекта и доступные операции. Все члены после метки доступа сохраняют этот доступ до следующей метки.

| Метка | Кто имеет доступ |
|---|---|
| `private` | Члены класса и его друзья |
| `protected` | Также производные классы с учётом правил наследования |
| `public` | Код, использующий объект |

В векторе указатель, длину и вместимость стоит сделать закрытыми, а поддерживаемые операции — открытыми. Наследование и `protected` для этих заданий не нужны. `struct` похож на `class`, но по умолчанию его члены открыты, а у `class` — закрыты.

### Полный пример: небольшой класс

```cpp
#include <cstdio>

class Counter {
private:
    int value_;

public:
    Counter() : value_(0) {}
    explicit Counter(int initial) : value_(initial) {}

    ~Counter() = default;

    int value() const {
        return value_;
    }

    void add(int amount) {
        value_ += amount;
    }
};

int main() {
    Counter counter(4);
    counter.add(3);
    std::printf("%d\n", counter.value());
}
```

У обычного метода есть возвращаемый тип, имя, параметры и тело. Тип `void` означает отсутствие возвращаемого значения. Метод объекта вызывают через `.`, метод через указатель на объект — через `->`.

### Конструкторы, инициализация и уничтожение

Имя конструктора совпадает с именем класса; возвращаемого типа у него нет. Список инициализации после `:` инициализирует поля до выполнения тела. Поля инициализируются в порядке их объявления в классе, независимо от порядка в списке.

`explicit` у конструктора с одним аргументом запрещает нежелательные неявные преобразования к вашему классу. Прямое создание `Counter c(4);` остаётся допустимым.

Деструктор называется `~Counter`, не принимает параметров и не имеет возвращаемого типа. Он вызывается при завершении времени жизни объекта. `= default` просит компилятор сгенерировать стандартное поведение; счётчику дополнительная очистка не нужна. Вектору, владеющему массивом, нужен деструктор, освобождающий выделенную память.

### Определение внутри и снаружи класса

Объявление метода находится внутри класса. Определение можно написать там же или снаружи, указав имя класса:

```cpp
class Meter {
private:
    int reading_;

public:
    explicit Meter(int reading);
    int reading() const;
};

Meter::Meter(int reading) : reading_(reading) {}

int Meter::reading() const {
    return reading_;
}
```

Для обычных нешаблонных классов объявления часто размещают в `.h`, а определения снаружи класса — в `.cpp`. Заголовочному файлу обычно нужна защита от повторного включения: include guard или `#pragma once`. После определения класса ставится `;`.

### this и константные методы

Внутри нестатического метода `this` указывает на текущий объект. Можно написать `this->reading_` или просто `reading_`. Выражение `*this` обозначает сам объект. Запись `this.reading_` неверна: `this` — указатель.

Завершающий `const` объявляет метод, который читает состояние:

```cpp
int reading() const;
```

Его можно вызвать у константного объекта; менять обычные поля через `this` он не может. Но константность объекта не делает автоматически константной память, на которую указывает его поле-указатель. Это обещание нужно поддерживать в реализации методов.

**Практика:** напишите класс с одним закрытым целым полем, двумя конструкторами, методом чтения и методом изменения. Один метод определите снаружи класса.

## 3. Динамическая память и собственный вектор

### Выделение памяти и владение

```cpp
int* single = new int(7);
delete single;

int* array = new int[20];
delete[] array;
```

Парой к `new` служит `delete`, к `new[]` — `delete[]`. Не смешивайте их с `malloc` и `free`. У каждого выделенного блока должен быть понятный владелец, который освобождает его ровно один раз.

`new int[20]` оставляет числа неинициализированными. `new int[20]{}` заполняет их нулями. Удалять нулевой указатель безопасно; повторно освобождать уже освобождённый блок — нет. Удаление не присваивает переменной-указателю `nullptr` автоматически.

### Состояние и инварианты

Вектору целых чисел нужны указатель, длина и вместимость:

```cpp
int* arr_;
int len_;
int cap_;
```

Поддерживайте условие:

$$
0 \leq \text{len} \leq \text{cap}.
$$

Первые `len_` ячеек содержат логические элементы вектора. Остальные — запас места для будущих добавлений. Удобное состояние по умолчанию: `nullptr`, `0`, `0`.

```array
title: Длина и вместимость
caption: Три элемента занимают индексы от 0 до 2; выделенный индекс 3 — следующая свободная ячейка.
[10, 20, 30, "свободно", "свободно"] highlight: 3 sorted: 0,1,2
```

### Сначала определите интерфейс

Это набросок интерфейса, а не готовая реализация:

```cpp
class Vector {
private:
    int* arr_;
    int len_;
    int cap_;

public:
    Vector();
    explicit Vector(int capacity);
    Vector(int count, int initial);
    ~Vector();

    Vector(const Vector& from);
    Vector& operator=(const Vector& from);

    int size() const;
    int capacity() const;
    int& operator[](int index);
    const int& operator[](int index) const;

    void reserve(int requested);
    void push_back(int value);
    int pop_back();
    void clear();
};
```

В этом интерфейсе конструктор с одним аргументом резервирует память, но оставляет вектор пустым. Конструктор с двумя аргументами создаёт `count` элементов. Это ваш выбор интерфейса: `std::vector<int>(count)` создаёт именно указанное количество элементов.

Первый `operator[]` возвращает ссылку, поэтому возможна запись `v[0] = 42;`. Константная перегрузка возвращает ссылку, через которую нельзя изменить элемент. При непроверяемом доступе вызывающий код обязан передать допустимый индекс существующего элемента. Отдельный метод `at()` может проверять индекс и сообщать об ошибке.

### Конструктор копирования и копирующее присваивание

```cpp
Vector a(3, 7);
Vector b = a; // конструирование копированием: создаётся b
Vector c(a); // тоже конструирование копированием
b = a;       // присваивание: b уже существует
```

Передача существующего вектора в функцию по значению тоже может вызвать копирование. Параметр `const Vector&` даёт доступ для чтения без создания копии.

Копирование одного `arr_` копирует адрес. Два владельца начнут использовать один блок и оба попытаются удалить его. При глубоком копировании выделяется отдельный массив, в который копируются первые `from.len_` элементов. Метод `Vector` имеет доступ к закрытым полям другого объекта `Vector`.

Деструктор, конструктор копирования и копирующий оператор присваивания образуют **правило трёх** для этого класса-владельца. В операторе присваивания `return *this;` возвращает изменённый объект по ссылке. Самоприсваивание проверяют сравнением `this` с `&from`.

### Сначала выделить замену, затем освободить старое

И при росте массива, и при подготовке независимой копии для присваивания удобно придерживаться порядка:

1. Вычислить и проверить новую вместимость в локальной переменной.
2. Выделить новый блок, сохранив его во временный указатель.
3. Скопировать существующие целые элементы.
4. Освободить старый массив.
5. Установить новый указатель, длину и вместимость.

:::warning
Обычный `new[]` сообщает о неудаче выделения памяти исключением. Если сначала удалить старый массив, то при исключении `arr_` может остаться адресом освобождённой памяти, которую позднее снова удалит деструктор. Если заранее изменить `cap_`, вместимость может начать описывать несуществующий блок. Подготовка нового состояния до замены предотвращает обе ошибки.
:::

Присваивание целых элементов само по себе не бросает исключений. Для произвольных типов элементов понадобятся дополнительные правила времени жизни и обработки исключений; это следующая тема.

### Рост массива и изменение длины

| Операция | Требуемое поведение |
|---|---|
| `reserve(n)` | Расти только при необходимости; сохранять длину и элементы |
| `push_back(x)` | Обеспечить место, записать в `arr_[len_]`, увеличить длину |
| `pop_back()` | Обработать пустой вектор, уменьшить длину, прочитать удалённое число |
| `clear()` | Для вектора целых чисел обнулить длину и сохранить память |
| Деструктор | Освободить массив; обнуление полей после этого не требуется |

Для удаления из пустого вектора выберите контракт. Можно потребовать от вызывающего кода сначала проверять `size()`, а можно явно сообщать о неправильном вызове. Проверяемая версия может использовать такую инструкцию из `<stdexcept>`:

```cpp
throw std::out_of_range("Vector is empty");
```

Выброс исключения завершает текущую операцию без возврата целого числа. Вызывающий код может обработать исключение через `try` и `catch`; необработанное исключение приводит к завершению программы. Функция с результатом `int` не может использовать пустой `return;`, а ноль в качестве ошибки неоднозначен: он может быть настоящим элементом. Этот контракт отделён от ошибки выделения памяти: предварительная подготовка нового блока сохраняет старый массив и при распространении исключения к вызывающему коду.

Для первого добавления выберите положительную вместимость: удвоение нуля оставляет ноль. Геометрический рост, например удвоение, позволяет не выделять память при каждой вставке. При вместимости типа `int` проверяйте возможность удвоения до вычисления, чтобы избежать переполнения знакового числа. Отрицательные вместимости нужно отвергать до выделения памяти.

Выражение `arr_[len_++]` использует старую длину, затем увеличивает её. `arr_[--len_]` сначала уменьшает длину. Перед такими сокращениями проследите индексы вручную. Запись `this[index]` индексирует указатель на объект вектора, а не его внутренний массив; используйте `arr_[index]` или `(*this)[index]`.

После перевыделения памяти старые указатели и ссылки на элементы недействительны. Нельзя сохранять ссылку вида `int& saved = v[0];` и пользоваться ею после операции, которая могла увеличить массив.

:::note
Конструктор перемещения и перемещающий оператор присваивания расширяют правило трёх до правила пяти: они передают владение вместо копирования элементов. Это полезная следующая тема, но для осенних заданий она не обязательна. Шаблонный вектор и сырая память с отдельным конструированием тоже могут подождать: `new T[capacity]` конструирует каждую выделенную ячейку и имеет другие требования, чем полноценный `std::vector`.
:::

**Практика:** реализуйте интерфейс по частям. Проверьте пустое создание, рост из нулевой вместимости, переход через границу вместимости, независимость копии, присваивание поверх существующего массива, самоприсваивание и удаление из пустого вектора. ## 4. C-строки и массивы записей о словах

### Завершающий ноль

```cpp
char word[] = "cat"; // {'c', 'a', 't', '\0'}
char buffer[100];   // пока не является инициализированной строкой
char empty[100]{};  // изначально пустая строка
```

`'\0'` — нулевой символ, а не цифра `'0'`. Для C-строки из 100 однобайтовых букв нужна как минимум 101 ячейка.

```cpp
char greeting[10];
greeting[0] = 'h';
greeting[1] = 'i';
greeting[2] = '\0';
```

### Библиотечные функции

Подключите `<cstring>`.

| Функция или выражение | Назначение |
|---|---|
| `std::strlen(s)` | Число символов до завершающего нуля |
| `std::strcmp(a, b) == 0` | Равенство содержимого строк |
| `std::strcmp(a, b) < 0` | Первая строка раньше второй в побайтовом лексикографическом порядке |
| `std::memcpy(dst, src, n)` | Копирование ровно `n` байт между непересекающимися областями |

`strcmp` возвращает отрицательное число, ноль или положительное число; не требуйте именно `-1` или `1`. Операция `==` между двумя указателями сравнивает адреса, а не текст.

Независимую копию корректной строки можно создать так:

```cpp
std::size_t length = std::strlen(source);
char* copy = new char[length + 1];
std::memcpy(copy, source, length + 1);
// Используйте copy; позднее обязательно выполните delete[] copy.
```

Дополнительный байт нужен для терминатора. Места в приёмнике должно быть достаточно. `strcpy` тоже копирует терминатор, но не знает вместимости приёмника. `strncpy` не служит универсальной безопасной заменой: результат может остаться без терминатора. Проверку длины с последующим явным копированием проще обосновать.

:::warning
Строковые функции ищут завершающий ноль. Передача незавершённого буфера в `strlen`, `strcmp` или вывод через `%s` может привести к чтению за границами памяти. Блок, прочитанный через `fread`, не становится C-строкой автоматически.
:::

### Встроенные массивы и поля-указатели

```cpp
struct WordCount {
    char word[1025];
    int count;
};
```

Эта структура непосредственно содержит массив символов. Выбранная вместимость допускает до 1024 однобайтовых символов и терминатор. Присваивание структуры копирует и встроенный массив, и число. Массив таких записей можно увеличивать по тем же принципам владения, что и вектор целых чисел, но его элементами будут структуры.

Другой вариант:

```cpp
struct OwnedWord {
    char* word;
    int count;
};
```

Здесь стандартное копирование копирует адрес. Нужно решить, владеет ли структура строкой, и обеспечить соответствующие освобождение и копирование. Обычное поле-указатель не получает владение автоматически.

| Представление | Что хранится |
|---|---|
| `char words[20][101]` | Двадцать строк массива, каждая с местом под C-строку |
| `char* words[20]` | Двадцать указателей; память под слова этим объявлением не выделяется |
| `WordCount* entries` | Адрес записей; отдельно нужны выделение памяти и количество использованных записей |

Повторное сохранение адреса переиспользуемого буфера сохраняет несколько обращений к одной памяти, а не независимые слова. Копируйте слово до перезаписи буфера. Не храните адреса внутри временных буферов или записей, память которых будет перевыделена.

### Приведение регистра

Функции классификации, например `std::isalpha`, имеют то же требование к допустимым аргументам: значение символа передают через `unsigned char`. Поведение зависит от текущей C-локали. Такая побайтовая обработка подходит для базового английского алфавита, но не реализует Unicode-преобразование регистра UTF-8.

Приводите регистр одинаково до сравнения и сохранения слов. Сохраняйте пунктуацию, если условие не требует её удалять: в задаче о частотных словах заданы разделители, но не правило очистки от знаков препинания.

## 5. Аргументы командной строки, числа и пути

### argc и argv

```cpp
int main(int argc, char* argv[])
```

При обычном запуске `argc` считает аргументы вместе с записью имени программы. Пользовательские аргументы находятся в `argv[1]` — `argv[argc - 1]`; `argv[argc]` — нулевой указатель.

```bash
./program --input "my text.txt" --top 3
```

Получаются пять записей: имя программы, `--input`, `my text.txt`, `--top` и `3`. Оболочка убирает кавычки и сохраняет путь одним аргументом.

Имена параметров сравнивайте через `strcmp`. Перед чтением `argv[i + 1]` убедитесь, что значение существует. Определите поведение при неизвестных параметрах, пропущенных обязательных параметрах и повторах. Для позиционных аргументов проверьте количество и используйте указанные в условии позиции.

### Полный пример: проверяемое преобразование в положительное целое

```cpp
#include <cerrno>
#include <climits>
#include <cstdio>
#include <cstdlib>

bool parsePositiveInt(const char* text, int& result) {
    errno = 0;
    char* end = nullptr;
    long value = std::strtol(text, &end, 10);

    if (end == text || *end != '\0' || errno == ERANGE ||
        value <= 0 || value > INT_MAX) {
        return false;
    }

    result = static_cast<int>(value);
    return true;
}

int main(int argc, char* argv[]) {
    int value = 0;
    if (argc != 2 || !parsePositiveInt(argv[1], value)) {
        std::fprintf(stderr, "Ожидается одно положительное целое число\n");
        return 1;
    }
    std::printf("%d\n", value);
}
```

`end == text` означает, что не удалось прочитать ни одной цифры. Ненулевой символ по адресу `end` указывает на оставшийся суффикс. `ERANGE` сообщает о выходе за диапазон `long`; дополнительная верхняя граница защищает преобразование в `int`. Функция допускает начальные пробельные символы и необязательный плюс, которые принимает `strtol`. Если условие разрешает только цифры, такую форму нужно проверить отдельно. Справочник: [strtol](https://en.cppreference.com/cpp/string/byte/strtol).

В отличие от `atoi`, этот способ позволяет отличить некорректный ввод от настоящего нуля. Допустимый диапазон выбирает приложение: функция выше требует положительное значение, но это не универсальное правило для любого числового параметра.

### Пути и время жизни

`argv[i]` уже является C-строкой, пригодной для `fopen`; специальный класс для пути не нужен. Строки аргументов доступны во время исполнения программы. Их можно использовать без копирования, но нельзя удалять.

Абсолютный путь задаёт положение от корня файловой системы. Относительный отсчитывается от текущей рабочей папки программы; она может не совпадать с папкой исполняемого файла.

## 6. Чтение файлов через FILE, fgetc, fgets и fread

### Открытие и закрытие

Подключите `<cstdio>` и используйте `std::FILE*`, возвращаемый `std::fopen`.

| Режим | Действие |
|---|---|
| `"r"` | Открыть существующий текстовый файл для чтения |
| `"rb"` | Открыть существующий файл для побайтового чтения в двоичном режиме |
| `"w"` или `"wb"` | Создать или обнулить файл для записи |
| `"a"` или `"ab"` | При необходимости создать файл и дописывать в конец |

Перед чтением проверьте результат на `nullptr`. Закрывайте каждый успешно открытый файл на всех путях выхода. Если операция сообщает об ошибке через `errno`, `std::perror("input")` выводит её системное описание в стандартный поток ошибок.

Двоичный режим отключает текстовое преобразование переводов строк в системах, где режимы различаются. Читать текст в нём можно: просто парсер получает сохранённые байты. Не предполагайте, что любое окончание строки занимает один байт.

### fgetc: один символ за вызов

```cpp
int ch;
while ((ch = std::fgetc(file)) != EOF) {
    // Обработать прочитанный символ.
}
```

До проверки `EOF` храните результат в `int`. Успешное чтение возвращает символ, преобразованный через `unsigned char` в `int`. `EOF` — отдельное отрицательное значение макроса, а не переносимая запись конкретного числа, например `-1`.

После цикла проверьте `std::ferror(file)`, чтобы отличить ошибку от обычного конца файла. Признак конца устанавливается при попытке чтения, встретившей конец; поэтому не используйте `while (!std::feof(file))` как основное условие чтения.

Посимвольный код прост для понимания, а C-потоки обычно уже буферизуются внутри библиотеки. Это подходящий первый вариант; блочное чтение позволяет обрабатывать несколько байт за один библиотечный вызов.

### fgets: ограниченный фрагмент с терминатором

```cpp
char line[128];
while (std::fgets(line, sizeof line, file) != nullptr) {
    // При успешном чтении результат завершается '\0'.
}
```

В буфер вместимостью 128 помещается не более 127 символов и терминатор. Перевод строки сохраняется, если был прочитан. Длинная строка разбивается между вызовами: успешное чтение не обязательно даёт целую строку файла. При неудаче не обрабатывайте старое содержимое буфера. Справочник: [fgets](https://en.cppreference.com/cpp/io/c/fgets).

### fread: явное количество байт

Аргументы: приёмник, размер одного элемента, запрошенное количество элементов, поток. Возвращается число полностью прочитанных элементов. При размере элемента один результат соответствует количеству байт.

```cpp
char buffer[4096];
std::size_t count = std::fread(buffer, 1, sizeof buffer, file);
```

Обрабатывайте только первые `count` байт. `fread` не выделяет слова и не добавляет `\0`. Последнее успешное чтение может заполнить только часть буфера. Справочник: [fread](https://en.cppreference.com/cpp/io/c/fread).

### Полный пример: подсчёт байт в файле

```cpp
#include <cstdio>

int main(int argc, char* argv[]) {
    if (argc != 2) {
        std::fprintf(stderr, "Использование: byte_count PATH\n");
        return 1;
    }

    std::FILE* file = std::fopen(argv[1], "rb");
    if (file == nullptr) {
        std::perror("input");
        return 1;
    }

    char buffer[4096];
    std::size_t count;
    std::size_t total = 0;
    while ((count = std::fread(buffer, 1, sizeof buffer, file)) > 0) {
        total += count;
    }

    bool failed = std::ferror(file) != 0;
    if (std::fclose(file) != 0) {
        failed = true;
    }
    if (failed) {
        std::fprintf(stderr, "Ошибка работы с файлом\n");
        return 1;
    }

    std::printf("%zu\n", total);
}
```

Буфер — локальный массив, для него не нужен `delete[]`. Пример считает байты, а не символы Unicode. Как и любой счётчик конечного размера, `total` должен вмещать полный размер обрабатываемого файла.

:::warning
Используйте только действительную часть буфера, возвращённую чтением. Ни ограничение длины строки, ни вместимость массива не определяют размер последнего прочитанного фрагмента. Ограничение строки в 1024 символа не ограничивает весь файл 1024 байтами.
:::

**Практика:** реализуйте счётчик байт через `fgetc`, затем через `fread`. Проверьте пустой файл и файл, размер которого не делится на вместимость буфера.

## 7. Выделение слов на границах буферов

### Чтение и разбор — разные уровни

Чтение поставляет байты; парсер определяет начала и окончания слов. Слово может пересекать границу чтения:

```text
чтение 1: "one ele"
чтение 2: "phant two"
слова:    "one", "elephant", "two"
```

Храните текущее слово и его длину снаружи цикла, который читает очередные блоки. Повторное использование байтового буфера не должно стирать незавершённое слово.

В задаче о частотных словах пробелы разделяют слова внутри строки, а окончания строк тоже завершают слова. В двоичном режиме можно считать границами и `\r`, и `\n`: это позволяет обрабатывать CRLF, не создавая пустых слов. Не расширяйте определение слова незаметно; дополнительную политику нужно выбирать явно.

### Небольшой автомат состояний

Для каждого байта:

1. Если это граница, завершить непустое текущее слово и обнулить его длину.
2. Иначе проверить запас места, привести регистр и добавить символ.
3. Перед передачей слова строковым функциям записать `\0` в пределах выделенной памяти.
4. При обычном конце файла завершить оставшееся непустое слово.

Поведение при слишком длинном слове зависит от контекста. Если файл должен соблюдать ограничение, можно сообщить о его нарушении. При недопустимой игровой попытке нужно отбросить остаток этой попытки и повторить ввод. Нельзя молча обрезать слово и затем считать его префикс полноценным допустимым словом.

:::remember
Завершение блока чтения и завершение слова — разные события. Слово завершается настоящим разделителем либо обычным концом файла.
:::

## 8. Ограниченный консольный ввод и состояние игры

### Отличайте неверный ввод от EOF

Недопустимую попытку можно отбросить и запросить другую. EOF означает, что вход закончился. Бесконечное повторение чтения при EOF создаёт бесконечный цикл.

Возможный интерфейс функции ввода:

```cpp
enum class ReadStatus {
    Ok,
    TooLong,
    EndOfInput,
    Error
};

ReadStatus readLine(std::FILE* input, char* buffer,
                    std::size_t capacity);
```

У функции должен быть ясный контракт: какие окончания она удаляет, принимает ли последнюю строку без перевода строки и что остаётся в буфере при каждом результате. Для обычного чтения через `fgets` используйте вместимость хотя бы две ячейки.

Если слишком длинная попытка заполнила буфер, перед следующей попыткой дочитайте и отбросьте остаток той же строки. Иначе его символы станут следующей попыткой. Отдельно продумайте точное совпадение с пределом: полный буфер без перевода строки может содержать допустимую попытку максимальной длины, а её перевод строки ещё находится во входе. Нужно дочитать достаточно, чтобы отличить перевод строки или EOF от настоящего лишнего символа.

```cpp
int ch;
while ((ch = std::fgetc(stdin)) != '\n' && ch != EOF) {
    // Отбросить остаток уже отвергнутой строки.
}
```

Не используйте `fflush(stdin)` для удаления ввода: стандарт C/C++ не определяет его как переносимую операцию очистки входного потока.

### Проверяйте ввод до расходования попытки

Разделите проверку и оценку слова:

```text

если произошла ошибка чтения: сообщить о ней
если попытка недопустима: запросить следующую
привести регистр допустимой попытки
оценить её и израсходовать одну попытку
проверить победу
```

К проверкам относятся длина и разрешённые символы. Не добавляйте проверку наличия догадки в словаре, если условие её не требует. Если понятие неверного ввода определено неоднозначно, уточните его границы.

Используйте ограниченный цикл или явный счётчик попыток и `bool won`. Неверные догадки не должны случайно расходовать допустимые попытки. После победы нужно остановиться, а не напечатать дополнительно сообщение о поражении.

Если приглашение к вводу напечатано без перевода строки, `std::fflush(stdout)` делает накопленный вывод видимым перед ожиданием. Выберите одно семейство ввода, например `<cstdio>`, чтобы не разбираться одновременно во взаимодействии по-разному настроенных потоковых систем.

**Практика:** читайте догадки фиксированной длины без самой игры. Проверьте пустую строку, допустимую догадку, слишком длинную строку перед допустимой, точную максимальную длину и EOF.

## 9. Случайный выбор и сравнения в Wordle

### Начальное состояние генератора и выбор

Функции `std::rand` и `std::srand` находятся в `<cstdlib>`, `std::time` — в `<ctime>`.

```cpp
std::srand(static_cast<unsigned>(std::time(nullptr)));
```

Задавайте начальное состояние генератора один раз около начала программы, а не перед каждым выбором. Иначе близкие по времени вызовы могут заново запускать одну последовательность. Фиксированное начальное значение, например `std::srand(42);`, удобно для воспроизведения ошибок.

Для небольшого положительного количества кандидатов:

```cpp
int index = std::rand() % candidateCount;
```

Сначала проверьте, что кандидаты есть. Остаток от деления не обеспечивает идеально равномерное распределение в общем случае. Если количество кандидатов больше числа возможных результатов генератора, некоторые кандидаты такой формулой вообще не выбираются. Учитывайте это ограничение. Когда уместно и разрешено, `<random>` предоставляет распределения, например `std::uniform_int_distribution`; стандартный контейнер для этого не нужен. Собственный генератор случайных чисел здесь реализовывать не требуется.

### Один проход по словарю

Понятный вариант: прочитать словарь один раз, сохранить подходящие слова нужной длины, затем выбрать слово из сохранённой коллекции. Увеличение массива кандидатов не требует повторного чтения файла. До случайного выбора обработайте случай, когда подходящих слов нет.

### Сравнение догадки с загаданным словом

Разделите три операции:

| Вопрос | Операция |
|---|---|
| Совпадает ли символ на этой позиции? | Сравнить символы с одинаковым индексом |
| Есть ли такой символ в загаданном слове? | Поиск по символам загаданного слова |
| Правильна ли догадка целиком? | Сравнить полные нормализованные слова |

В опубликованном осеннем условии `+` означает совпадение по позиции, `=` — наличие буквы в другом месте, `-` — отсутствие. В примере догадка `lllll` для слова `hello` получает `==++=`. Это проверка наличия повторяющейся буквы без ограничения числа совпадений количеством её вхождений в загаданное слово. Следуйте данным правилам и примерам. [Примеры Wordle](https://is-itmo-c-26.github.io/lectures/livecoding/2025-autumn.html)

**Практика:** выбирайте элемент из небольшого массива с фиксированным начальным значением генератора. Отдельно напишите проверку наличия символа и проверьте повторяющиеся буквы до соединения с консольным вводом.

## 10. Поиск, подсчёт и выбор top N

### Начните с линейного поиска

Храните записи для различных нормализованных слов. Для каждого завершённого слова сравнивайте его с использованными записями. Если оно найдено, увеличьте счётчик. Иначе добавьте независимую запись со счётчиком один.

Просматривайте только использованную часть массива, а не всю выделенную вместимость. У функции поиска должен быть понятный результат отсутствия, например `-1` при знаковых индексах. Нельзя путать индекс первой записи, равный нулю, с отсутствием результата.

Пусть во входе $T$ слов, различных слов $U$, а длина сравниваемых слов не превосходит $L$. Прямая реализация с линейным поиском имеет худшую временную сложность:

$$
O(TUL).
$$

Стоимость сравнения строк тоже учитывается. Хеш-таблица может ускорить поиск, но это самостоятельное упражнение по структурам данных, а не обязательное условие для первой правильной программы.

### Выбор записей по частоте

Top N означает N записей о различных словах с наибольшими счётчиками, а не только слова с общим максимальным счётчиком. Определите поведение, если N больше числа различных слов. При отсутствии других указаний разумно вывести все доступные различные слова. Равенство счётчиков на границе отбора тоже требует выбранного правила, если условие его не задаёт.

Два подхода: отсортировать все записи по убыванию счётчика или последовательно выбирать наибольшую оставшуюся запись. Второй — частичная сортировка выбором: каждый проход ставит максимум оставшейся части в её начало.

Схема ниже показывает выбор только на счётчиках. В программе меняйте местами целые записи «слово — счётчик», чтобы текст оставался связан со своей частотой.

```array
title: Выбор двух наибольших счётчиков
[3, 8, 2, 5]
pointers: i, j, best
code:
for (let i = 0; i < 2; i++) {
  let best = i;
  for (let j = i + 1; j < a.length; j++) {
    if (a[j] > a[best]) best = j;
  }
  swap(a, i, best);
  done(i);
}
```

Для $K = \min(N, U)$ выборов сравнения счётчиков требуют $O(KU)$ времени и постоянной дополнительной рабочей памяти. Если записи содержат длинные встроенные массивы символов, их обмен имеет дополнительную стоимость.

«Вывод в произвольном порядке» разрешает любой порядок уже выбранных слов. Требование выбирать их по частоте при этом сохраняется.

**Практика:** создайте записи вручную до подключения чтения файла. Проверьте одинаковые счётчики, одно различное слово, повторения в разном регистре и N больше числа доступных записей.

```quiz

- [ ] Только слово со счётчиком 9
- [x] Слово со счётчиком 9 и одно из слов со счётчиком 7

explain: Top N отбирает записи по частоте. Выбранная политика разрешает равенство на границе отбора.
```

## 11. Вывод через printf, fwrite и проверка потоков

### Строка и явно заданное число байт

Для корректной C-строки:

```cpp
std::printf("%s\n", word);
```

Для последовательности байт известной длины:

```cpp
std::size_t written = std::fwrite(data, 1, length, stdout);
```

`fwrite` принимает источник, размер элемента, количество элементов и поток. Возвращает число полностью записанных элементов. При размере один сравнивайте результат с запрошенным количеством байт. Функция не добавляет ни перевод строки, ни завершающий ноль. Справочник: [fwrite](https://en.cppreference.com/cpp/io/c/fwrite).

При текстовом выводе слова обычно записывают его буквы и затем `\n`; терминатор C-строки в файл выводить не нужно. Для `int` используйте `%d`, для `std::size_t` — `%zu`. В форматном выводе типы аргументов должны соответствовать спецификаторам.

:::warning
Форматная строка должна задаваться программой. Пишите `printf("%s", word)`, а не `printf(word)`. Знаки процента из входного текста должны оставаться данными.
:::

### Буферизация и ошибки

`stdout` предназначен для результата программы, `stderr` — для диагностики. Ненулевой результат `main` сообщает о неудачном завершении.

Некоторые ошибки вывода обнаруживаются при сбросе буфера, а не в исходном вызове записи. При завершении проверяемого вывода в стандартный поток проверяйте `std::fflush(stdout)`. Для отдельно открытого выходного файла проверяйте `fclose`: закрытие сбрасывает поток и может сообщить об ошибке. После закрытия обращаться к потоку нельзя.

### Полный пример: запись короткой последовательности байт

```cpp
#include <cstdio>

int main() {
    const char text[] = "sample\n";
    std::size_t length = sizeof text - 1;

    if (std::fwrite(text, 1, length, stdout) != length) {
        std::fprintf(stderr, "Ошибка вывода\n");
        return 1;
    }
    if (std::fflush(stdout) == EOF) {
        std::fprintf(stderr, "Ошибка сброса выходного буфера\n");
        return 1;
    }
}
```

Нельзя сохранять вектор-владелец записью байтов самого объекта вектора. Среди этих байтов находятся адреса, а не содержимое массива. Побайтовая запись структур также может захватить выравнивание и машинно-зависимое представление. В этих заданиях требуется текстовый вывод, поэтому записывайте нужные слова явно.

**Практика:** скопируйте входные байты в stdout, проверяя чтение и запись. Затем выводите по одной C-строке на строку, не записывая её терминатор.

## 12. Компиляция, отладка и план самостоятельной практики

### Собирайте небольшие законченные программы

Для Clang в системе с установленными библиотеками санитайзеров:

```bash
clang++ -std=c++23 -Wall -Wextra -Wpedantic -g \
  -fsanitize=address,undefined main.cpp -o program
./program
```

Предупреждения помогают обнаруживать пропущенные возвраты и подозрительные преобразования. AddressSanitizer находит многие выходы за границы, обращения к освобождённой памяти и повторные удаления. UndefinedBehaviorSanitizer обнаруживает отдельные виды неопределённого поведения. Эти инструменты не доказывают корректность и не выявляют любое чтение неинициализированных данных.

Для выданного CMake-проекта:

```bash
cmake -S . -B build
cmake --build build
```

Относительные пути всё равно отсчитываются от рабочей папки в момент запуска исполняемого файла.

### Небольшие проверки до объединения частей

| Часть | Что проверить |
|---|---|
| Вектор | Пустое создание, первую вставку, рост, независимость копии, присваивание, самоприсваивание, пустое удаление |
| C-строки | Пустую строку, точную предельную длину, место терминатора, независимость копий |
| Аргументы | Пропущенное значение, неизвестный параметр, путь с пробелами, некорректные и переполняющие числа |
| Чтение | Отсутствующий файл, пустой файл, неполное последнее чтение, очень маленький буфер |
| Выделение слов | Повторные пробелы, пустые строки, CRLF, слово на границе чтений, отсутствие последнего перевода строки |
| Подсчёт | Одно различное слово, разный регистр, повторения, равные частоты, top N больше числа различных слов |
| Консольный ввод | Неверную догадку, слишком длинную строку перед допустимой, точную предельную длину, EOF |
| Игра | Отсутствие подходящих слов, победу сразу, победу последней попыткой, исчерпание попыток, повторяющиеся буквы |
| Вывод | Одно слово на строку, отсутствие лишних нулевых байт, отделение ошибок от результата |

Для проверки вывода отдельно от отображения в терминале:

