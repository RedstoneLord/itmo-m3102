# ООП. Абстракция и инкапсуляция

[Материалы курса](https://is-itmo-c-26.github.io/lectures/lectures/08-oop-abstraction-encapsulation.html)

## 1. Абстракция и инвариант

:::meaning
**Абстракция** задаёт, как пользоваться объектом и какого поведения от него ожидать. Например, стек хранит элементы в порядке LIFO: элемент, добавленный последним, извлекается первым. Место хранения элементов для этого правила несущественно.
:::

| Операция стека | Результат |
|---|---|
| `push(value)` | Кладёт значение на вершину. Для стека фиксированной ёмкости требуется свободное место. |
| `pop()` | Удаляет вершину непустого стека. |
| `top()` | Читает вершину непустого стека. |
| `empty()` | Сообщает, пуст ли стек. |

### Стек и дата с открытыми полями

В процедурном варианте стека структура хранит массив из десяти элементов и счётчик `size`, а свободные функции получают структуру по ссылке. При добавлении функция кладёт значение в ячейку с индексом `size` и увеличивает счётчик. При чтении вершины берёт индекс `size - 1`.

:::example
После добавления 42 у стека один элемент, вершина лежит в ячейке с индексом ноль. Открытое поле позволяет клиенту записать `stack.size = 100500;` напрямую. Счётчик теперь выходит за пределы массива, хотя записанное значение по-прежнему лежит на первом месте.
:::

У структуры `Date` проблема похожа: год, месяц и день описывают календарную дату, а `timestamp` хранит то же состояние как число секунд от начала 1970 года в UTC. Функция создания может заполнить их согласованно, но изменение одного открытого поля обходит эту проверку и оставляет метку времени прежней.

:::meaning
**Инвариант** — условие согласованности состояния объекта. У стека число элементов должно лежать между нулём и ёмкостью, а заполненная часть начинается с первой ячейки. У даты сочетание года, месяца и дня должно существовать в календаре. Если метка времени хранится отдельно, она должна соответствовать этим полям.
:::

```quiz

```

## 2. Класс и инкапсуляция

**Класс** объединяет поля и функции-члены из одной предметной задачи. Поля стека хранят данные и размер, а методы реализуют операции из таблицы.

:::meaning
**Инкапсуляция** объединяет данные и операции в одном типе и скрывает детали представления за интерфейсом. Клиент вызывает методы, которые поддерживают инвариант, и больше не может напрямую переписать внутренний размер.
:::

В `IntStack` можно поменять массив на `std::vector<int>`: добавление идёт в конец, чтение вершины возвращает последний элемент, удаление убирает его. Клиентский вызов остаётся таким же.

```diagram
title: Два способа хранения стека
CLIENT: box "Клиент"
API: round "push, pop, top, empty"
ARRAY: box "Массив и счётчик"
VECTOR: box "std::vector"
CLIENT -> API
API -> ARRAY
API -> VECTOR
```

:::warning
Одинакового вывода в одном примере недостаточно для совместимости. Если интерфейс обещает ёмкость 10, версия с вектором тоже должна соблюдать этот предел. Прямой вызов `push_back` без проверки разрешит одиннадцатый элемент.
:::

| Спецификатор | Доступ |
|---|---|
| `public` | Члены и друзья класса, а также внешний код. |
| `private` | Члены и друзья самого класса. |
| `protected` | Как у `private`, плюс члены и друзья производных классов с ограничениями. |

У класса `Date` год, месяц и день закрыты. Публичные методы читают компоненты, а `timestamp()` вычисляет метку времени из текущей даты. Так отдельное сохранённое значение не может устареть после изменения даты.

## 3. Конструктор и методы: пример `Date`

Конструктор инициализирует объект. У него имя класса и отсутствует возвращаемый тип. Поля инициализируются **в порядке объявления в классе** до входа в тело конструктора. Порядок записи в списке инициализации этого не меняет.

В `Date` конструктор получает год, месяц и день и проверяет их сочетание. Для невозможной даты он выбрасывает `std::invalid_argument`, и готового объекта не появляется. Публичный метод `set` выполняет такую же проверку для новых аргументов **до** записи в поля. Метод может вернуть `Date&` через `return *this;`: `this` указывает на объект, для которого метод вызван.

```cpp
// Фрагмент Date: valid_date проверяет сочетание трёх компонентов.
Date& Date::set(int year, unsigned month, unsigned day) {
    if (valid_date(year, month, day)) {
        year_ = year;
        month_ = month;
        day_ = day;
        return *this;
    }
    throw std::invalid_argument{"invalid calendar date"};
}
```

:::example
Для объекта с 31 марта 2024 года отдельный сеттер месяца может принять апрель и создать 31 апреля. Вызов `set(2024, 4, 31)` проверяет все три аргумента вместе и останавливается до изменения полей. После перехвата исключения объект по-прежнему описывает 31 марта.
:::

## 4. Конструкторы и методы рационального числа

`Rational` хранит целые числитель и знаменатель. Конструктор нормализует входные значения: дробь сокращается, знак относится к числителю, знаменатель положителен. Для нуля каноническое представление — $0/1$.

| Вызов | Как получается объект |
|---|---|
| `Rational{}` | Из аргументов по умолчанию `0` и `1`. |
| `Rational{5, 10}` | Из указанных значений с нормализацией до $1/2$. |
| `Rational{original}` | Копирующий конструктор получает `const Rational&`. |
| `Rational{std::move(original)}` | Перемещающий конструктор получает `Rational&&`. |

Копирующий конструктор переносит в новый объект значения двух полей и сохраняет источник. В разобранной реализации перемещающий конструктор забирает оба значения через `std::exchange` и записывает в источник ноль и единицу. В итоге копия и перемещённая дробь равны $1/2$, а источник — $0/1$. Само выражение `std::move(original)` лишь позволяет выбрать перегрузку для перемещения. Состояние источника меняет тело операции или её инициализаторы.

Методы `numerator() const` и `denominator() const` читают данные и доступны для константного объекта. Константность метода указывается после списка параметров. Попытка присвоить новое значение обычному полю внутри такого метода вызывает ошибку компиляции.


## 5. Деструктор, присваивание и порядок вызовов

### Деструктор

Деструктор имеет форму `~ИмяКласса()` без параметров и возвращаемого типа. Для буфера, получившего массив через `new[]`, его тело вызывает `delete[]`. Если такой буфер — локальный объект блока, деструктор выполняется при выходе из блока. После тела деструктора его поля уничтожаются в обратном порядке объявления.

### Создание и присваивание

В `T second = first;` переменная `second` создаётся копирующим конструктором. Запись `second = first;` после объявления меняет существующий объект, вызывая `operator=`. Копирующее присваивание обычно принимает `const T&` и возвращает `T&` на результат через `*this`. Передача по `const T&` позволяет читать объект без дополнительной копии и принимать константные объекты.

Стандартное копирование переносит значения полей и базовых частей. Для поля-указателя это копирование адреса. Нового объекта по этому адресу оно не создаёт.

### Конструктор по умолчанию

Конструктор по умолчанию можно вызвать без аргументов. Это применимо и к `Rational`, у которого оба параметра имеют значения по умолчанию. `Date` требует три аргумента. Если класс объявляет собственный конструктор с обязательными параметрами, компилятор не добавляет отдельный конструктор без аргументов. Его можно запросить через `= default`, если стандартная инициализация подходит для класса.

### Порядок вызовов на примере `GeoPoint`

У географической точки два поля типа `Rational`: сначала широта, затем долгота. Вывод из тел конструкторов и деструкторов позволяет проследить порядок операций.

| Операция | Порядок в примере с `GeoPoint` |
|---|---|
| Обычное создание | Создаётся широта, создаётся долгота, выполняется тело конструктора точки. |
| Копирующее или перемещающее создание | Копируются или перемещаются широта и долгота, затем выполняется тело соответствующего конструктора точки. |
| Копирующее или перемещающее присваивание | Выполняется оператор присваивания точки, внутри него присваиваются два уже существующих поля. |
| Уничтожение | Сначала выполняется тело деструктора точки, затем уничтожаются долгота и широта. |

Если несколько локальных объектов созданы в одном блоке, они уничтожаются в обратном порядке создания. В примере после четвёртой точки уничтожаются третья и вторая, затем отдельно объявленные долгота и широта, затем первая точка.

## 6. `= default`, `= delete` и `explicit`

`= default` просит компилятор использовать стандартную реализацию специальной функции. `= delete` объявляет операцию запрещённой: компилятор отвергнет вызов, если выберет эту перегрузку. Класс `NonCopyable` в примере разрешает создание обычного объекта и удаляет копирующий конструктор и копирующее присваивание.

У конструктора `Rational(int numerator = 0, int denominator = 1)` второй параметр можно опустить. Без `explicit` это даёт неявное преобразование из `int`: копирующая инициализация `Rational number = 1;` создаст дробь $1/1$, а вызов функции с параметром `const Rational&` сможет принять `2` через временную дробь $2/1$. После добавления `explicit` дроби создаются явно: `Rational number{1};` и `print_rational(Rational{2});`.

:::note
При определении того, какие специальные функции компилятор объявит неявно, запись `= default` или `= delete` всё равно считается пользовательским объявлением. Например, пользовательское объявление деструктора, даже со стандартным телом, препятствует неявному объявлению операций перемещения.
:::

## 7. Владение ресурсом: правила трёх, пяти и нуля

| Правило | Что проверить при проектировании |
|---|---|
| Трёх | Согласовать деструктор, копирующий конструктор и копирующее присваивание. |
| Пяти | Дополнительно определить поведение перемещающего конструктора и перемещающего присваивания. |
| Нуля | Передать владение полю готового типа и использовать стандартные операции класса, если они сохраняют инвариант. |

Эти правила помогают выбрать, какие операции реализовать, оставить стандартными или запретить.

:::warning
У `ShallowArray` обычное копирование указателя создаёт двух владельцев одного массива. Изменение элемента через один объект видно через второй. При уничтожении оба деструктора попытаются освободить один адрес, что приводит к неопределённому поведению.
:::

### Независимая копия `IntArray`

Копирующий конструктор выделяет отдельный массив размера источника и переносит значения элементов. При присваивании получатель уже владеет своим массивом, поэтому шаги другие:

1. При присваивании самому себе можно сразу вернуть текущий объект.
2. Выделить новый массив и скопировать в него элементы источника.
3. Освободить прежний массив, заменить указатель и сохранить новый размер.

```cpp
// Фрагмент IntArray. Для std::copy_n нужен заголовок <algorithm>.
IntArray& IntArray::operator=(const IntArray& other) {
    if (this != &other) {
        int* replacement = nullptr;
        if (other.size_ != 0) {
            replacement = new int[other.size_];
            std::copy_n(other.data_, other.size_, replacement);
        }

        delete[] data_;
        data_ = replacement;
        size_ = other.size_;
    }
    return *this;
}
```

:::example
Порядок шагов защищает прежнее состояние при ошибке выделения. Если новый массив создать не удалось, старый указатель и старый размер ещё действительны. После успешного копирования обе версии массива хранят одинаковые значения в разных областях памяти.
:::

Если поле — `std::vector<int>`, уже сам вектор управляет памятью и создаёт независимую копию элементов. Когда это соответствует инварианту `IntArray`, собственные деструктор, копирование и перемещение не нужны.

Для динамического объекта выражение `new` выделяет память и инициализирует объект, а `delete` уничтожает объект и освобождает память. Вызовы `std::malloc` и `std::free` сами не вызывают конструктор и деструктор.

## 8. `class` и `struct`

Оба объявления поддерживают поля, методы, конструкторы, деструктор и спецификаторы доступа. Для `class` доступ к членам и наследование по умолчанию — `private`, для `struct` — `public`. По соглашению `struct` часто выбирают для открытого набора данных, а `class` — для типа, поддерживающего инвариант через методы.
