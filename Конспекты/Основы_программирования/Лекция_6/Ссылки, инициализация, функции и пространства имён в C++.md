## Ссылки и время жизни объектов

### Обмен значениями через указатели

Начнём с задачи: написать функцию, которая меняет местами значения двух переменных. Чтобы функция могла изменить **исходные** переменные, а не их копии, ей нужно передать адреса этих переменных.

```cpp
#include <iostream>

void swap_values(int* left, int* right) {
    int temporary = *left;
    *left = *right;
    *right = temporary;
}

int main() {
    int first = 10;
    int second = 20;
    swap_values(&first, &second);
    std::cout << first << ' ' << second << '\n'; // 20 10
}
```

:::example
Разберём работу программы по шагам.

1. В `main` созданы `first = 10` и `second = 20`.
2. Вызов `swap_values(&first, &second)` передаёт в функцию адреса переменных: `left` указывает на `first`, `right` — на `second`.
3. `int temporary = *left;` — читаем значение по адресу `left` (это `10`) и сохраняем во временную переменную.
4. `*left = *right;` — записываем по адресу `left` значение, лежащее по адресу `right` (`20`). Теперь `first` равна `20`.
5. `*right = temporary;` — записываем по адресу `right` сохранённое `10`. Теперь `second` равна `10`.
6. Программа печатает `20 10`.
:::

### Указатель может быть нулевым

Указатель — это значение, которое может оказаться нулевым (`nullptr`). Что будет, если передать в `swap_values` нулевой указатель?

```cpp
void swap_values(int* left, int* right) {
    int temporary = *left;
    *left = *right;
    *right = temporary;
}

int main() {
    int value = 10;
    swap_values(&value, nullptr);
}
```

:::warning
Разыменование `nullptr` приводит к **неопределённому поведению**. Здесь выражение `*right` разыменовывает нулевой указатель, поэтому результат программы не определён стандартом: нельзя рассчитывать ни на конкретное значение, ни на предсказуемое падение.
:::

Для обмена нужны **два существующих объекта**. Можно было бы добавить в функцию проверку и молча выйти через `return`, если указатель нулевой, но это скрыло бы нарушение условия задачи: вызывающий код ошибся, а ошибка осталась незамеченной.

Эта проблема — мотивация для ссылок: у них нет «нулевого» состояния.

### Ссылка — другое имя объекта

:::meaning
**Lvalue-ссылка** (`T&`) — другое имя, или **псевдоним**, объекта типа `T`. Обращаясь к ссылке, мы работаем с самим этим объектом.
:::

Основные свойства ссылки:

- при создании ссылку **нужно инициализировать**, то есть связать с объектом;
- привязка **не создаёт копию** объекта;
- **перепривязать** ссылку к другому объекту нельзя;
- **указателя на саму ссылку нет**: взятие её адреса даёт адрес объекта, на который она ссылается.

### Ссылка в коде

```cpp
#include <iostream>

int main() {
    int value = 10;
    int& alias = value;
    alias = 20;
    std::cout << value << '\n'; // 20
    std::cout << std::boolalpha << (&alias == &value) << '\n'; // true
}
```

:::example
Пошагово:

1. `int& alias = value;` — `alias` становится вторым именем переменной `value`. Новый объект не создаётся.
2. `alias = 20;` — присваивание через ссылку изменяет сам объект, поэтому `value` теперь равна `20`.
3. `&alias == &value` — адрес «ссылки» совпадает с адресом объекта, потому что адреса самой ссылки нет; получаем `true` (флаг `std::boolalpha` печатает логические значения словами `true`/`false`).
:::

:::warning
Символ `&` играет две разные роли:

- в **объявлении** `int&` он задаёт ссылочный тип;
- в **выражении** `&alias` он берёт адрес объекта.

Ссылка без инициализатора — ошибка: `int& alias;` не скомпилируется.
:::

### Ссылка и указатель в памяти

Имена `i` и `j` обозначают один и тот же объект. Указатель `p` — это **отдельный объект** со своим адресом; он хранит адрес `i`.

:::note
Будет ли сама связь ссылки с объектом занимать память, зависит от реализации. Поэтому нельзя рассуждать о ссылке как об объекте с гарантированным размером и адресом — в отличие от указателя.
:::

### Ссылку нельзя перепривязать

```cpp
#include <iostream>

int main() {
    int first = 10;
    int second = 20;
    int& alias = first;
    alias = second; // Assign to first; alias still refers to first.
    alias = 30;
    std::cout << first << ' ' << second << '\n'; // 30 20
}
```

:::example
Пошагово:

1. `alias` связана с `first`.
2. `alias = second;` — это **не** привязка к `second`, а присваивание: значение `second` (`20`) копируется в объект `first`. Теперь `first == 20`, а `alias` по-прежнему ссылается на `first`.
3. `alias = 30;` — снова меняется `first`, теперь она равна `30`.
4. `second` ни разу не менялась: `20`.
5. Результат: `30 20`.
:::

:::remember
Присваивание через ссылку меняет **объект**, а не связь ссылки с ним.
:::

### Чтение через const-ссылку

```cpp
#include <iostream>

int main() {
    int value = 10;
    const int& view = value;
    // view = 20; // Error: cannot modify value through this reference.
    value = 20;
    std::cout << view << '\n'; // 20
}
```

`const T&` запрещает изменение **через эту ссылку**. Сам объект при этом может оставаться изменяемым: здесь `value = 20;` допустимо, и `view` видит новое значение.

:::warning
`const`-ссылка — это ограничение на способ доступа, а не обещание, что объект никогда не изменится. Другое имя того же объекта (в примере — `value`) по-прежнему позволяет его менять.
:::

### Обмен значениями через ссылки

```cpp
#include <iostream>

void swap_values(int& left, int& right) {
    int temporary = left;
    left = right;
    right = temporary;
}

int main() {
    int first = 10;
    int second = 20;
    swap_values(first, second);
    std::cout << first << ' ' << second << '\n'; // 20 10
}
```

Тело функции стало проще: нет ни `*`, ни `&` при вызове. Вызов передаёт **сами переменные** (а `left` и `right` — это их другие имена внутри функции).

:::note
У ссылки нет корректного «нулевого» состояния — передать «ничего» вместо объекта нельзя. Зато объект должен оставаться живым всё время, пока на него ссылаются (подробнее — в следующих подразделах).
:::

### Копия или исходный объект?

```cpp
#include <iostream>

void increment_copy(int value) {
    ++value;
    std::cout << value << '\n';
}
void increment_original(int& value) {
    ++value;
}

int main() {
    int count = 10;
    increment_copy(count); // Prints 11; count is still 10.
    std::cout << count << '\n'; // 10
    increment_original(count);
    std::cout << count << '\n'; // 11
}
```

:::example
Пошагово:

1. `count = 10`.
2. `increment_copy(count)` — параметр `value` — **отдельный объект**, в него скопировано `10`. `++value` меняет копию, функция печатает `11`.
3. После возврата `count` по-прежнему `10` — печатается `10`.
4. `increment_original(count)` — параметр `value` является ссылкой на `count`. `++value` увеличивает саму `count`.
5. Печатается `11`.
:::

### Ссылка не владеет объектом

```cpp
#include <iostream>

int& local_value() {
    int value = 20;
    return value; // Reference to a local variable.
}

int main() {
    int& result = local_value();
    std::cout << result << '\n'; // Undefined behavior.
}
```

Ссылка **не владеет** объектом: она не продлевает ему жизнь. Локальная переменная `value` уничтожается при выходе из `local_value`, а функция вернула ссылку на неё.

:::warning
После возврата из `local_value` локальный объект уже уничтожен. Чтение через возвращённую ссылку — **неопределённое поведение**. Такая ссылка называется *висячей*.

Диагностика компилятора не заменяет контроль времени жизни. Нельзя рассчитывать ни на конкретное значение, ни на падение программы.
:::

### Локальный результат возвращаем по значению

```cpp
#include <iostream>

int make_value() {
    int value = 20;
    return value;
}

int main() {
    int result = make_value();
    std::cout << result << '\n'; // 20
}
```

Вызывающий код получает **результат** (значение), а не ссылку на локальную переменную. После выхода из функции локальная переменная больше не нужна — и это нормально.

:::remember
Локальный результат функции возвращают по значению, а не по ссылке.
:::

### Какие привязки ссылок допустимы?

```cpp
#include <iostream>

int main() {
    int x = 10;
    int& a = x;
    const int& b = x;
    const int& c = 42;
    // int& d = 42;

    std::cout << a << ' ' << b << ' ' << c << '\n';
}
```

:::example
Разберём каждую строку.

- `int& a = x;` и `const int& b = x;` — `a` и `b` ссылаются на `x`.
- `const int& c = 42;` — `42` не лежит ни в какой переменной, поэтому для него создаётся **временный** `int`, и `c` привязывается к нему. Время жизни этого временного объекта **продлевается до конца блока** (здесь — до конца `main`).
- `int& d = 42;` — **ошибка**: неконстантная lvalue-ссылка не привязывается к такому временному объекту.
:::

### Временный объект в аргументе const&

```cpp
#include <iostream>
#include <string>

void greet(const std::string& name) {
    std::cout << "Hello, " << name << "!\n";
}

int main() {
    greet("world"); // A temporary std::string is created for this call.
} // The temporary has already been destroyed after the call expression.
```

Параметр `const&` **не копирует** готовую `std::string`. Но здесь аргумент — строковый литерал `"world"`, а не `std::string`. Поэтому вызов `greet("world")` требует создать временную строку из литерала; `name` ссылается на эту временную строку.

:::warning
Временная строка живёт **до конца полного выражения** с вызовом — здесь до `;`. Если сохранить на неё ссылку и использовать после этого, ссылка будет висячей.
:::

## Выбор способа передачи аргументов

### Как передавать аргумент?

| Параметр | Смысл | Типичный случай |
|---|---|---|
| `T value` | Отдельный объект-параметр | Дёшево копируемое значение: `int`, `double` |
| `const T& value` | Чтение без копирования в параметр | Большая структура или строка |
| `T& value` | Работа с исходным изменяемым объектом | Изменить переданный объект |
| `const T* value` | Чтение через указатель | Объект может отсутствовать |
| `T* value` | Изменение через указатель | Объект может отсутствовать |

Допустимость `nullptr` определяет **договорённость функции**: сам тип указателя этого не гарантирует. Указатель также может обозначать начало массива.

:::remember
Если функция вычисляет **новый результат**, обычно возвращайте его через `return`. Для изменения **существующего** объекта используйте `T&`.
:::

### Что получает функция

При разных способах передачи функция получает разное:

- **по значению** (`T value`) — копию изображения;
- **по ссылке** (`T&`) — то же самое изображение;
- **по указателю** (`T*`) — копию адреса.

### Параметры для работы с изображением

Пусть `Image` хранит большое изображение. Какие типы параметров нужны этим функциям?

- `show` — показать существующее изображение, не меняя его;
- `blur` — размыть существующее изображение;
- `set_logo` — использовать изображение как логотип, не меняя его; отсутствие означает «убрать логотип»;
- `set_zoom` — задать масштаб целым числом процентов.

```cpp
// Interface declarations; Image and the functions are defined elsewhere.
struct Image;

void show(const Image& image);   // Read the image without copying it.
void blur(Image& image);         // Modify the original image.
void set_logo(const Image* logo); // nullptr means no logo.
void set_zoom(int percent);      // Copy a small value.
```

:::example
Обоснуем выбор для каждой функции.

1. `show` — изображение большое, поэтому копировать его не нужно; при этом менять его нельзя. Значит, `const Image&`.
2. `blur` — нужно изменить **исходное** изображение. Значит, `Image&`.
3. `set_logo` — изображение только читается (`const`), а отсутствие логотипа — допустимое состояние. У ссылки нет «нулевого» состояния, поэтому подходит указатель: `const Image*`, где `nullptr` означает «логотипа нет».
4. `set_zoom` — число процентов дёшево копировать, поэтому параметр по значению: `int`.
:::

### Когда отсутствие объекта допустимо

```cpp
#include <iostream>

void print_value(const int* value) {
    if (value == nullptr) {
        std::cout << "No value\n";
        return;
    }
    std::cout << *value << '\n';
}

int main() {
    int value = 42;
    print_value(&value); // 42
    print_value(nullptr); // No value
}
```

Здесь `nullptr` имеет **осмысленное значение**, которое функция явно обрабатывает: перед разыменованием она проверяет указатель. Это отличается от `swap_values`, где нулевой указатель был бы ошибкой вызывающего кода.

```quiz
explain: Когда объект может отсутствовать, используют указатель; допустимость `nullptr` определяется договорённостью функции.

```

## Перегрузка функций, `nullptr` и аргументы по умолчанию

### Перегрузка: одно имя, разные параметры

:::meaning
**Перегрузка функций** — несколько функций с одним именем, но разными списками параметров: по типам или по количеству.
:::

```cpp
#include <iostream>

void print(int value) {
    std::cout << "int: " << value << '\n';
}
void print(double value) {
    std::cout << "double: " << value << '\n';
}

int main() {
    print(20);   // int
    print(20.1); // double
}
```

Компилятор выбирает перегрузку **по аргументам**. Здесь оба вызова имеют **точное совпадение** типов: `20` — это `int`, `20.1` — это `double`.

### Перегрузки с разным числом параметров

```cpp
#include <iostream>

void print() {
    std::cout << '\n';
}
void print(int value) {
    std::cout << value << '\n';
}
void print(int first, int second) {
    std::cout << first << ' ' << second << '\n';
}

int main() {
    print();
    print(10);
    print(10, 20);
}
```

В каждом вызове подходит **только одна** функция по числу аргументов, поэтому выбор очевиден.

### Что напечатает print(value)?

```cpp
#include <iostream>

void print(int value) {
    std::cout << value << '\n';
}

int main() {
    double value = 20.1;
    print(value);
}
```

:::example
Ответ: **`20`**.

1. Перегрузки для `double` нет — есть только `print(int)`.
2. Но `double` можно преобразовать в `int`, поэтому вызов допустим.
3. При преобразовании дробная часть теряется: `20.1` превращается в `20`.
:::

### А если добавить перегрузку для float?

Какую функцию выберет компилятор?

```cpp
void print(int) {}
void print(float) {}

int main() {
    print(20.1); // The argument has type double.
}
```

:::warning
**Ни одну: вызов неоднозначен.** `20.1` имеет тип `double`. Преобразование `double` → `int` и преобразование `double` → `float` — ни одно из них не лучше другого, поэтому компилятор не может выбрать.
:::

### Как выбрать нужную перегрузку

```cpp
#include <iostream>

void print(int value) {
    std::cout << "int: " << value << '\n';
}
void print(float value) {
    std::cout << "float: " << value << '\n';
}

int main() {
    print(20);    // int: exact match.
    print(20.1F); // float: exact match.
}
```

Суффикс `F` задаёт литералу тип `float`. Теперь оба вызова имеют **точное совпадение** типов, и неоднозначности нет: `print(20)` вызывает версию для `int`, а `print(20.1F)` — версию для `float`.

### Возвращаемый тип не различает перегрузки

```cpp
int convert(int value) {
    return value;
}
float convert(int value) {
    return static_cast<float>(value);
}

int main() {
    return convert(10);
}
```

:::warning
У этих функций **одинаковый список параметров** (`int`), они отличаются только возвращаемым типом, поэтому объявления конфликтуют. Тип переменной, в которую мы хотим записать результат, не исправит эту ошибку: по возвращаемому типу компилятор перегрузку не выбирает.
:::

### nullptr вместо числового нуля

```cpp
#include <iostream>

void print(int) {
    std::cout << "int\n";
}
void print(const char*) {
    std::cout << "const char*\n";
}

int main() {
    print(0);       // int
    print("hello"); // const char*
    print(nullptr); // const char*
}
```

Литерал `0` — это число, поэтому `print(0)` вызывает перегрузку для `int`. А `nullptr` выбирает перегрузку с указателем.

:::warning
`NULL` — макрос с зависящим от реализации определением. Не полагайтесь на него при выборе перегрузки; для нулевого указателя используйте `nullptr`.
:::

### nullptr не выбирает тип указателя

```cpp
void print(const char*) {}
void print(int*) {}

int main() {
    print("hello"); // OK: const char*.
    print(nullptr); // Error: ambiguous call.
}
```

Для `nullptr` **обе** указательные перегрузки подходят, поэтому вызов неоднозначен. Нулевой указатель **конкретного типа** (например, переменная типа `int*`) выбрал бы соответствующую перегрузку.

### У nullptr есть собственный тип

```cpp
#include <cstddef>
#include <iostream>

void print(const char*) { std::cout << "const char*\n"; }
void print(int*) { std::cout << "int*\n"; }
void print(std::nullptr_t) { std::cout << "nullptr\n"; }

int main() {
    print(nullptr); // Exact match: std::nullptr_t.
}
```

У `nullptr` есть собственный тип `std::nullptr_t`, объявленный в `<cstddef>`. Сам он не является указательным типом, но его значения преобразуются в указательные типы. Если добавить отдельную перегрузку для `std::nullptr_t`, то вызов `print(nullptr)` получает **точное совпадение** и больше не неоднозначен.

### Аргументы по умолчанию

```cpp
#include <iostream>

struct Point {
    int x;
    int y;
};

Point make_point(int x = 0, int y = 0) {
    return {x, y};
}

void print(Point point) {
    std::cout << '(' << point.x << ", " << point.y << ")\n";
}

int main() {
    print(make_point(10, 20)); // (10, 20)
    print(make_point(10));     // (10, 0)
    print(make_point());       // (0, 0)
}
```

:::example
Как подставляются значения:

1. `make_point(10, 20)` — оба аргумента заданы явно: `(10, 20)`.
2. `make_point(10)` — `x = 10`, пропущенный `y` берётся по умолчанию: `(10, 0)`.
3. `make_point()` — оба берутся по умолчанию: `(0, 0)`.
:::

:::warning
Пропущенные аргументы подставляются **справа**. Нельзя пропустить первый аргумент, передав только второй.
:::

### Где указывать значение по умолчанию

- Значение должно быть **видно в объявлении в месте вызова**.
- Если объявление и определение разделены, значение обычно указывают **в объявлении**; повторять его в определении нельзя.
- В обычном списке параметров после параметра со значением по умолчанию **остальные тоже** должны иметь значения по умолчанию.
- Значения по умолчанию **не создают новые перегрузки**: сочетание `f(int)` и `f(int, int = 0)` делает вызов `f(1)` неоднозначным.

## Инициализация: начальное значение и фигурные скобки

### Инициализация и присваивание

:::meaning
**Инициализация** задаёт начальное состояние объекта при его создании. **Присваивание** меняет значение уже существующего объекта.
:::

```cpp
#include <iostream>

int main() {
    int value = 10; // Initialization: create an object with a value.
    value = 20;     // Assignment: change an existing object.
    std::cout << value << '\n';
}
```

Знак `=` в первой строке — это **инициализация** (объект создаётся сразу с нужным значением), а во второй — **присваивание** (объект `value` уже существует).

### Пустые скобки: () и {}

```cpp
int main() {
    int value();
    value = 42;
}
```

```cpp
#include <iostream>

int main() {
    int value{};
    std::cout << value << '\n';
}
```

:::warning
- `int value();` объявляет **функцию** без параметров, возвращающую `int`. Присваивание `value = 42` вызывает ошибку компиляции, потому что `value` — не переменная.
- `int value{};` создаёт **переменную** типа `int` со значением `0`.
:::

### Виды инициализации

| Название | Описание |
|---|---|
| Default-initialization | Объявление объекта без инициализатора |
| Value-initialization | В частности, получение нуля для `int` с пустым `{}` |
| Direct-initialization | Прямая инициализация: аргументы в `()` или `{}` без `=` |
| Copy-initialization | В частности, инициализация через `=` при объявлении |
| List-initialization | Инициализация списком в фигурных скобках |
| Aggregate initialization | Поэлементная инициализация массива или простой структуры |

:::note
Эти понятия **пересекаются**: фигурные скобки могут привести к value-initialization или к инициализации агрегата. Названия описывают разные стороны инициализации (есть ли инициализатор, как он записан, какой у объекта тип), а не взаимоисключающие категории.
:::

### Есть ли начальное значение?

```cpp
#include <iostream>

int main() {
    int uninitialized; // No initial value; do not read it.
    int zero{};       // Initialized to 0.
    uninitialized = 7; // Assign before the first read.
    std::cout << uninitialized << ' ' << zero << '\n'; // 7 0
}
```

:::warning
Для локального `int` запись без инициализатора **не задаёт значение**. Чтение такого значения в C++20 — неопределённое поведение. Нужно сначала присвоить значение (как в примере), и только потом читать.

У глобальных и `static` переменных действуют дополнительные правила нулевой инициализации.
:::

### Несколько форм инициализации

```cpp
#include <iostream>

int main() {
    int copy = 2;    // Copy-initialization.
    int direct(2);   // Direct-initialization.
    int list{2};     // Direct-list-initialization.
    int zero{};      // Empty list leads to value-initialization: 0.
    std::cout << copy << ' ' << direct << ' ' << list << ' ' << zero;
}
```

Во всех четырёх строках создаётся переменная `int`; различается способ записи инициализатора. Это не набор непересекающихся категорий: пустой список `{}` для `int` приводит к value-initialization.

### Фигурные скобки запрещают сужение

```cpp
#include <iostream>

int main() {
    double source = 3.5;
    int rounded = source; // Allowed conversion; value is 3.
    int checked{source}; // Error: narrowing conversion.
    std::cout << rounded << ' ' << checked << '\n';
}
```

:::example
Сравним две строки:

1. `int rounded = source;` — преобразование `double` → `int` допустимо; дробная часть теряется, получается `3`.
2. `int checked{source};` — фигурные скобки **запрещают сужающее преобразование**, поэтому это ошибка компиляции.
:::

Если потеря дробной части задумана, выразите её явно: `static_cast<int>(source)`.

### Инициализация агрегата

```cpp
#include <iostream>

struct Point {
    int x;
    int y;
};
struct Circle {
    Point center;
    int radius;
};

int main() {
    Circle circle{{1, 2}, 3};
    std::cout << circle.center.x << ' ' << circle.center.y
              << ' ' << circle.radius << '\n'; // 1 2 3
}
```

Значения задаются **в порядке объявления полей**. Вложенные скобки инициализируют вложенный `Point`.

```tree
circle{{1, 2}, 3}
  center = {1, 2}
    x = 1
    y = 2
  radius = 3
```

### Выбор формы инициализации

- По возможности инициализируйте переменную **при объявлении**. Не читайте её до получения корректного значения.
- Для чисел `{}` удобно, когда нужна проверка сужения; пустые скобки дают ноль.
- Для простых структур используйте список значений полей.
- Для классов `()` и `{}` могут выбирать **разные конструкторы**.

## Пространства имён

### Что такое пространство имён?

:::meaning
**Пространство имён** (`namespace`) — область, в которой можно объединить объявления функций, типов и переменных.
:::

- Одинаковые имена в разных пространствах **не конфликтуют** сами по себе.
- **Квалифицированное имя** с `::` указывает, в каком пространстве искать сущность.
- Одно пространство можно **дополнять** несколькими блоками объявлений.
- Пространства могут быть **вложенными**; для длинного имени можно задать **псевдоним**.

### Пространства имён предотвращают конфликты

Перед выбором перегрузки компилятору нужно **найти имя** функции.

```cpp
#include <iostream>

namespace screen {
    void print() { std::cout << "screen\n"; }
}
namespace file {
    void print() { std::cout << "file\n"; }
}

int main() {
    screen::print();
    file::print();
}
```

Квалифицированное имя `screen::print` явно указывает, какую функцию вызвать. Две функции `print` живут в разных пространствах и поэтому не мешают друг другу.

### using: одно имя или всё пространство?

```cpp
#include <iostream>

namespace screen {
    void print() { std::cout << "screen\n"; }
    void clear() { std::cout << "clear\n"; }
}

int main() {
    using screen::print;
    print();
    screen::clear();
    // clear(); // Error: using-declaration introduced only print.
}
```

- `using screen::print;` — **using-объявление**: вводит конкретное имя `print`. Поэтому `print()` можно вызвать без квалификации, а `clear()` — нельзя.
- `using namespace screen;` — **using-директива**: позволяет искать неквалифицированные имена во всём пространстве.

Здесь область действия `using` — блок `main`.

### Директивы using могут создать неоднозначность

```cpp
namespace screen {
    void print() {}
}
namespace file {
    void print() {}
}

int main() {
    using namespace screen;
    using namespace file;
    print(); // Error: screen::print or file::print?
}
```

:::warning
Вызов `print()` неоднозначен: подходят обе функции. Укажите `screen::print()` или `file::print()`.

Не размещайте `using namespace` в **глобальной области заголовка**: это влияет на весь код, который его включает.
:::

### Вложенные пространства имён

```cpp
#include <iostream>

namespace course {
    namespace graphics {
        void draw() {
            std::cout << "draw\n";
        }
    }
}

int main() {
    course::graphics::draw();
}
```

`graphics` находится внутри `course`. Полное имя функции — `course::graphics::draw`.

```tree
course
  graphics
    draw
    clear
```

### Продолжение пространства и псевдоним

```cpp
#include <iostream>

namespace course::graphics {
    void draw() { std::cout << "draw\n"; }
}
namespace course::graphics {
    void clear() { std::cout << "clear\n"; }
}

int main() {
    namespace gfx = course::graphics;
    gfx::clear();
    gfx::draw();
}
```

:::example
Что здесь происходит:

1. Запись `namespace course::graphics` сокращает вложенные блоки `namespace` — так можно писать **начиная с C++17**.
2. Второй блок `namespace course::graphics` **дополняет то же самое** пространство: теперь в нём есть и `draw`, и `clear`.
3. `namespace gfx = course::graphics;` — **псевдоним**, сокращающий длинное имя.
4. `gfx::clear()` и `gfx::draw()` вызывают функции из `course::graphics`.
:::

### Безымянное пространство имён

```cpp
#include <iostream>

namespace {
    int counter = 0;
}

void increment() {
    ++counter;
}

int main() {
    increment();
    std::cout << counter << '\n'; // 1
}
```

`counter` — деталь реализации **этой единицы трансляции**. В другом `.cpp` одноимённый счётчик в безымянном пространстве будет **отдельным объектом**.

### Где применять безымянное пространство?

- В `.cpp`: для вспомогательных функций и переменных, которые не должны предоставляться другим единицам трансляции.
- **Единица трансляции** — исходный файл после обработки `#include` и остальных директив препроцессора.
- Это **не запрет доступа** из `main` в том же файле и не механизм защиты данных.
- В заголовке такие объявления создадут **отдельные сущности в каждой включающей его единице трансляции**; обычно это не то, что нужно для общего состояния.
