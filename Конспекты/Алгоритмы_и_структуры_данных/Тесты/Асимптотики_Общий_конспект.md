# Асимптотики: общий конспект

## 1. Алгоритм, модель вычислений и функция трудоёмкости

:::meaning
**Алгоритм** — точная конечная последовательность действий, которая за конечное число шагов преобразует **вход** (входные данные) в **выход** (результат).
:::

- **Точная** — каждый шаг определён однозначно.
- **Конечная** — алгоритм обязан завершиться.
- Алгоритм всегда работает с **памятью**, где хранятся вход, промежуточные данные и выход, и выполняется на некоторой **модели вычислений**.

```diagram
title: Алгоритм как преобразование входа в выход
A: round "Вход"
B: box "Алгоритм"
C: round "Выход"
M: db "Память"
A -> B
B -> C
B -> M : читает и пишет
```

### 1.1. Машина Тьюринга

:::meaning
**Машина Тьюринга** — абстрактная модель вычислений: бесконечная лента с ячейками, головка (читает и пишет символ, сдвигается на одну ячейку влево или вправо), конечное множество состояний и таблица переходов.
:::

Любую вычислимую функцию можно вычислить на машине Тьюринга. Это **тезис Чёрча–Тьюринга**: он не доказывается, потому что понятие «вычислимо каким-либо алгоритмом» интуитивное. Все известные модели вычислений (в том числе RAM) эквивалентны машине Тьюринга по мощности.

:::warning
Тезис говорит о **принципиальной вычислимости**, а не об **эффективности**. Задача может решаться на машине Тьюринга, но за экспоненциальное число шагов. Для оценок скорости удобнее модель, близкая к реальному компьютеру, — RAM.
:::

### 1.2. RAM и word RAM

:::meaning
**RAM** (Random Access Machine) — модель с памятью в виде массива ячеек. К любой ячейке можно обратиться напрямую по номеру (адресу) за один шаг. У машины Тьюринга доступ последовательный.

**word RAM** — уточнение RAM: память состоит из ячеек (машинных слов) одинаковой фиксированной длины $w$ бит. За одну операцию обрабатывается целое слово.
:::

| | Машина Тьюринга | RAM |
|---|---|---|
| Память | бесконечная лента | массив ячеек с адресами |
| Доступ | последовательный, головка сдвигается по одной ячейке | прямой, по номеру, за один шаг |
| Близость к реальному компьютеру | далека | гораздо ближе |

:::remember
В модели word RAM **любая операция над двумя машинными словами выполняется за $1$ такт**: арифметика ($+,-,*,/,\%$), сдвиги ($>>$, $<<$), сравнения ($<,>,=$), условные переходы `if`/`else`. Поэтому, например, сложение двух чисел — это $O(1)$.
:::

:::warning
Это верно, пока числа помещаются в одно слово длины $w$. Для «длинной арифметики» операция раскладывается на несколько операций над словами и уже не $O(1)$.
:::

### 1.3. Ограничение на объём данных

Одно слово из $w$ бит принимает ровно $2^w$ значений. Адрес ячейки — тоже число, которое хранится в слове, поэтому:

:::formula
$$
\text{число адресуемых ячеек памяти} \le 2^{w}
$$
:::

Размер входа в модели word RAM ограничен: больше $2^w$ элементов в адресуемой памяти не разместить.

### 1.4. Атомарные операции и функция $T(n)$

Для анализа действия алгоритма раскладываются на **атомарные операции**: сложение, вычитание, умножение, деление, одна итерация цикла (проверка условия и переход). Каждая считается выполняющейся за постоянное время, не зависящее от размера входа.

:::meaning
**Функция трудоёмкости** $T(n)$ — количество атомарных операций, которые алгоритм выполняет на входе размера $n$. Она показывает, как растёт объём работы с ростом входа, и служит основой для сравнения алгоритмов.
:::

:::example
Суммирование элементов массива из $n$ элементов:

```python
sum = 0
for i in range(n):        # i = 0 .. n-1
    sum = sum + a[i]
```

1. На каждой итерации выполняется одно сложение.
2. Итераций ровно $n$.
3. Следовательно, $T(n) = n$.
:::

```quiz

```

## 2. Зачем нужна асимптотическая оценка

Допустим, два алгоритма имеют трудоёмкости

$$
T_1(n) = n^3 + 15n^2 + 72, \qquad T_2(n) = 550000n^2 + 352n + 4.
$$

У $T_2$ огромный коэффициент, поэтому на малых $n$ она проигрывает. Посчитаем значения:

| $n$ | $T_1(n)$ | $T_2(n)$ |
|---|---|---|
| $10$ | $2\,572$ | $\approx 5.5\cdot 10^7$ |
| $100$ | $\approx 1.15\cdot 10^6$ | $\approx 5.5\cdot 10^9$ |
| $1\,000$ | $\approx 1.015 \cdot 10^9$ | $\approx 5.5\cdot 10^{11}$ |
| $10\,000$ | $\approx 1.0015\cdot 10^{12}$ | $\approx 5.5\cdot 10^{13}$ |
| $600\,000$ | $\approx 2.16\cdot10^{17}$ | $\approx 1.98\cdot10^{17}$ |
| $10^7$ | $10^{21}$ | $\approx 5.5\cdot 10^{19}$ |

```plot
title: T₁(n) и T₂(n) вблизи точки пересечения
caption: По оси x — n в тысячах, по оси y — значение T в единицах 10^12. Кривые пересекаются при n около 550 000.
x: 0..700 y: 0..400000 grid
y = x^3/1000 + 0.015*x^2 {color: red, label: "T1 (кубическая)"}
y = 0.55*x^2 + 0.000352*x {color: blue, label: "T2 (квадратичная)"}
x = 550 {color: gray, dashed, label: "n ≈ 550 000"}
```

Кубическая $T_1$ рано или поздно обгоняет квадратичную $T_2$: большую степень не компенсирует никакая константа.

:::remember
При $n \to \infty$ поведение функции определяется **старшим (доминирующим) слагаемым**. Константы и слагаемые низших порядков несущественны. На этом строятся **асимптотические оценки** — оценки роста функции «в пределе».
:::

Асимптотические оценки позволяют:

1. Сравнивать алгоритмы независимо от «железа», языка и мелких деталей реализации.
2. Не считать точные константы.
3. Предсказывать поведение на больших данных. Например, при $O(n^2)$ увеличение входа в $10$ раз увеличивает время примерно в $100$ раз.
4. Давать гарантии: алгоритм никогда не будет работать дольше, чем $c\cdot g(n)$ шагов. Это важно для систем реального времени.

## 3. Асимптотические обозначения

**Порядок роста** — то, как быстро растёт $T(n)$ при $n \to \infty$ без учёта констант и младших слагаемых. Буква $O$ происходит от немецкого *Ordnung* — «порядок».

Оценки напоминают асимптоты функции из анализа: функция $g(n)$ «обрамляет» рост $T(n)$ сверху или снизу, но не обязательно совпадает с ним.

### 3.1. Оценка сверху: $O$

:::meaning
$$
f(n) \in O(g(n)) \iff \exists\, c > 0,\ \exists\, n_0 > 0:\ \forall n > n_0:\ 0 \le f(n) \le c \cdot g(n).
$$
:::

Разбор кванторов:

- $\exists c>0$ — найдётся фиксированная константа (не зависящая от $n$), поэтому постоянные множители «не учитываются»: $5n$ и $1000n$ оба $O(n)$.
- $\exists n_0$ — поведение при малых $n$ неважно, нужен лишь некоторый порог.
- $\forall n>n_0$ — дальше неравенство выполняется без исключений.

$O(g(n))$ — это **множество** функций, растущих не быстрее $g$ (с точностью до константы). Строго нужно писать $f \in O(g)$, но по традиции пишут $f = O(g)$.

Графически: начиная с $n_0$ график $c\cdot g(n)$ идёт не ниже графика $f(n)$ и образует для него «потолок».

:::warning
$O$ — оценка **только сверху**. Утверждение $f(n)=O(n^2)$ не означает, что $f$ растёт как $n^2$: функция $f(n)=n$ тоже удовлетворяет ему.
:::

:::example
Докажем, что $3n + 5 \in O(n)$.

1. Возьмём $c = 4$. Нужно, чтобы $3n + 5 \le 4n$ при всех $n > n_0$.
2. Решаем неравенство: $3n + 5 \le 4n \iff 5 \le n$.
3. Значит, $n_0 = 5$ подходит.
4. Следовательно, $3n+5 \in O(n)$.

Пара $(c, n_0)$ определяется неоднозначно: важно, что хотя бы одна такая пара существует.
:::

```plot
title: 3n + 5 = O(n): потолок 4n при n > 5
x: 0..12 y: 0..50 grid
y = 3*x + 5 {color: blue, label: "f(n) = 3n + 5"}
y = 4*x {color: red, dashed, label: "c·g(n) = 4n"}
x = 5 {color: gray, dashed, label: "n0 = 5"}
```

### 3.2. Оценка снизу: $\Omega$

:::meaning
$$
f(n) \in \Omega(g(n)) \iff \exists\, c > 0,\ \exists\, n_0 > 0:\ \forall n > n_0:\ 0 \le c \cdot g(n) \le f(n).
$$
:::

$f$ растёт **не медленнее** $g$: график $c\cdot g(n)$ служит «полом» для $f(n)$. Оценки двойственны: $f \in O(g) \iff g \in \Omega(f)$.

### 3.3. Точная оценка: $\Theta$

:::meaning
$$
f(n) \in \Theta(g(n)) \iff \exists\, c_1, c_2 > 0,\ n_0 > 0:\ \forall n > n_0:\ 0 \le c_1 \cdot g(n) \le f(n) \le c_2 \cdot g(n).
$$
:::

$f$ растёт **с тем же порядком**, что $g$: она зажата в «коридоре» между двумя кратными $g$. Если $f \in \Theta(g)$, то одновременно $f \in O(g)$ и $f \in \Omega(g)$.

```plot
title: Θ-оценка: f(n) = n²/2 + 3n зажата между n²/2 и 2n²
caption: При n > 2 выполнено n²/2 ≤ f(n) ≤ 2n², то есть n0 = 2, c1 = 1/2, c2 = 2.
x: 0..8 y: 0..100 grid
y = 2*x^2 {color: red, dashed, label: "c2·g(n)"}
y = x^2/2 + 3*x {color: blue, label: "f(n)"}
y = x^2/2 {color: green, dashed, label: "c1·g(n)"}
x = 2 {color: gray, dashed, label: "n0"}
```

:::remember
- Известна только $O$ — «не хуже, чем».
- Известна только $\Omega$ — «не лучше, чем».
- Известна $\Theta$ — порядок роста известен точно.
:::

### 3.4. Оценки и лучший/худший/средний случай — разные оси

1. $O$, $\Omega$, $\Theta$ описывают **форму роста** функции $T(n)$ (линейно, квадратично, логарифмически и т. д.).
2. **Лучший, худший и средний случаи** описывают, **на каких входах** размера $n$ измеряется время.

Эти понятия независимы и комбинируются. У одного алгоритма может быть несколько функций $T(n)$ (по одной на случай), и для каждой ставится своя оценка $O$, $\Omega$ или $\Theta$.

:::warning
$O$ — **не синоним** «худшего случая». $O$-оценку можно ставить и для лучшего, и для среднего случая.
:::

### 3.5. Свойства

**Транзитивность** (верна для $O$, $\Omega$, $\Theta$):

$$
f \in O(g),\ g \in O(h) \implies f \in O(h).
$$

**Рефлексивность** (достаточно $c=1$):

$$
f \in O(f),\quad f \in \Omega(f),\quad f \in \Theta(f).
$$

**Симметрия** — только для $\Theta$:

$$
f \in \Theta(g) \iff g \in \Theta(f).
$$

:::warning
Для $O$ и $\Omega$ симметрии нет: это направленные отношения «не быстрее» и «не медленнее», а не «равенство скоростей».
:::

### 3.6. Арифметика оценок

Эти правила позволяют оценивать составные алгоритмы, не возвращаясь к определению.

| Правило | Формула | Пример |
|---|---|---|
| Сумма | $f_1+f_2 = O(\max(g_1, g_2))$ | $O(n)+O(n^2)=O(n^2)$ (два цикла подряд) |
| Произведение | $f_1\cdot f_2 = O(g_1\cdot g_2)$ | $O(n)\cdot O(n)=O(n^2)$ (вложенные циклы) |
| Умножение на константу | $c\cdot f_1 = O(g_1)$ | $1000n = O(n)$ |
| Прибавление константы | $f_1 + c = O(g_1)$, если $g_1$ не стремится к $0$ | $n + 5 = O(n)$ |

:::note
Все правила следуют из определения $O$: константы и меньшие слагаемые «поглощаются» подбором достаточно большой константы $c$.
:::

## 4. Классификация сложности

От медленного роста к быстрому:

$$
O(1) \ll O(\log n) \ll O(n) \ll O(n\log n) \ll O(n^2) \ll O(n^3) \ll \dots \ll O(2^n) \ll O(n!)
$$

```plot
title: Рост основных функций
caption: Чем правее и выше уходит кривая, тем быстрее растёт время работы.
x: 1..8 y: 0..40 grid
y = 1 {color: gray, label: "1"}
y = log2(x) {color: green, label: "log n"}
y = x {color: blue, label: "n"}
y = x*log2(x) {color: purple, label: "n log n"}
y = x^2 {color: orange, label: "n^2"}
y = 2^x {color: red, label: "2^n"}
```

| Оценка | Название | Пояснение |
|---|---|---|
| $O(1)$ | константная | время не зависит от размера входа (доступ к элементу массива по индексу) |
| $O(\log n)$ | логарифмическая | на каждом шаге отбрасывается часть данных (бинарный поиск) |
| $O(n)$ | линейная | один проход по всем элементам |
| $O(n\log n)$ | линейно-логарифмическая | эффективные сортировки (слиянием) |
| $O(n^k)$ | полиномиальная | «наивные» алгоритмы с вложенными циклами |
| $O(2^n)$ | экспоненциальная | полный перебор подмножеств; неприменима уже при десятках элементов |
| $O(n!)$ | факториальная | полный перебор перестановок; невыполнима уже при $n\approx 20$–$25$ |

:::remember
Полиномиальные алгоритмы ($O(n^k)$ при фиксированном $k$) считаются практически применимыми, экспоненциальные и факториальные — как правило нет.
:::

## 5. Сложность циклов

| Цикл | Число итераций | Оценка |
|---|---|---|
| `for (i = 0; i < 100; ++i)` | $100$ | $O(1)$ |
| `for (i = 0; i < n; ++i)` | $n$ | $O(n)$ |
| внешний `i < 100`, внутренний `j < n` | $100n$ | $O(n)$ |
| `for (i = 0; i * i < n; ++i)` | $\approx \sqrt{n}$ | $O(\sqrt{n})$ |

- Цикл с фиксированным числом итераций не зависит от $n$ — это $O(1)$.
- В $100n$ константа $100$ отбрасывается при переходе к асимптотике.
- Условие $i^2<n$ равносильно $i<\sqrt n$, поэтому итераций примерно $\sqrt{n}$ — это сублинейный, но не константный рост.

:::warning
Вложенность циклов сама по себе не повышает порядок роста, если один из циклов не зависит от $n$: растёт только множитель, связанный с $n$.
:::

## 6. Оценка по памяти

**Пространственная сложность** $S(n)$ — объём **дополнительной** памяти (сверх входа) в зависимости от $n$. К ней применяются те же $O$, $\Omega$, $\Theta$.

- Константная дополнительная память — алгоритм работает **на месте** (*in-place*), $O(1)$. Её специально учитывать не нужно.
- Память, растущая вместе с $n$ (например, вспомогательный массив размера $n$), входит в оценку: $O(n)$.

:::note
Более быстрый алгоритм иногда требует больше памяти. Пример: сортировка слиянием работает за $O(n\log n)$ и требует $O(n)$ памяти, а сортировка вставками — $O(n^2)$ и $O(1)$ памяти.
:::

## 7. Рекурсия и рекуррентные соотношения

:::meaning
**Рекурсия** — решение задачи, при котором функция вызывает сама себя для более мелкой подзадачи до тех пор, пока не дойдёт до **базового случая**, который решается напрямую.
:::

Рекурсию удобно изображать **деревом вызовов**: корень — исходный вызов, дети — рекурсивные вызовы, листья — базовые случаи.

- **Время** равно суммарной работе по всем узлам дерева.
- **Память стека** равна **глубине** дерева: в каждый момент «живут» только вызовы вдоль одного пути от корня.

:::warning
Не путайте: число узлов дерева определяет время, а его глубина — память стека. Эти параметры растут по-разному.
:::

### 7.1. Merge Sort и рекуррентное соотношение

Алгоритм: если элементов не больше одного — массив отсортирован. Иначе делим массив пополам, рекурсивно сортируем каждую половину и сливаем их за $O(n)$. Отсюда

$$
T(n) = 2\,T\!\left(\frac{n}{2}\right) + O(n),
$$

где $2T(n/2)$ — два рекурсивных вызова, $O(n)$ — слияние.

```tree
title: Дерево рекурсии Merge Sort (размеры подзадач)
caption: На уровне k находится 2^k вызовов размера n/2^k.
n
  n/2
    n/4
      ...
    n/4
      ...
  n/2
    n/4
      ...
    n/4
      ...
```

| Уровень | Число вызовов | Размер каждого | Суммарная работа |
|---|---|---|---|
| $0$ | $1$ | $n$ | $O(n)$ |
| $1$ | $2$ | $n/2$ | $2\cdot O(n/2)=O(n)$ |
| $2$ | $4$ | $n/4$ | $4\cdot O(n/4)=O(n)$ |
| $k$ | $2^k$ | $n/2^k$ | $2^k\cdot O(n/2^k)=O(n)$ |

На каждом уровне работа одна и та же — $O(n)$. Размер подзадачи равен $1$, когда $n/2^k=1$, то есть $k=\log_2 n$. Значит, уровней $\log_2 n$ (это же глубина, то есть память стека), и

$$
T(n) = O(n)\cdot\log_2 n = O(n\log n).
$$

## 8. Мастер-теорема

Можно ли заранее определить асимптотику рекурсивного алгоритма по его рекуррентному соотношению? Типичная схема:

```text
fun(n):
    if n is small:
        solve directly
    construct a subproblems of size n/b
    solve every subproblem recursively
    combine results
```

:::meaning
- $a \ge 1$ — число рекурсивных вызовов (подзадач).
- $n/b$ ($b>1$) — размер каждой подзадачи.
- $f(n)$ — работа вызова **вне** рекурсии: разделение на подзадачи и объединение результатов.
:::

$$
T(n) = a\,T\!\left(\frac{n}{b}\right) + f(n).
$$

Для Merge Sort: $a=2$, $b=2$, $f(n)=\Theta(n)$.

### 8.1. Дерево рекурсии в общем виде

Размер подзадачи на уровне $k$ равен $n/b^k$. Рекурсия заканчивается при $n/b^k=1$, то есть глубина дерева $k=\log_b n$. На уровне $i$ находится $a^i$ узлов, поэтому число листьев:

:::formula
$$
a^{\log_b n} = n^{\log_b a}
$$
:::

Работа по уровням: $f(n)$; $a\,f(n/b)$; $a^2 f(n/b^2)$; …; $a^k f(n/b^k)$. Суммарно:

$$
T(n) = \sum_{i=0}^{\log_b n} a^i \cdot f\!\left(\frac{n}{b^i}\right).
$$

Для произвольной $f$ эту сумму оценить сложно, поэтому сначала разбирается частный случай $f(n)=n^c$.

### 8.2. Случай $f(n) = n^c$

$$
T(n) = \sum_{i=0}^{\log_b n} a^i\left(\frac{n}{b^i}\right)^c = n^c\sum_{i=0}^{\log_b n} q^i,\qquad q = \frac{a}{b^c}.
$$

От уровня к уровню работа умножается на $q$. Сумма геометрической прогрессии: $\sum_{i=0}^{m-1} q^i = \dfrac{1-q^m}{1-q}$ (при $q\ne1$).

- **$q = 1$**, то есть $a=b^c$. Все уровни выполняют одинаковую работу, всего уровней $\log_b n$: $T(n)=\Theta(n^c\log n)$.
- **$q < 1$**, то есть $a<b^c$. Прогрессия убывает, сумма ограничена константой $\frac{1}{1-q}$: $T(n)=\Theta(n^c)$. Работа определяется корнем.
- **$q > 1$**, то есть $a>b^c$. Прогрессия возрастает, сумма определяется последним слагаемым: $\Theta\!\left(q^{\log_b n}\right)$. Подстановка:

$$
n^c\cdot\frac{a^{\log_b n}}{b^{c\log_b n}} = n^c\cdot\frac{a^{\log_b n}}{n^c} = a^{\log_b n} = n^{\log_b a}.
$$

Работа определяется листьями: $T(n)=\Theta(n^{\log_b a})$.

### 8.3. Классическая мастер-теорема

:::formula
Для $T(n)=a\,T(n/b)+n^c$, где $a\ge1$, $b\ge2$, $c\ge0$ — константы:

$$
T(n) \in
\begin{cases}
\Theta(n^c), & a < b^c \ \ (c > \log_b a)\\[4pt]
\Theta(n^c \log n), & a = b^c \ \ (c = \log_b a)\\[4pt]
\Theta\left(n^{\log_b a}\right), & a > b^c \ \ (c < \log_b a)
\end{cases}
$$
:::

Удобно обозначить $d=\log_b a$ — критическое значение показателя. Условие $a/b^c \gtrless 1$ равносильно $c \lessgtr d$, потому что $a/b^c=b^{d-c}$.

```diagram
title: Как выбрать случай мастер-теоремы
A: round "Найти a, b, c"
B: box "Вычислить d = log_b a"
C: diamond "Сравнить c и d"
D: box "c меньше d: T = Θ(n^d)"
E: box "c равно d: T = Θ(n^c log n)"
F: box "c больше d: T = Θ(n^c)"
A -> B
B -> C
C -> D : меньше
C -> E : равно
C -> F : больше
```

:::example
**Merge Sort.** $T(n)=2T(n/2)+n$: $a=2$, $b=2$, $c=1$.

1. $d=\log_2 2=1$.
2. $c=d$ — средний случай.
3. $T(n)=\Theta(n^1\log n)=\Theta(n\log n)$ — совпадает с результатом подсчёта по дереву.
:::

:::example
**Рекуррентность $T(n)=2T(n/3)+n^2$.**

1. $a=2$, $b=3$, $c=2$; $b^c=9$.
2. $a=2<9=b^c$, то есть $c>d=\log_3 2$.
3. Доминирует корень: $T(n)=\Theta(n^2)$.
:::

:::warning
Типичные ошибки:

1. $c$ — показатель работы **одного вызова**, а не всей задачи.
2. Сравнивать нужно $c$ с $d=\log_b a$ (или $a$ с $b^c$), а не $a$ с $b$.
3. Теорема применима, только если задача делится на $a$ подзадач **одинакового** размера $n/b$ и $f(n)=\Theta(n^c)$.
:::

### 8.4. Мастер-теорема для произвольной $f(n)$

Функция $f(n)$ сравнивается с суммарной работой в листьях — $n^{\log_b a}$. Три случая:

1. **Листья доминируют.** Если $\exists\,\varepsilon>0:\ f(n)\in O\!\left(n^{\log_b a-\varepsilon}\right)$, то $T(n)\in\Theta\!\left(n^{\log_b a}\right)$.
2. **Все уровни равны.** Если $f(n)\in\Theta\!\left(n^{\log_b a}\right)$, то $T(n)\in\Theta\!\left(n^{\log_b a}\log n\right)$.
3. **Корень доминирует.** Если $\exists\,\varepsilon>0:\ f(n)\in\Omega\!\left(n^{\log_b a+\varepsilon}\right)$ **и** выполнено условие регулярности

$$
\exists\, a_0<1,\ n_0>0:\ \forall n>n_0:\quad a\,f\!\left(\frac{n}{b}\right)\le a_0\, f(n),
$$

то $T(n)\in\Theta(f(n))$.

:::meaning
Условие регулярности гарантирует, что вклад каждого следующего уровня не больше вклада предыдущего, умноженного на $a_0<1$. Тогда вклад корня доминирует над суммой остальных.
:::

:::warning
Если ни одно из трёх условий не выполнено (например, $f(n)=\Theta(n\log n)$ при $a=b=2$: нет полиномиального зазора $n^\varepsilon$), классическая мастер-теорема неприменима. Тогда сумму по уровням считают напрямую.
:::

### 8.5. Рекуррентность для памяти

Для памяти рекурсивного алгоритма аналогично записывается $M(n)=a\cdot M(n/b)+s(n)$, где $s(n)$ — память текущего вызова вне рекурсии. Эта запись соответствует случаю, когда память подзадач суммируется. Если память подвызовов освобождается и используется повторно (как у стека вызовов), память определяется глубиной дерева, то есть путём от корня до листа.

## 9. Сортировки и их асимптотика

### 9.1. Ключ и устойчивость

:::meaning
**Ключ сортировки** — характеристика элемента (поле), по значению которой выполняется сравнение.

Сортировка **устойчива**, если сохраняет относительный порядок элементов с равными ключами.
:::

Устойчивость критична при последовательной сортировке по нескольким ключам: если сначала отсортировать по оценке, а затем по возрасту, то устойчивая сортировка сохранит внутри одного возраста порядок по оценке. Неустойчивая — не гарантирует.

### 9.2. Сортировка вставками

Массив делится на отсортированную часть (начало) и необработанную. На каждом шаге очередной элемент вставляется в нужное место отсортированной части со сдвигом больших элементов вправо.

```python
def insertion_sort(a, n):
    for i in range(1, n):        # i = 1 .. n-1
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j = j - 1
        a[j + 1] = key
```

```array
title: Сортировка вставками
[6, 3, 8, 2, 5]
pointers: i, j
print: last
code:
for (let i = 1; i < a.length; i++) {
  let key = a[i];
  let j = i - 1;
  while (j >= 0 && a[j] > key) {
    a[j + 1] = a[j];
    j = j - 1;
  }
  a[j + 1] = key;
  done(0, i);
}
```

**Худший случай** (массив по убыванию): на шаге $i$ сдвигается $i$ элементов, поэтому

$$
T(n)=\sum_{i=1}^{n-1} i = \frac{(n-1)\,n}{2}=\frac{n^2-n}{2}.
$$

:::example
Докажем по определению, что $\dfrac{n^2-n}{2}\in O(n^2)$.

1. Берём $c=1$, $n_0=1$. При $n>1$ имеем $n^2-n\ge0$, значит, $0\le\frac{n^2-n}{2}$.
2. Проверяем верхнюю границу: $\frac{n^2-n}{2}\le n^2 \iff n^2-n\le 2n^2 \iff -n\le n^2$.
3. Последнее верно при всех $n\ge0$.
4. Следовательно, $\frac{n^2-n}{2}\in O(n^2)$.

Множитель $\frac12$ и младшее слагаемое $-n$ не меняют порядок роста: первый уходит в константу $c$, а второй при больших $n$ мал по сравнению с $n^2$.
:::

- **Лучший случай** (массив отсортирован): внутренний цикл не выполняется, $T(n)=\Theta(n)$.
- **Худший и средний случаи:** $\Theta(n^2)$ (в среднем элемент сдвигается примерно на половину пройденной части — множитель $\frac12$ порядок не меняет).
- **Память:** $O(1)$ (работает на месте).
- **Устойчивость:** устойчива, так как сдвигаются только элементы, строго большие `key` (`a[j] > key`).

### 9.3. Инверсии и время сортировки вставками

:::meaning
**Инверсия** массива $a$ — пара индексов $i<j$, для которой $a[i]>a[j]$. Обозначим $Inv(a)$ — общее число инверсий.
:::

- **Лучший случай:** $Inv(a)=0$ — массив отсортирован.
- **Худший случай:** $Inv(a)=\dfrac{n(n-1)}{2}=\binom n2$ (каждая пара — инверсия, массив по убыванию), то есть $\Theta(n^2)$.

Элемент $a[i]$ при сортировке вставками сдвигается ровно столько раз, сколько элементов левее него больше его — то есть на число инверсий, где он стоит правее. Суммарное число сдвигов равно $Inv(a)$, поэтому

:::formula
$$
T(n) = \Theta\bigl(n + Inv(a)\bigr)
$$
:::

Чем меньше инверсий, тем быстрее работает сортировка вставками. При $Inv(a)=0$ время линейно.

### 9.4. Сортировка слиянием

Метод **«разделяй и властвуй»**: разделить задачу на подзадачи, решить их рекурсивно, объединить решения.

```python
def merge_sort(a, l, r):          # сортирует a[l..r-1]
    if r - l <= 1:
        return
    mid = (l + r) // 2
    merge_sort(a, l, mid)
    merge_sort(a, mid, r)
    merge(a, l, mid, r)
```

Функция `merge` сливает две отсортированные части с помощью временного буфера и двух указателей. Меньший из текущих элементов записывается в буфер; при равенстве берётся элемент **левой** части (это даёт устойчивость). Когда одна часть закончилась, остаток другой дописывается в буфер, затем буфер копируется назад. Слияние диапазона размера $n$ стоит $O(n)$ времени и $O(n)$ памяти.

**Итеративная (восходящая) версия.** Блоки длины $s=1,2,4,\dots$ попарно сливаются, пока $s<n$. Проходов около $\log_2 n$ (для $n=7$ — три прохода: $s=1,2,4$), каждый проход стоит $O(n)$.

```array
    }

    }
  }
  say("swap(arr, buf): результат прохода копируется в a");
  for (let q = 0; q < n; q++) {
    a[q] = buf[q];
  }
}
done(0, n - 1);
```

**Оценка.** По мастер-теореме $T(n)=2T(n/2)+\Theta(n)$ даёт

$$
T(n)=\Theta(n\log n)
$$

во всех случаях — лучшем, худшем и среднем: алгоритм всегда делит массив пополам и всегда выполняет полное слияние. Память $O(n)$. Алгоритм устойчив.

### 9.5. Сортировка выбором и пирамидальная сортировка

**Сортировка выбором:** на каждом шаге максимум неотсортированной части ищется просмотром и переносится в конец. Число сравнений

$$
(n-1)+(n-2)+\dots+1=\frac{n(n-1)}{2}=O(n^2).
$$

Слабое место: результаты сравнений не сохраняются.

**Мотивация (турниры).** Круговая система ($n(n-1)$ матчей) — $O(n^2)$, как у сортировки выбором. Кубковая система находит победителя за $n-1$ матч, а следующее место — ещё за $O(\log n)$ игр (второй — среди проигравших победителю напрямую). Все места определяются за $O(n)+n\cdot O(\log n)=O(n\log n)$. Кубковая сетка — дерево, хранящее результаты сравнений, и эту роль играет пирамида.

:::meaning
**Макс-куча (пирамида)** — завершённое бинарное дерево (заполнены все слои, кроме последнего, последний заполняется слева направо), в котором значение каждого узла не меньше значений его детей. Максимум находится в корне. В **мин-куче** — наоборот.
:::

Куча хранится в массиве (индексация с нуля):

:::formula
- левый ребёнок узла $i$: $2i+1$
- правый ребёнок: $2i+2$
- родитель: $\left\lfloor \dfrac{i-1}{2} \right\rfloor$
:::

Листья — узлы с индексами от $\lfloor n/2\rfloor$ до $n-1$, их $\lceil n/2\rceil$. Высота дерева $\Theta(\log n)$.

:::warning
Куча упорядочена только между узлом и его детьми, но не между поддеревьями. Максимум всегда в корне, но минимум может быть в любом листе.
:::

**Просеивание вниз (`siftdown`):** пока у узла есть дети, выбирается **больший** ребёнок. Если узел меньше него — они меняются местами, и мы спускаемся ниже. Каждый обмен опускает элемент на уровень, поэтому одно просеивание стоит $O(\log n)$.

**Пирамидальная сортировка:**

```python
def heap_sort(a):
    n = len(a)
    for i in range(n // 2 - 1, -1, -1):   # построение кучи
        sift_down(a, i, n)
    for end in range(n - 1, 0, -1):       # извлечение максимумов
        a[0], a[end] = a[end], a[0]
        sift_down(a, 0, end)
```

**Построение кучи за $O(n)$.** Оценка «$n/2$ узлов по $O(\log n)$» слишком грубая. Просеивание узла высоты $h$ стоит порядка $h$, а узлов высоты $h$ не более $\lceil n/2^{h+1}\rceil$. Поэтому

$$
\sum_{h=0}^{\log n}\frac{n}{2^{h+1}}\cdot O(h)=O\!\left(n\sum_{h=0}^{\infty}\frac{h}{2^h}\right)=O(n),
$$

потому что ряд $\sum h/2^h$ сходится (к $2$). Основная часть узлов находится у листьев, где просеивание дёшево.

| Действие | Время |
|---|---|
| Сортировка выбором | $O(n^2)$ |
| Одно просеивание | $O(\log n)$ |
| Построение кучи | $O(n)$ |
| $n$ извлечений максимума | $n\cdot O(\log n)=O(n\log n)$ |
| Пирамидальная сортировка | $O(n)+O(n\log n)=O(n\log n)$ |

### 9.6. Сортировка подсчётом

Применяется к целым числам из диапазона (алфавита) размера $k$. Строится массив $C$ количества вхождений. Для сохранения объектов и устойчивости строятся **префиксные суммы** $P[i]=C[0]+\dots+C[i]$, а исходный массив обходится **справа налево**: элемент с ключом $i$ кладётся на позицию $P[i]-1$, после чего $P[i]$ уменьшается.

Размер алфавита: за один проход $O(n)$ находятся $\min$ и $\max$, затем $k=\max-\min+1$, а индекс в $C$ равен $x-\min$.

Время: $O(n)+O(n)+O(k)+O(n)$, то есть

:::formula
$$
T(n,k) = O(n+k),\qquad \text{память } O(n+k).
$$
:::

Алгоритм выгоден, только если $k$ сопоставимо с $n$; при $k\gg n$ он невыгоден.

### 9.7. Поразрядная сортировка (radix sort)

Числа сортируются по разрядам устойчивой сортировкой подсчётом: **LSD** — от младшего разряда к старшему, **MSD** — от старшего к младшему. Если $d$ — число разрядов, а $k$ — размер алфавита одного разряда (для десятичных цифр $k=10$), то каждый проход стоит $O(n+k)$ и

:::formula
$$
T = O\bigl(d\,(n+k)\bigr).
$$
:::

При постоянных $d$ и $k$ время линейно: $O(n)$. Для LSD устойчивость сортировки на каждом шаге **обязательна**.

### 9.8. Сводная таблица

| Алгоритм | Лучший | Средний | Худший | Память | Устойчива |

| Слиянием | $\Theta(n\log n)$ | $\Theta(n\log n)$ | $\Theta(n\log n)$ | $O(n)$ | да |
| Выбором | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | — | — |
