# Куча и динамическое программирование

## Куча

### Что такое куча

Куча (пирамида) устроена на двух уровнях:

- **логически** это бинарное дерево;
- **физически** это обычный массив, в котором элементы дерева лежат подряд.

:::meaning
**Куча** — бинарное дерево, хранимое в физическом массиве, в корне которого всегда находится самый «главный» элемент: минимум или максимум (в зависимости от вида кучи).
:::

Главное удобство кучи: **минимум или максимум находится за $O(1)$** — достаточно взять элемент из корня, то есть первый элемент массива.

Кучу используют для сортировок: пирамидальной и основанной на вставках элементов в кучу.

#### Нумерация узлов

Узлы дерева нумеруются сверху вниз и слева направо, начиная с нуля. Эта нумерация и есть индексы элементов в физическом массиве.

Разберём пример — кучу, в которой в корне стоит максимум:

```array
title: Куча в массиве (индексы 0–7)
[105, 81, 95, 65, 75, 55, 45, 25] highlight: 5
```

```tree
105
  81
    65
      25
    75
  95
    55
    45
```

Индексы узлов: $105$ — $0$, $81$ — $1$, $95$ — $2$, $65$ — $3$, $75$ — $4$, $55$ — $5$, $45$ — $6$, $25$ — $7$.

:::remember
Связь индексов в массиве-куче (нумерация с нуля):

- у узла с индексом $i$ дети имеют индексы $2i + 1$ и $2i + 2$;
- у узла с индексом $i > 0$ родитель имеет индекс $\lfloor (i - 1) / 2 \rfloor$.

Например, у узла $7$ (значение $25$) родитель — узел $3$ (значение $65$), у узла $5$ (значение $55$) родитель — узел $2$ (значение $95$).
:::

:::note
В этой куче каждый родитель не меньше своих детей: $105 \ge 81, 95$; $81 \ge 65, 75$; $95 \ge 55, 45$; $65 \ge 25$. Именно поэтому максимум лежит в корне.
:::

### Аналогия: Яндекс Такси

Работу кучи удобно представлять на примере Яндекс Такси: находим таксиста, он отвечает — повезёт или нет. При этом заявки выстраиваются в **очередь**.

:::note
На рисунке: треугольник (пирамида) с отмеченными вершинами; основание треугольника подписано словом «очередь».
:::

Очереди встречаются и в маршрутах: их можно строить по километражу, по времени и по другим признакам.

### Пирамида как паттерн

Пирамида — первый паттерн, который учит нас работать с **предыдущими вычислениями**: результат уже проделанной работы (упорядоченность элементов) сохраняется в структуре и используется в следующих операциях, а не вычисляется заново.

### Очередь с приоритетом

Чтобы использовать принцип очереди на пирамиде, нужно научиться выполнять с ней операции. Начнём с добавления.

#### Добавление элемента

В очередь нужно уметь добавлять элементы. Новый элемент встаёт на своё место с помощью операции **sift up** («всплытие»): элемент поднимается вверх по дереву, пока не окажется на подходящем месте.

#### Что такое приоритет

:::meaning
**Приоритет** — динамический признак объекта, по которому определяется его место в очереди. «Динамический» значит, что приоритет может меняться со временем.
:::

Пример: поступление, конкурсные списки — положение абитуриента в списке определяется его приоритетом.

:::meaning
**Очередь с приоритетом** — очередь, в которой порядок элементов определяется их приоритетами.
:::

#### Как связаны очередь и пирамида

Очередь — это **надстройка над пирамидой**: она реализуется через пирамиду. А сама очередь — просто массив, в котором хранятся элементы пирамиды.

### Повышение приоритета

Приоритет элемента может измениться. Разберём пример на уже знакомой куче: у элемента с индексом $5$ приоритет увеличивается с $55$ до $96$.

$$
55 \xrightarrow{\text{увеличим приоритет}} 96
$$

:::example
Пошаговый разбор повышения приоритета элемента с индексом $5$:

1. Меняем значение в узле $5$: вместо $55$ записываем $96$.
2. Сравниваем с родителем — узлом $2$ (значение $95$). Так как $96 > 95$, нарушен порядок кучи, и элементы меняются местами. Теперь $96$ стоит в узле $2$.
3. Сравниваем с новым родителем — узлом $0$ (значение $105$). Так как $96 < 105$, порядок не нарушен, подъём заканчивается.

Итог: элемент поднимается с позиции $5$ на позицию $2$. Массив становится таким: $[105, 81, 96, 65, 75, 95, 45, 25]$.
:::

```tree
105
  81
    65
      25
    75
  96
    95
    45
```

Тот же подъём пошагово:

```array
title: Подъём элемента (sift up) после повышения приоритета
[105, 81, 95, 65, 75, 55, 45, 25]
pointers: i, p
print: last
code:
let i = 5;
let p = 0;
a[i] = 96;
say("Приоритет элемента с индексом 5 увеличен с 55 до 96");
while (i > 0) {
  p = Math.floor((i - 1) / 2);
  if (a[p] < a[i]) {
    swap(a, p, i);
    i = p;
  } else {
    break;
  }
}
```

:::remember
Приоритет **увеличили** — элемент поднимается вверх (**sift up**).
:::

### Удаление элемента

Бывает, что элемент нужно убрать из очереди: например, студент хочет забрать документы. Поэтому надо научиться **удалять** элемент.

Алгоритм удаления:

1. Перемещаем удаляемый элемент в конец массива.
2. Уменьшаем размер кучи: $size \to size - 1$ (последняя ячейка больше не принадлежит куче).
3. Выполняем **sift down** и **sift up** для элемента, который оказался на освободившемся месте.

```diagram
title: Удаление элемента из кучи
A: round "Элемент выбран для удаления"
B: box "Переместить его в конец массива"
C: box "size = size - 1"
D: box "sift down"
E: box "sift up"
A -> B
B -> C
C -> D
D -> E
```

:::note
На место удалённого элемента попадает бывший последний элемент. Он может оказаться больше родителя (тогда сработает sift up) или меньше детей (тогда сработает sift down). Выполняются обе операции, но фактически сдвинуть элемент сможет только одна из них.
:::

### Понижение приоритета

Кроме того, надо уметь **уменьшать** приоритет. После уменьшения элемент опускается вниз по дереву — выполняется **sift down**.

:::remember
- Приоритет **увеличили** → **sift up** (подъём).
- Приоритет **уменьшили** → **sift down** (спуск).
:::

### Поиск элемента в куче

Прежде чем изменить или удалить элемент, его **нужно найти в куче**. Это отдельная задача: куча упорядочена только «вдоль» веток, и произвольный элемент в ней просто так не найти.

В принципе, для поиска можно сделать бинарное дерево поиска. Но платить за поиск $O(\log n)$ не хочется. Можно искать за $O(1)$:

- поиск идёт **по уникальному значению**;
- для этого значения хранится **указатель** на то место, где элемент лежит в куче.

```diagram
title: Поиск элемента в куче за O(1)
A: box "Уникальное значение"
B: box "Указатель"
C: box "Элемент в куче"
A -> B
B -> C : O(1)
```

:::warning
Поиск по указателю работает только для **уникальных** значений: по неуникальному значению нельзя однозначно определить, о каком элементе идёт речь.
:::

### Итог по очереди с приоритетом

Так мы научились реализовывать в пирамиде очередь с приоритетами: добавление (sift up), удаление, повышение и понижение приоритета (sift up / sift down) и поиск элемента.

Приоритет может быть **неизменяемым** или задаваться **классами приоритетов**. Но тогда используются другие структуры. Например, «коробочки» с обычными очередями — по одной обычной очереди на каждый класс приоритета.

## Динамическое программирование

### Числа Фибоначчи и наивная рекурсия

Числа Фибоначчи задаются так:

$$
F_1 = F_2 = 1, \qquad F_n = F_{n-1} + F_{n-2} \quad (n \ge 3)
$$

Прямолинейная рекурсивная реализация:

```python
def fib(n):
    if n <= 2:
        return 1
    else:
        return fib(n - 1) + fib(n - 2)
```

#### Абстрактное рекурсивное дерево

Чтобы увидеть, как работает рекурсия, рисуют дерево вызовов. Для $n = 4$ оно выглядит так:

```tree
4
  3
    2
      1
    1
  2
    1
```

:::note
Это абстрактное дерево: оно показывает, из каких значений складывается результат, а не точную последовательность реальных вызовов. Вершина $2$ условно раскрывается в $1$.
:::

В дереве видно, что поддерево с вершиной $2 \to 1$ встречается **дважды**. Считать одно и то же два раза неприятно. Иногда компиляторы умеют не считать такую ветку повторно.

Количество вызовов растёт как само число Фибоначчи, то есть сложность:

$$
O(F(n))
$$

### Мемоизация

Значение $O(F(n))$ может быть огромным — например, порядка 12 миллиардов. Столько операций Python за разумное время не выполнит. **Поэтому используется мемоизация.**

:::meaning
**Мемоизация** — запоминание уже вычисленных результатов: при повторном обращении с тем же аргументом возвращается сохранённое значение вместо нового вычисления.
:::

Динамическое программирование по сути аналитический подход: ответ выражается через ответы на подзадачи.

Реализация с массивом `mem`, в котором $-1$ означает «значение ещё не вычислено»:

```python
mem = [-1] * (n + 1)
mem[1] = mem[2] = 1

def fib(n):
    if mem[n] != -1:
        return mem[n]
    else:
        mem[n] = fib(n - 1) + fib(n - 2)
        return mem[n]
```

:::warning
Массив должен иметь размер $n + 1$, чтобы индекс $n$ был допустим. Значения базовых случаев ($n \le 2$) должны быть записаны заранее — иначе рекурсия не остановится.
:::

#### Подсчёт числа вызовов

Пусть $C_n$ — число вызовов функции при вычислении $\text{fib}(n)$ без мемоизации. Базовые вызовы ($n \le 2$) — по одному: $C_0 = C_1 = C_2 = 1$. Для остальных $n$:

$$
C_n = \underbrace{C_{n-1} + C_{n-2}}_{\text{переход}} + \underbrace{1}_{\text{база}}
$$

Слагаемые $C_{n-1} + C_{n-2}$ — число вызовов в двух подзадачах («переход»), единица — сам текущий вызов («база»).

:::formula
$$
C_n = 2F(n) - 1, \qquad F(n) \approx \frac{\varphi^n}{\sqrt{5}}, \qquad \varphi = \frac{1 + \sqrt{5}}{2}
$$
:::

:::example
Почему $C_n = 2F(n) - 1$:

1. Прибавим единицу к обеим частям рекуррентности: $C_n + 1 = (C_{n-1} + 1) + (C_{n-2} + 1)$.
2. Значит, последовательность $C_n + 1$ подчиняется тому же правилу, что и числа Фибоначчи.
3. Начальные значения: $C_1 + 1 = C_2 + 1 = 2$. Это $2F_1 = 2F_2 = 2$.
4. Следовательно, $C_n + 1 = 2F(n)$, то есть $C_n = 2F(n) - 1$.

Проверка: $C_3 = 3$, $C_4 = 5$, $C_5 = 9$.
:::

Так как $F(n)$ растёт как $\varphi^n$, число вызовов растёт **экспоненциально**.

### Подход top-down (сверху вниз)

Подход top-down — это рекурсия с запоминанием: идём от исходной задачи к подзадачам. Он похож на «разделяй и властвуй».

:::remember
Суть динамического программирования — **подзадачи могут пересекаться**. Одна и та же подзадача встречается в разных ветках рекурсии, и поэтому её результат стоит запомнить.
:::

### Подход bottom-up (снизу вверх)

Можно идти и в обратную сторону — от индукции к дедукции: от базовых значений к искомому. Это подход **bottom-up**, он называется **табуляцией**.

Тогда для чисел Фибоначчи массив не нужен — достаточно хранить только 3 элемента:

```python
def fib(n):
    if n <= 2:
        return 1
    prev2, prev1 = 1, 1
    for i in range(3, n + 1):
        cur = prev1 + prev2
        prev2, prev1 = prev1, cur
    return prev1
```

### Задача «Кузнечик» (Climbing stairs)

:::meaning
**Кузнечик** — задача: клетки пронумерованы $0, 1, 2, \dots$; кузнечик стоит в клетке $0$ и может прыгать на $1$ или $2$ клетки (или, в обобщении, на любое число от $1$ до $k$ клеток). Нужно найти, **сколько способов** добраться до какой-то клетки.
:::

:::note
На рисунке: ряд клеток с номерами $0$–$5$ и дугами-прыжками от клетки $0$ к следующим клеткам; ряд продолжается многоточием.
:::

Пусть $dp[i]$ — число способов дойти до клетки $i$. Последний прыжок был из клетки $i - j$, где $j$ — длина прыжка. Значит:

$$
dp[i] = \sum_{j=1}^{k} dp[i - j], \qquad i - j \ge 0
$$

Начальное значение: $dp[0] = 1$ (в клетке $0$ кузнечик уже стоит).

```python
dp[0] = 1
for i in range(1, n + 1):
    for j in range(1, k + 1):
        if i - j >= 0:
            dp[i] += dp[i - j]
```

:::example
Для $k = 2$ (прыжки на 1 или 2) заполняем клетки $0$–$5$ слева направо:

1. $dp[0] = 1$.
2. $dp[1] = dp[0] = 1$ (прыжок на 2 невозможен: $1 - 2 < 0$).
3. $dp[2] = dp[1] + dp[0] = 2$.
4. $dp[3] = dp[2] + dp[1] = 3$.
5. $dp[4] = dp[3] + dp[2] = 5$.
6. $dp[5] = dp[4] + dp[3] = 8$.
:::

```array
title: Кузнечик: число способов дойти до клетки (k = 2)
[1, 0, 0, 0, 0, 0]
pointers: i, j
print: last
code:
let k = 2;
for (let i = 1; i < a.length; i++) {
  for (let j = 1; j <= k; j++) {
    if (i - j >= 0) a[i] += a[i - j];
  }
  done(i);
}
```

:::note
При $k = 2$ получаются те же числа, что и в последовательности Фибоначчи: правило $dp[i] = dp[i-1] + dp[i-2]$ совпадает с рекуррентностью чисел Фибоначчи.
:::

#### Префиксные суммы и скользящее окно

Внутренний цикл по $j$ считает сумму последних $k$ значений. Её можно получать быстрее — с помощью **префиксной суммы**. Техника называется **«скользящее окно»**: окно из $k$ последних значений сдвигается на клетку вперёд, при этом новое значение прибавляется к сумме, а выпавшее из окна — вычитается.

### Направления разбиения

Кроме разбиения **сверху вниз** и **снизу вверх** есть ещё порядок **слева направо** и **справа налево**.

### Пример: $f(k) = f(k/2) + f(k/3)$

Рассмотрим рекуррентность:

$$
f(k) = f\!\left(\frac{k}{2}\right) + f\!\left(\frac{k}{3}\right)
$$

Дерево её вызовов показывает пересечение подзадач — значение $f(k/6)$ встречается в двух ветках:

```tree
f(k)
  f(k/2)
    f(k/4)
    f(k/6)
  f(k/3)
    f(k/6)
    f(k/9)
```

Эта задача **не считается bottom-up** (не получается заполнить таблицу подряд снизу вверх), зато подход **top-down решает её за 4 строки**:

```python
def f(k):
    if k in mem:
        return mem[k]
    mem[k] = f(k // 2) + f(k // 3)
    return mem[k]
```

:::note
Деление здесь целочисленное. Словарь `mem` заранее содержит значения базовых случаев.
:::

- [ ] Из-за слишком глубокого стека рекурсии при каждом вызове :: Дело не в глубине стека, а в количестве вызовов.
- [x] Одни и те же подзадачи вычисляются много раз, и число вызовов растёт как $F(n)$ :: Ветки рекурсии пересекаются, повторные вычисления не запоминаются.
- [ ] Из-за того, что массив `mem` слишком мал :: В наивной версии массива `mem` нет.
explain: Мемоизация устраняет повторные вычисления: каждая подзадача решается один раз.

? Число вызовов $C_n$ при вычислении $\text{fib}(n)$ без мемоизации подчиняется правилу $C_n = C_{n-1} + C_{n-2} + 1$ при $C_1 = C_2 = 1$. Чему равно $C_5$? Введите целое число.
= 9
explain: $C_3 = 1 + 1 + 1 = 3$, $C_4 = 3 + 1 + 1 = 5$, $C_5 = 5 + 3 + 1 = 9$; это совпадает с $2F(5) - 1 = 2 \cdot 5 - 1 = 9$.

? Какие утверждения о подходах к динамическому программированию верны?
- [x] Top-down — рекурсия с запоминанием, похожая на «разделяй и властвуй» :: Подход идёт от исходной задачи к подзадачам.
- [x] Bottom-up (табуляция) идёт от базовых значений к ответу
- [ ] В bottom-up для чисел Фибоначчи обязательно хранить весь массив :: Достаточно трёх значений.
- [x] Суть динамического программирования в том, что подзадачи могут пересекаться
- [ ] Мемоизацию можно применять, только если подзадачи не пересекаются :: Наоборот: мемоизация полезна именно при пересечении подзадач.
explain: Общая идея — не решать одну и ту же подзадачу дважды.

? Кузнечик начинает в клетке 0 и прыгает на 1 или на 2 клетки. Сколько существует способов добраться до клетки 4? Введите целое число.
= 5
explain: $dp[0] = 1$, $dp[1] = 1$, $dp[2] = 2$, $dp[3] = 3$, $dp[4] = dp[3] + dp[2] = 5$.

? Почему рекуррентность $f(k) = f(k/2) + f(k/3)$ удобно решать подходом top-down?
- [ ] Потому что она решается bottom-up за 4 строки :: Наоборот: она не считается bottom-up.
- [x] Рекурсивная функция с запоминанием записывается всего в 4 строки :: Достаточно проверить `mem`, посчитать значение и вернуть его.
- [ ] Потому что подзадачи в ней не пересекаются :: Значение $f(k/6)$ встречается в разных ветках.
explain: Пересекающиеся подзадачи запоминаются, и рекурсия с `mem` получается короткой.

title: Итоговый тест: куча и динамическое программирование

? Какое утверждение верно описывает связь очереди с приоритетом и кучи?
- [ ] Куча реализуется через очередь с приоритетом :: Наоборот.
- [x] Очередь с приоритетом реализуется через кучу, а сама очередь — это массив :: Куча лежит в физическом массиве, а очередь является надстройкой над ней.
- [ ] Это две несвязанные структуры :: Очередь строится именно поверх кучи.
explain: Поэтому операции над очередью сводятся к sift up и sift down в куче.

? За какое время находится максимум в куче с максимумом в корне?
- [ ] $O(\log n)$ :: Столько занимают добавление и подъём элемента, но не доступ к корню.
- [x] $O(1)$ :: Максимум лежит в корне — в первой ячейке массива.
- [ ] $O(n)$ :: Просматривать весь массив не нужно.
explain: Корень кучи всегда содержит экстремальный элемент.

? В очереди с приоритетом приоритет элемента увеличили. Что произойдёт с ним в куче?
- [x] Он поднимется вверх по дереву (sift up) :: Элемент сравнивается с родителем и меняется с ним местами, пока нужно.
- [ ] Он опустится вниз по дереву (sift down) :: Спуск нужен при уменьшении приоритета.
- [ ] Он удалится из кучи :: Удаление — отдельная операция.
explain: Повышение приоритета — sift up, понижение — sift down.

? Чему равно $C_4$ — число вызовов при вычислении $\text{fib}(4)$ без мемоизации по формуле $C_n = C_{n-1} + C_{n-2} + 1$ при $C_1 = C_2 = 1$? Введите целое число.
= 5
explain: $C_3 = 3$, $C_4 = 3 + 1 + 1 = 5$, что совпадает с $2F(4) - 1 = 2 \cdot 3 - 1 = 5$.

? Сколько элементов достаточно хранить при подходе bottom-up для чисел Фибоначчи? Введите число.
= 3 | три
explain: Для нового значения нужны два предыдущих, плюс одно новое — всего три значения вместо массива.

? Что необходимо для поиска элемента в куче за $O(1)$?
- [ ] Бинарное дерево поиска :: Оно даёт поиск за $O(\log n)$.
- [ ] Просмотр всего массива :: Это занимает $O(n)$.
- [x] Уникальное значение и указатель на положение элемента в куче :: По значению сразу получаем место элемента.
- [ ] Сортировка кучи перед поиском :: Сортировка здесь не используется.
explain: Именно поэтому поиск по неуникальному значению через указатель невозможен.
