# Динамическое программирование по профилю

## 1. Введение и общие принципы

:::meaning
**Динамическое программирование по профилю** (англ. *dynamic programming with profile*) — метод оптимизации перебора количества вариантов или поиска оптимума в задачах на сетках и таблицах, когда одно из измерений сетки небольшое ($N \le 16\ldots20$), а второе ($M$) может быть сколь угодно большим.

**Профиль** (англ. *profile*) — сечение (срез) сетки, разделяющее уже обработанную область и ещё не рассмотренную. Конфигурация среза кодируется числом — **битовой маской** длины $N$, где каждый бит отражает локальное состояние клетки (занята/свободна, цвет, тип выступа).
:::

### Мотивация: сокращение перебора

Рассмотрим сетку $N \times M$. Пусть каждую клетку можно заполнить или раскрасить $a$ способами (например, $a = 2$ для замощения домино или двухцветной раскраски):
- **Наивный полный перебор**: перебирает все возможные конфигурации сетки целиком за время $O(a^{N \cdot M})$. При сетке $4 \times 10$ это $2^{40} \approx 10^{12}$ операций — алгоритмически непрактично.
- **Динамика по профилю (по столбцам)**: благодаря свойству локальности (заполнение текущего столбца зависит только от состояния предыдущего), мы переходим от столбца к столбцу. Время сокращается до $O(M \cdot a^{2N})$ или $O(M \cdot a^N)$.
- **Динамика по изломанному профилю (поклеточная)**: граница сдвигается на одну клетку за шаг, что уменьшает число переходов из каждого состояния до $O(1)$. Итоговая сложность падает до **$O(N \cdot M \cdot a^N)$**!

| Метод | Сложность по времени для $N \times M$ | При $N=8, M=10$ ($a=2$) |
|---|---|---|
| Полный перебор | $O(2^{N \cdot M})$ | $2^{80} \approx 1.2 \cdot 10^{24}$ (невозможно) |
| ДП по столбцам (матрица) | $O(M \cdot 2^{2N})$ | $10 \cdot 2^{16} \approx 6.5 \cdot 10^5$ |
| ДП по столбцам (DFS-переходы) | $O(M \cdot 3^N)$ | $10 \cdot 3^8 \approx 6.5 \cdot 10^4$ |
| **Изломанный профиль (Broken Profile)** | **$O(N \cdot M \cdot 2^N)$** | **$80 \cdot 2^8 \approx 2.0 \cdot 10^4$** |

### Битовые маски как инструмент кодирования

Вектор состояний клеток среза длины $N$ взаимно однозначно отображается в целое число $mask \in [0, 2^N - 1]$:

```cpp
// Проверка, занята ли i-я клетка (0 <= i < N):
bool is_set = (mask >> i) & 1;

// Установка i-го бита (клетка становится занятой):
int new_mask = mask | (1 << i);

// Сброс i-го бита (клетка освобождается):
int clear_mask = mask & ~(1 << i);

// Инверсия i-го бита:
int flipped = mask ^ (1 << i);
```

:::remember
Главное условие применимости ДП по профилю: **одно из измерений сетки должно быть малым** ($N \le 16\ldots22$). Если оба измерения велики (например, $100 \times 100$), число состояний профиля $2^{100} \approx 10^{30}$ превышает любые вычислительные лимиты. Если дано поле $1000 \times 10$, сетку следует транспонировать, выбрав $N = 10, M = 1000$.
:::

## 2. Задача о замощении домино

### Постановка

:::meaning
**Задача.** Найти количество способов замостить прямоугольную таблицу $N \times M$ непересекающимися костяшками домино размерами $1 \times 2$ (горизонтальные) и $2 \times 1$ (вертикальные) так, чтобы каждая клетка сетки была покрыта ровно одной половиной домино.
:::

:::note
**Необходимое условие существования замощения:** площадь $N \cdot M$ обязана быть **чётной**, так как каждое домино покрывает ровно 2 клетки. Если $N \cdot M$ нечётно, ответ сразу равен $0$.
:::

### Динамика по столбцам

Будем заполнять сетку столбец за столбцом слева направо. 

:::meaning
**Состояние:** $dp[c][mask]$ — количество способов частично замостить первые $c-1$ столбцов так, чтобы из $(c-1)$-го столбца в $c$-й выступали горизонтальные доминошки в тех строках $i$, где $i$-й бит маски $mask$ равен $1$ ($0 \le mask < 2^N$).
:::

Ответом на задачу будет **$dp[M][0]$**: все $M$ столбцов покрыты, и за правую границу сетки в виртуальный столбец $M$ ничего не выступает.

**База:**
$$
dp[0][0] = 1, \qquad dp[0][mask] = 0 \quad (\text{при } mask \ne 0).
$$
Перед началом обработки нулевого столбца сетка пуста, и в неё ничего не выступает.

### Переход между профилями

Пусть в столбец $c$ выступает профиль $mask_1$. Мы хотим положить доминошки в столбце $c$ так, чтобы в следующий столбец $c+1$ выступал профиль $mask_2$.

Когда переход $mask_1 \to mask_2$ корректен?
1. **Горизонтальные домино:** если в строке $i$ стоит бит $1$ в $mask_2$, это означает, что здесь начинается горизонтальное домино, занимающее клетки $(i, c)$ и $(i, c+1)$. Следовательно, в клетке $(i, c)$ не должно быть выступа из предыдущего столбца: $mask_1$ в этом бите обязан иметь $0$.
   $$
   (mask_1 \ \& \ mask_2) = 0
   $$
2. **Вертикальные домино:** в клетках столбца $c$, где нет выступа слева ($mask_1 = 0$) и нет выхода вправо ($mask_2 = 0$), клетки обязаны быть закрыты вертикальными костяшками $2 \times 1$. Это возможно тогда и только тогда, когда все непрерывные группы нулевых бит в побитовом объединении $(mask_1 \mid mask_2)$ имеют **чётную длину**!

Определим матрицу смежности переходов:
$$
T[mask_1][mask_2] =
\begin{cases}
1, & \text{если из } mask_1 \text{ можно получить } mask_2, \\
0, & \text{иначе.}
\end{cases}
$$

Тогда переход выражается суммой:
$$
dp[c+1][mask_2] = \sum_{mask_1 = 0}^{2^N - 1} dp[c][mask_1] \cdot T[mask_1][mask_2].
$$

### Генерация переходов через DFS за $O(M \cdot 3^N)$

Вместо наивной проверки всех $2^N \times 2^N = 4^N$ пар масок, допустимые переходы из текущей маски $mask_1$ генерируются рекурсивно:

```cpp
// row — текущая строка (от 0 до N)
// mask1 — профиль выступов в текущий столбец
// mask2 — формируемый профиль выступов в следующий столбец
void generateTransitions(int row, int N, int mask1, int mask2, vector<int>& next_masks) {
    if (row == N) {
        next_masks.push_back(mask2);
        return;
    }
    // Если клетка (row) уже занята выступом из предыдущего столбца:
    if ((mask1 >> row) & 1) {
        // Мы обязаны пропустить её; в mask2 этот бит равен 0
        generateTransitions(row + 1, N, mask1, mask2, next_masks);
    } else {
        // Вариант 1: кладём горизонтальное домино вправо (бит row в mask2 становится 1)
        generateTransitions(row + 1, N, mask1, mask2 | (1 << row), next_masks);

        // Вариант 2: кладём вертикальное домино (занимает row и row + 1)
        // Возможно, только если row + 1 < N и следующая клетка не занята выступом слева
        if (row + 1 < N && !((mask1 >> (row + 1)) & 1)) {
            generateTransitions(row + 2, N, mask1, mask2, next_masks);
        }
    }
}
```

:::note
Каждая незанятая клетка либо продолжается вправо (1 вариант), либо объединяется со следующей по вертикали (1/2 варианта), либо уже занята. Рекуррентное уравнение даёт ровно $3^N$ суммарных переходов по всем маскам. При $N = 8$ это всего $3^8 = 6561$ операций на столбец!
:::

### Код решения замощения по столбцам

```cpp
#include <iostream>
#include <vector>

using namespace std;

long long countDominoTilings(int N, int M) {
    if ((N * M) % 2 != 0) return 0;
    if (N > M) swap(N, M); // гарантируем, что N — наименьшее измерение

    int total_masks = 1 << N;
    // Предподсчёт всех допустимых переходов: adj[mask1] = список всех mask2
    vector<vector<int>> adj(total_masks);
    for (int mask = 0; mask < total_masks; mask++) {
        generateTransitions(0, N, mask, 0, adj[mask]);
    }

    // dp[mask] — число способов для текущего столбца
    vector<long long> dp(total_masks, 0);
    dp[0] = 1; // База

    for (int c = 0; c < M; c++) {
        vector<long long> next_dp(total_masks, 0);
        for (int mask = 0; mask < total_masks; mask++) {
            if (dp[mask] == 0) continue;
            for (int nxt : adj[mask]) {
                next_dp[nxt] += dp[mask];
            }
        }
        dp = move(next_dp);
    }

    return dp[0];
}
```

## 3. Матричное возведение в степень при $M \le 10^{18}$

### Линейность шага динамики

Заметим, что переход между столбцами задаётся умножением вектора состояний $\vec{dp}_{c}$ на фиксированную матрицу $T$ размера $2^N \times 2^N$:
$$
\vec{dp}_{c} = \vec{dp}_{c-1} \times T.
$$

Развернув рекуррентность от начального состояния $\vec{dp}_0 = (1, 0, 0, \dots, 0)$, получаем:
$$
\vec{dp}_M = \vec{dp}_0 \times T^M.
$$

:::formula
Искомый ответ равен элементу в первой строке и первом столбце матрицы $T^M$:
$$
\text{Ответ} = (T^M)_{0, 0}.
$$
:::

### Бинарное возведение матрицы в степень

Используя бинарное возведение в степень (Binary Matrix Exponentiation), матрица $T^M$ вычисляется всего за $O(\log M)$ матричных умножений:

$$
T^M =
\begin{cases}
I, & M = 0, \\
\bigl(T^{M/2}\bigr)^2, & M \text{ чётно}, \\
T \times T^{M-1}, & M \text{ нечётно}.
\end{cases}
$$

```cpp
typedef vector<vector<long long>> Matrix;
const long long MOD = 1e9 + 7;

Matrix multiply(const Matrix& A, const Matrix& B, int K) {
    Matrix C(K, vector<long long>(K, 0));
    for (int i = 0; i < K; i++) {
        for (int k = 0; k < K; k++) {
            if (!A[i][k]) continue;
            for (int j = 0; j < K; j++) {
                C[i][j] = (C[i][j] + A[i][k] * B[k][j]) % MOD;
            }
        }
    }
    return C;
}

Matrix power(Matrix A, long long p, int K) {
    Matrix res(K, vector<long long>(K, 0));
    for (int i = 0; i < K; i++) res[i][i] = 1; // Единичная матрица
    while (p > 0) {
        if (p & 1) res = multiply(res, A, K);
        A = multiply(A, A, K);
        p >>= 1;
    }
    return res;
}
```

:::example
Пусть $N = 4$, а $M = 10^{18}$.
Размер матрицы $T$: $2^4 \times 2^4 = 16 \times 16$.
Одно умножение двух матриц $16 \times 16$ требует $16^3 = 4096$ операций.
Число умножений для $M = 10^{18}$: $\approx 2 \log_2(10^{18}) \approx 120$.
Всего операций: $120 \times 4096 \approx 4.9 \cdot 10^5$, что занимает менее **1 миллисекунды**!
:::

**Сложность матричного метода:**
- По времени: $O\bigl((2^N)^3 \log M\bigr) = O(8^N \log M)$.
- По памяти: $O(4^N)$ для хранения матрицы переходов.

## 4. Задача о симпатичных узорах

### Постановка

:::meaning
**Задача.** Прямоугольное поле $N \times M$ раскрашивается в два цвета (например, чёрный и белый, кодируемые 0 и 1). Раскраска называется **симпатичным узором** (англ. *nice pattern*), если в ней **нет ни одного квадрата $2 \times 2$, целиком состоящего из клеток одного цвета**. Требуется найти общее число симпатичных узоров (обычно по модулю).
:::

### Профиль и условие совместимости

В этой задаче профиль — это цвет всех клеток одного столбца. Он задаётся битовой маской длины $N$, где $i$-й бит равен $0$, если клетка белая, и $1$, если чёрная. Всего существует $2^N$ возможных столбцов.

Два соседних столбца $p$ и $q$ совместимы, если ни в каких двух соседних строках $i$ и $i+1$ они не образуют одноцветный квадрат $2 \times 2$:

:::formula
Условие запрещённого монохромного квадрата $2 \times 2$ на строках $(i, i+1)$ между столбцами $p$ и $q$:
$$
\text{bad}(p, q, i) \iff \bigl(bit(p, i) = bit(p, i+1) = bit(q, i) = bit(q, i+1)\bigr).
$$
Столбцы $p$ и $q$ совместимы ($A[p][q] = 1$), если для **всех** $i \in [0, N-2]$ условие $\text{bad}(p, q, i)$ ложно.
:::

```cpp
bool isCompatible(int p, int q, int N) {
    for (int i = 0; i < N - 1; i++) {
        int b1 = (p >> i) & 1;
        int b2 = (p >> (i + 1)) & 1;
        int b3 = (q >> i) & 1;
        int b4 = (q >> (i + 1)) & 1;
        // Если все четыре клетки одного цвета — квадрат найден, переход запрещён
        if (b1 == b2 && b2 == b3 && b3 == b4)
            return false;
    }
    return true;
}
```

### Решение

1. Строим граф переходов (матрицу смежности $A$ размера $2^N \times 2^N$), где $A[p][q] = 1$, если столбцы совместимы, и $0$ иначе.
2. База: при $M = 1$ любой столбец допустим, поэтому $dp[0][p] = 1$ для всех $p \in [0, 2^N - 1]$.
3. Переход: $dp[c][q] = \sum_{p: A[p][q] = 1} dp[c-1][p]$.
4. При больших $M$ (например, $M \le 10^{18}$) возводим матрицу $A$ в степень $M - 1$ и суммируем все элементы произведения $\vec{1} \times A^{M-1}$.

## 5. Динамика по изломанному профилю (Broken Profile)

### В чём проблема динамики по столбцам?

При переходе целыми столбцами для $N = 16$ число состояний равно $2^{16} = 65536$. Матрица переходов содержит $(2^{16})^2 \approx 4.3 \cdot 10^9$ элементов, а число DFS-переходов $3^{16} \approx 4.3 \cdot 10^7$ на каждый столбец. При $M = 16$ это уже сотни миллионов операций!

Как сделать алгоритм быстрее? **Переходить не по целым столбцам, а поклеточно!**

### Концепция излома

Будем обходить таблицу последовательно клетка за клеткой: слева направо по строкам или сверху вниз по столбцам: $(r, c) \to (r+1, c) \to \dots \to (N-1, c) \to (0, c+1)$.

:::meaning
**Изломанный профиль** (англ. *broken profile*, поклеточная динамика) — граница между уже заполненными и ещё не заполненными клетками, имеющая форму «ступеньки» (излома) в текущей обрабатываемой клетке $(r, c)$.
:::

Контур этой границы состоит ровно из $N$ (или $N+1$) элементов:
- $r$ клеток текущего столбца $c$ уже обработаны.
- $N - r$ клеток текущего столбца $c$ ещё не обработаны (граница проходит левее них).
- Вектор состояния задаётся тройкой $(r, c, mask)$, где $mask$ длины $N+1$ бит отражает занятость клеток на изломанном контуре.

```
Текущий столбец c:
  Строка 0  : [ покрыто ]
  ...
  Строка r-1: [ покрыто ]
  Строка r  : [ ТЕКУЩАЯ КЛЕТКА (r, c) ] <-- излом границы!
  Строка r+1: [ ещё не покрыто ]
  ...
  Строка N-1: [ ещё не покрыто ]
```

### Переходы из текущей клетки $(r, c)$

Пусть $dp[mask]$ хранит количество способов замостить префикс клеток до $(r, c)$ с профилем контура $mask$. Пусть нулевой бит в маске отвечает за занятость клетки $(r, c)$ выступом сверху или слева.

Возможны следующие случаи для клетки $(r, c)$:

1. **Клетка $(r, c)$ уже занята** (бит равен $1$):
   В неё уже положена часть костяшки с предыдущего шага. Положить новое домино сюда нельзя. Мы обязаны перейти к следующей клетке, при этом в новом профиле этот бит освобождается ($1 \to 0$):
   $$
   next\_dp[mask \gg 1] += dp[mask].
   $$

2. **Клетка $(r, c)$ свободна** (бит равен $0$):
   Мы обязаны закрыть её прямо сейчас, так как в будущем вернуться к ней уже будет невозможно:
   - **Вариант А (горизонтальное домино $1 \times 2$):** кладём домино, накрывающее $(r, c)$ и правого соседа $(r, c+1)$. Это допустимо, если $c + 1 < M$. При этом клетка $(r, c+1)$ помечается занятой на следующем витке (устанавливается $N$-й бит):
     $$
     next\_dp[(mask \gg 1) \mid (1 \ll N)] += dp[mask].
     $$
   - **Вариант Б (вертикальное домино $2 \times 1$):** кладём домино, накрывающее $(r, c)$ и нижнего соседа $(r+1, c)$. Это допустимо, если $r + 1 < N$ и нижний сосед свободен (первый бит маски равен $0$):
     $$
     next\_dp[(mask \gg 1) \mid 1] += dp[mask].
     $$

### Сравнение асимптотик: почему изломанный профиль побеждает

:::formula
- **Число состояний на каждом микро-шаге:** $2^{N+1}$ (или $2^N$ при циклическом сдвиге).
- **Число переходов из каждого состояния:** не более **2**!
- **Всего шагов (клеток):** $N \cdot M$.
- **Итоговая асимптотика по времени:**
  $$
  O(N \cdot M \cdot 2^N).
  $$
- **Память:** $O(2^N)$ — достаточно хранить только массив для текущей клетки и массив для следующей (скользящий буфер).
:::

Поклеточный алгоритм быстрее динамики по столбцам в $O\left(\dfrac{3^N}{N \cdot 2^N}\right) = O\left(\dfrac{1.5^N}{N}\right)$ раз!
При $N = 16$: $3^{16} \approx 4.3 \cdot 10^7$ против $16 \cdot 2^{16} \approx 10^6$ — выигрыш более чем в **40 раз**!

### Полная реализация замощения на изломанном профиле

```cpp
#include <iostream>
#include <vector>

using namespace std;

long long dominoBrokenProfile(int N, int M) {
    if ((N * M) % 2 != 0) return 0;
    if (N > M) swap(N, M);

    int total_masks = 1 << (N + 1);
    vector<long long> dp(total_masks, 0);
    dp[0] = 1; // Начальное состояние: всё пусто

    for (int c = 0; c < M; c++) {
        for (int r = 0; r < N; r++) {
            vector<long long> next_dp(total_masks, 0);

            for (int mask = 0; mask < total_masks; mask++) {
                if (dp[mask] == 0) continue;

                bool current_occupied = (mask >> 0) & 1;

                if (current_occupied) {
                    // Клетка уже занята выступом. Ничего не кладём,
                    // сдвигаем контур на 1 бит вправо
                    int nxt_mask = mask >> 1;
                    next_dp[nxt_mask] += dp[mask];
                } else {
                    // Клетка свободна — обязаны положить домино:

                    // 1. Горизонтальное домино (вправо в клетку (r, c + 1)):
                    if (c + 1 < M) {
                        // Помечаем, что через N шагов (в столбце c + 1, строке r) клетка будет занята
                        int nxt_mask = (mask >> 1) | (1 << N);
                        next_dp[nxt_mask] += dp[mask];
                    }

                    // 2. Вертикальное домино (вниз в клетку (r + 1, c)):
                    // Допустимо, если r + 1 < N и сосед снизу ещё не занят
                    bool down_occupied = (mask >> 1) & 1;
                    if (r + 1 < N && !down_occupied) {
                        int nxt_mask = (mask >> 1) | 1;
                        next_dp[nxt_mask] += dp[mask];
                    }
                }
            }
            dp = move(next_dp);
        }
    }

    // В конце все клетки должны быть покрыты, и никаких выступов быть не должно
    return dp[0];
}
```

## 6. Границы применимости и подводные камни

:::warning
### Ловушка коллоквиума: почему профиль не работает для сетки $100 \times 100$?
**Вопрос с экзамена:** Можно ли замостить доминошками или найти число узоров на доске $100 \times 100$ методом динамики по профилю?

**Ответ:** Категорически **нет**. 
Вектор состояния требует профиля длины как минимум $N = 100$. Количество состояний профиля составляет $2^{100} \approx 1.27 \cdot 10^{30}$. Для сравнения:
- Количество микросекунд с момента Большого взрыва $\approx 4 \cdot 10^{23}$.
- Количество атомов в человеческом теле $\approx 7 \cdot 10^{27}$.

Обойти $10^{30}$ состояний невозможно ни на каком суперкомпьютере. Динамика по профилю предназначена **только для узких полос**, где $\min(N, M) \le 16\ldots22$. Для свободных сеток $100 \times 100$ существование замощения домино решается полиномиально через **поиск максимального паросочетания в двудольном графе** алгоритмом Куна/Диница за $O(V \cdot E) = O((NM)^2)$, а точное количество замощений находится через **определитель матрицы Кастелейна (теорема Кастелейна — Темперли — Фишера)** за $O((NM)^3)$!
:::
