# Базовые динамические структуры данных: стек, очередь, дек и связные списки

## Интерфейсы и абстрактные типы данных: стек, очередь, дек и вектор

### Понятие абстрактного типа данных и интерфейса

В теории алгоритмов и структур данных принципиально важно разделять **интерфейс** (спецификацию поведения) и **структуру данных** (конкретную физическую реализацию в оперативной памяти).

:::meaning
**Интерфейс (Абстрактный тип данных, АТД)** — это математическая модель, определяющая набор поддерживаемых операций, их семантику (что именно делает операция) и контракты на входные и выходные данные, без фиксации способа хранения данных в памяти.
:::

Один и тот же интерфейс может быть реализован различными структурами данных:
- на непрерывном статическом массиве;
- на динамическом расширяемом массиве (`std::vector`);
- на односвязных или двусвязных динамических списках.

Выбор конкретной реализации интерфейса — это инженерный компромисс. Например, массив обеспечивает идеальную пространственную локальность данных и быстрый доступ к кэш-памяти процессора ($L1/L2/L3$), однако требует выделения непрерывного блока памяти и может вызывать накладные расходы при расширении. Связные списки, напротив, позволяют выделять память по одному узлу в произвольных адресах кучи, но создают накладные расходы на хранение указателей и страдают от промахов кэша (cache miss).

### Стек (Stack): принцип LIFO и метафора «стакана»

:::meaning
**Стек (Stack)** — динамическая структура данных, реализующая дисциплину доступа **LIFO** (*Last In, First Out* — «последним пришёл, первым ушёл»).
:::

Стек наиболее наглядно визуализируется как **узкий высокий стакан** или стопка тарелок:
1. Элементы можно опускать в стакан только через открытый верхний край.
2. Каждый новый элемент ложится строго поверх предыдущего.
3. Извлечь элемент со дна стакана невозможно, не вынув предварительно все элементы, находящиеся выше него.
4. В любой момент времени доступен только самый верхний элемент — **вершина стека** (`top`).

```array stack
title: Стек как стакан (вершина сверху — элемент 42)
[10, 25, 7, 42]
```

```diagram

```

Базовый интерфейс стека включает три ключевые операции:

- `push(x)` — поместить элемент $x$ на вершину стека;
- `pop()` — удалить элемент с вершины стека;
- `top()` (или `peek()`) — вернуть значение элемента на вершине стека без его удаления.

:::remember
В стеке действует дисциплина **LIFO**. Операции происходят строго с одного конца — с вершины (`top`). Для поддержания стека не требуется знание о других элементах, кроме находящегося на вершине.
:::

### Очередь (Queue): принцип FIFO

:::meaning
**Очередь (Queue)** — динамическая структура данных, реализующая дисциплину доступа **FIFO** (*First In, First Out* — «первым пришёл, первым ушёл»).
:::

Очередь моделирует реальную очередь людей у кассы:
- Элементы поступают в структуру с одного конца, называемого **хвостом** (`tail` или `back`).
- Извлекаются элементы с противоположного конца, называемого **головой** (`head` или `front`).
- Элемент, пришедший первым, покинет очередь раньше остальных.

```array queue
title: Очередь FIFO (head слева, tail справа)
[5, 12, 99, 3]
```

```diagram
title: Потоки данных в очереди

TAIL: round "Хвост очереди (tail / back)"
BODY: box "Тело очереди"
HEAD: round "Голова очереди (head / front)"
OUT: box "dequeue() / pop()"
IN -> TAIL
TAIL -> BODY
BODY -> HEAD
HEAD -> OUT
```

Базовые операции очереди:
- `enqueue(x)` (в ряде библиотек `push(x)`) — добавить элемент $x$ в конец очереди (`tail`);
- `dequeue()` (в ряде библиотек `pop()`) — удалить элемент из начала очереди (`head`);
- `front()` (в разговорной речи иногда `top()`) — посмотреть первый элемент в очереди без его удаления.

:::warning
Не путайте принципы LIFO и FIFO!
- **Стек = LIFO** (стакан, патроны в магазине, стопка книг).
- **Очередь = FIFO** (труба, очередь в магазине, конвейер).
:::

### Дек (Deque): двусторонняя очередь

:::meaning
**Дек (Deque — Double-Ended Queue)** — структура данных, представляющая собой двустороннюю очередь, в которой операции вставки и удаления допустимы с обоих концов.
:::

Дек обобщает стек и очередь:
- если использовать операции только на одном конце (`push_back` и `pop_back`), дек ведёт себя как стек;
- если добавлять элементы в один конец, а извлекать из другого (`push_back` и `pop_front`), дек ведёт себя как стандартная FIFO-очередь.

```diagram

L_IN: box "push_front(x)"
L_OUT: box "pop_front()"
FRONT: round "Голова (front)"
BODY: box "Элементы дека"
BACK: round "Хвост (back)"
R_IN: box "push_back(x)"
R_OUT: box "pop_back()"
L_IN -> FRONT
FRONT -> L_OUT
FRONT -> BODY
BODY -> BACK
R_IN -> BACK
BACK -> R_OUT
```

Интерфейс дека включает:
- `push_front(x)` — добавить элемент в начало;
- `push_back(x)` — добавить элемент в конец;
- `pop_front()` — удалить элемент из начала;
- `pop_back()` — удалить элемент из конца;
- `front()` и `back()` — просмотреть первый и последний элементы.

### Вектор (динамический массив)

Вектор (`std::vector`) — это динамический массив, непрерывно размещённый в оперативной памяти с автоматическим управлением ёмкостью (`capacity`).

```array
title: Вектор в непрерывной памяти (size = 4, capacity = 8)
[14, 88, 42, 99, 0, 0, 0, 0] highlight: 0,1,2,3
```

Особенности вектора:
1. **Произвольный доступ за $O(1)$:** доступ к любому элементу по индексу $i$ осуществляется за константное время благодаря адресной арифметике:
   $$\text{addr}(i) = \text{base\_addr} + i \cdot \text{sizeof}(T)$$
2. **Добавление в конец:** при наличии свободной ёмкости ($\text{size} < \text{capacity}$) вставка занимает $O(1)$. Если буфер полон, выделяется новый блок памяти размером $2 \cdot \text{capacity}$ (геометрическая прогрессия), все элементы копируются, а старый блок освобождается. Амортизированное время вставки составляет $O(1)$, а худшее — $O(n)$.
3. **Операции с началом вектора:** `push_front` и `pop_front` на стандартном векторе требуют сдвига всех $n$ элементов в памяти, что занимает линейное время $O(n)$.
4. **Кольцевой буфер (Circular Buffer):** чтобы реализовать очередь или дек на массиве со строгим временем $O(1)$ на обоих концах, массив замыкают в кольцо. Указатели `head` и `tail` инкрементируются по модулю размера буфера $N$:
   $$i_{\text{next}} = (i + 1) \pmod N$$

## Связные списки: односвязные и двусвязные

### Метафора поезда и устройство связного списка

Связный список — динамическая структура данных, элементы которой не обязаны находиться в непрерывном блоке памяти.

:::note
**Метафора поезда:** Связный список устроен подобно железнодорожному поезду.
- Каждый узел списка — это отдельный «вагон».
- В вагоне находятся полезные данные (`value`).
- Вагоны сцеплены друг с другом сцепками-указателями (`next`).
- Локомотив поезда задаётся указателем на первый вагон — **голову** (`head`).
- Последний вагон состава не сцеплен ни с чем: его указатель направлен в «пустоту» — `nullptr` (`NULL`).
:::

N2: round "Вагон 2: data | next"

### Односвязный список (Singly Linked List)

В односвязном списке каждый узел хранит ровно одно значение и ровно один указатель — адрес следующего узла в памяти.

```cpp
struct Node {
    int value;       // Данные
    Node* next;      // Указатель на следующий вагон

    Node(int val) : value(val), next(nullptr) {}
};
```

Для управления списком как единым целым достаточно хранить указатель на первый элемент: `Node* head = nullptr;`. Дополнительно часто сохраняют указатель на последний узел: `Node* tail = nullptr;`.

```array linked
title: Односвязный список со значениями 10 -> 20 -> 30 -> 40
[10, 20, 30, 40]
```

### Двусвязный список (Doubly Linked List)

:::meaning
**Двусвязный список** — это связный список, в котором каждый узел содержит два указателя: на следующий узел (`next`) и на предыдущий узел (`prev`).
:::

Благодаря двум указателям по списку можно двигаться в обоих направлениях: от головы к хвосту и от хвоста к голове.

```cpp
struct DNode {
    int value;       // Данные
    DNode* prev;     // Указатель на предыдущий узел
    DNode* next;     // Указатель на следующий узел

    DNode(int val) : value(val), prev(nullptr), next(nullptr) {}
};
```

### Базовые операции со списками

Разберём пошагово алгоритмы всех операций над списками и манипуляции с указателями.

#### 1. Добавление в начало (`push_front`)

Вставка нового элемента перед текущей головой `head`:

:::example
Пошаговый алгоритм `push_front(x)`:
1. Выделяем память под новый узел: `Node* new_node = new Node(x);`.
2. Направляем указатель нового узла на текущую голову: `new_node->next = head;`.
3. Перенаправляем указатель `head` на новый узел: `head = new_node;`.
4. Если список был пуст и поддерживается `tail`, обновляем: `tail = new_node;`.
:::

Временная сложность: выполняется ровно $3$ присваивания указателей, цикл отсутствует $\implies$ **строгое $O(1)$**.

#### 2. Удаление из начала (`pop_front`)

:::example
Пошаговый алгоритм `pop_front()`:
1. Проверяем, что список не пуст (`head != nullptr`).
2. Запоминаем адрес удаляемого узла: `Node* tmp = head;`.
3. Сдвигаем голову на следующий вагон: `head = head->next;`.
4. Освобождаем память: `delete tmp;`.
5. Если список стал пуст (`head == nullptr`), сбрасываем `tail = nullptr;`.
:::

Временная сложность: **строгое $O(1)$**.

#### 3. Добавление в конец (`push_back`)

Сложность операции критически зависит от наличия указателя `tail`:

- **Без указателя `tail`:**
  Чтобы зацепить новый вагон в конец поезда, необходимо начать с локомотива (`head`) и пройти по связям `next` все $n$ узлов, пока не встретится узел, у которого `p->next == nullptr`. Вставка занимает **$O(n)$**.
- **При наличии указателя `tail`:**
  Новый узел привязывается напрямую:
  ```cpp
  tail->next = new_node;
  tail = new_node;
  ```
  Сложность составляет **строгое $O(1)$**.

#### 4. Удаление из конца (`pop_back`)

:::warning
**Классическая ловушка:** можно ли удалить последний элемент односвязного списка за $O(1)$, если есть указатель `tail`?
**Ответ: НЕТ!** 
Чтобы удалить последний узел и освободить память, необходимо обнулить указатель `next` у **предпоследнего** узла (`prev_node->next = nullptr;`). Но в односвязном списке стрелки ведут только вперёд! Из узла `tail` невозможно сделать «шаг назад». Чтобы найти предпоследний узел, придётся пройти от `head` по всему списку за $n-1$ шагов. 

Поэтому в **односвязном списке** удаление из конца всегда требует **$O(n)$**, даже при наличии указателя `tail`!
:::

В **двусвязном списке** эта проблема отсутствует:
```cpp
Node* prev_node = tail->prev;
prev_node->next = nullptr;
delete tail;
tail = prev_node;
```
В двусвязном списке удаление из конца выполняется за **$O(1)$**.

#### 5. Вставка после элемента и перед элементом

- **Вставка после заданного узла $P$ (`insert_after`):**
  Имея прямой указатель на узел $P$:
  ```cpp
  new_node->next = P->next;
  P->next = new_node;
  ```
  Операция занимает **$O(1)$**.

- **Вставка перед заданным узлом $P$ (`insert_before`):**
  - В *односвязном списке* для вставки перед $P$ требуется найти предшествующий узел, что требует прохода от `head` за $O(n)$ (либо трюк с обменом значений узлов за $O(1)$).
  - В *двусвязном списке* предшествующий узел доступен по ссылке `P->prev` за $O(1)$, поэтому вставка выполняется за **строгое $O(1)$**.

#### 6. Удаление из середины

Если удаляется узел $P$, находящийся в середине списка:
- В односвязном списке нужно обновить `next` предыдущего узла, что требует $O(n)$ на его поиск от начала списка.
- В двусвязном списке узел «выстёгивается» из цепочки мгновенно:
  ```cpp
  P->prev->next = P->next;
  P->next->prev = P->prev;
  delete P;
  ```
  Удаление любого заданного узла в двусвязном списке занимает **$O(1)$**.

- [ ] Доступ к $i$-му элементу по индексу за $O(1)$ :: Произвольный доступ по-прежнему требует $O(n)$.
explain: Двусвязный список сохраняет ссылки на обоих соседей каждого узла.

## Вывод асимптотики всех операций

### Анализ сложности: массивы против связных списков

Выведем точные асимптотические оценки трудоёмкости для каждой операции, опираясь на физическую модель памяти.

1. **Доступ по индексу ($k$-й элемент):**
   - В статическом массиве и векторе: адрес ячейки вычисляется за $1$ арифметическую операцию $\implies O(1)$.
   - В связных списках: адрес узла в памяти случаен, индексации нет. Чтобы попасть в $k$-й узел, необходимо выполнить цепочку из $k$ разыменований:
     $$\text{head} \to \text{next} \to \text{next} \dots \to \text{target}$$
     В худшем случае ($k = n$) число шагов равно $n \implies O(n)$.

2. **Вставка и удаление на границах (голова/хвост):**
   - Вектор: добавление/удаление в конец — $O(1)$ амортизированное, в начало — $O(n)$ из-за сдвига.
   - Односвязный список без `tail`: начало — $O(1)$, конец — $O(n)$.
   - Односвязный список с `tail`: добавление в конец — $O(1)$, но удаление из конца — $O(n)$.
   - Двусвязный список с `tail`: обе операции на обоих концах — строгое $O(1)$.

:::formula
**Ключевой фактор асимптотики списка:** Наличие указателя `tail` превращает вставку в конец односвязного списка из $O(n)$ в $O(1)$, но не меняет сложность удаления из конца ($O(n)$). Переход к двусвязному списку обеспечивает строгое $O(1)$ для всех операций на обоих концах.
:::

## Реализация стека, очереди и дека на связных списках

### Стек на односвязном списке: почему tail не нужен

Вспомним физическую метафору: стек — это узкий стакан. Все изменения происходят исключительно на одном конце — на вершине (`top`).

:::note
Если сопоставить вершину стека `top` с головой связного списка `head`, то:
- `push(x)` превращается в `push_front(x)`;
- `pop()` превращается в `pop_front()`;
- `top()` превращается в обращение к `head->value`.
:::

Так как вставка и удаление в начало односвязного списка работают за строгое $O(1)$, для реализации полноценного стека **указатель `tail` не нужен вообще**.

```diagram

TOP: box "head (вершина стека)"
N3: round "30 (top)"
N2: round "20"
N1: round "10 (дно стека)"
NIL: box "nullptr"

N3 -> N2 : next
N2 -> N1 : next
N1 -> NIL : next
```

Реализация стека на C++:

```cpp
class ListStack {
private:
    struct Node {
        int value;
        Node* next;
        Node(int val, Node* nxt) : value(val), next(nxt) {}
    };

    Node* head = nullptr;
    size_t count = 0;

public:
    ~ListStack() {
        while (!empty()) pop();
    }

    void push(int x) {
        head = new Node(x, head); // Вставка в начало за O(1)
        count++;
    }

    void pop() {
        if (empty()) return;
        Node* tmp = head;
        head = head->next;        // Удаление из начала за O(1)
        delete tmp;
        count--;
    }

    int top() const {
        return head->value;       // Доступ за O(1)
    }

    bool empty() const {
        return head == nullptr;
    }

    size_t size() const {
        return count;
    }
};
```

Все операции `push`, `pop`, `top` выполняются за **строгое гарантированное время $O(1)$** без необходимости реаллокаций и без лишней траты памяти на хранение указателя на хвост.

### Очередь на односвязном списке: взаимное расположение head и tail

Для очереди элементы должны добавляться с одного конца, а извлекаться с другого.

Рассмотрим два возможных варианта распределения ролей между концами односвязного списка:

1. **Вариант А (Ошибочный):** `head` — это конец очереди (`enqueue`), `tail` — это начало очереди (`dequeue`).
   - Добавление `push_front` в начало списка занимает $O(1)$.
   - Но удаление `pop_back` из конца списка требует $O(n)$, так как невозможно за $O(1)$ обновить указатель `tail` на предпоследний узел!
   - Такой вариант неэффективен.

2. **Вариант Б (Корректный):** `head` — это начало очереди (`dequeue`), `tail` — это конец очереди (`enqueue`).
   - Извлечение `dequeue` происходит из `head` (`pop_front`) за $O(1)$.
   - Добавление `enqueue` происходит в `tail` (`push_back`) за $O(1)$:
     $$\text{tail->next} = \text{new\_node};\quad \text{tail} = \text{new\_node};$$
   - Обе операции работают за **строгое $O(1)$**!

```diagram

N1: round "Узел 1"

N1 -> N2 : next
N2 -> N3 : next

```

Реализация очереди на C++:

```cpp
class ListQueue {
private:
    struct Node {
        int value;
        Node* next;
        Node(int val) : value(val), next(nullptr) {}
    };

    Node* head = nullptr;
    Node* tail = nullptr;

public:
    ~ListQueue() {
        while (!empty()) dequeue();
    }

    void enqueue(int x) {
        Node* new_node = new Node(x);
        if (empty()) {
            head = tail = new_node;
        } else {
            tail->next = new_node; // Вставка в хвост за O(1)
            tail = new_node;
        }
    }

    void dequeue() {
        if (empty()) return;
        Node* tmp = head;
        head = head->next;         // Удаление из головы за O(1)
        delete tmp;
        if (head == nullptr) {
            tail = nullptr;
        }
    }

    int front() const {
        return head->value;        // Доступ за O(1)
    }

    bool empty() const {
        return head == nullptr;
    }
};
```

### Дек на двусвязном списке

Так как дек требует удаления и добавления с обоих концов за $O(1)$, односвязный список принципиально непригоден из-за медленного `pop_back` ($O(n)$).

Для дека применяется **двусвязный список с указателями `head` и `tail`**:
- `push_front` / `pop_front` манипулируют узлом `head` за $O(1)$;
- `push_back` / `pop_back` манипулируют узлом `tail` за $O(1)$.

## Реализация очереди на стеках: две и три копии

### Очередь на двух стеках

Классическая алгоритмическая задача: реализовать интерфейс FIFO-очереди (`enqueue`, `dequeue`, `front`), имея в качестве строительных блоков исключительно LIFO-стеки.

#### Архитектура решения

Заведём два независимых стека:
1. $S_{\text{in}}$ — **входной стек** (*In-stack*), предназначенный исключительно для приёма новых элементов;
2. $S_{\text{out}}$ — **выходной стек** (*Out-stack*), предназначенный для выдачи элементов наружу.

```diagram
title: Очередь на двух стеках
ENQ: box "enqueue(x)"
SIN: box "Входной стек S_in"
SOUT: box "Выходной стек S_out"
DEQ: box "dequeue() / front()"
ENQ -> SIN : push
SIN -> SOUT : Переливание при пустом S_out (разворот порядка)
SOUT -> DEQ : pop / top
```

#### Алгоритм выполнения операций

1. `enqueue(x)`:
   - Всегда просто кладём элемент во входной стек:
     $$S_{\text{in}}.\text{push}(x)$$
   - Сложность: строгое $O(1)$.

2. `dequeue()` и `front()`:
   - Если выходной стек $S_{\text{out}}$ **не пуст**, нужный нам самый старый элемент уже находится на его вершине:
     $$\text{выполняем } S_{\text{out}}.\text{pop}()$$
   - Если же выходной стек $S_{\text{out}}$ **пуст**:
     - Мы берем все элементы из $S_{\text{in}}$ и по одному перекладываем («переливаем») их в $S_{\text{out}}$:
       ```cpp
       while (!S_in.empty()) {
           S_out.push(S_in.top());
           S_in.pop();
       }
       ```
     - **Магия двух LIFO:** порядок элементов при перекладывании полностью обращается! Тот элемент, который вошёл в $S_{\text{in}}$ самым первым (на дно), окажется на самой вершине $S_{\text{out}}$!
     - После переливания забираем верхний элемент из $S_{\text{out}}$.

:::example
Проследим за элементами $1, 2, 3$:
1. `enqueue(1)`, `enqueue(2)`, `enqueue(3)`:
   - $S_{\text{in}} = [1, 2, 3]$ (вершина — $3$).
   - $S_{\text{out}} = []$.
2. Вызываем `dequeue()`:
   - $S_{\text{out}}$ пуст. Переливаем из $S_{\text{in}}$:
     - достали $3 \implies S_{\text{out}}.\text{push}(3)$
     - достали $2 \implies S_{\text{out}}.\text{push}(2)$
     - достали $1 \implies S_{\text{out}}.\text{push}(1)$
   - Состояние: $S_{\text{in}} = []$, $S_{\text{out}} = [3, 2, 1]$ (вершина — $1$).
   - Выталкиваем вершину: $S_{\text{out}}.\text{pop}() \implies$ извлечена $1$!
   - Порядок FIFO соблюдён: первым вошёл $1$ — первым вышел $1$.
:::

```cpp
class TwoStackQueue {
private:
    std::vector<int> in_stack;
    std::vector<int> out_stack;

    void transfer() {
        if (out_stack.empty()) {
            while (!in_stack.empty()) {
                out_stack.push_back(in_stack.back());
                in_stack.pop_back();
            }
        }
    }

public:
    void enqueue(int x) {
        in_stack.push_back(x);
    }

    void dequeue() {
        transfer();
        if (!out_stack.empty()) {
            out_stack.pop_back();
        }
    }

    int front() {
        transfer();
        return out_stack.back();
    }

    bool empty() const {
        return in_stack.empty() && out_stack.empty();
    }
};
```

### Амортизационный анализ очереди на двух стеках

Операция `dequeue()` в худшем случае требует $O(n)$ действий (когда $S_{\text{out}}$ пуст и в $S_{\text{in}}$ накопилось $n$ элементов). Однако утверждать, что очередь работает за $O(n)$, неверно.

Докажем, что **амортизированная стоимость любой операции составляет $O(1)$**, используя **учётный метод (метод предоплаты)**:

:::formula
**Жизненный цикл каждого элемента:**
За всё время нахождения в очереди каждый элемент участвует ровно в трёх операциях:
1. Ровно $1$ раз кладётся во входной стек $S_{\text{in}}$ (`push`);
2. Ровно $1$ раз извлекается из $S_{\text{in}}$ и кладётся в $S_{\text{out}}$ (`transfer`);
3. Ровно $1$ раз извлекается из выходного стека $S_{\text{out}}$ (`pop`).
:::

Пусть реальная стоимость одной базовой операции со стеком равна $1$ условной монете.
- При вызове `enqueue` мы взимаем с пользователя сбор в размере **$3$ монет**:
  - $1$ монета немедленно оплачивает текущую вставку в $S_{\text{in}}$;
  - $1$ монета сохраняется на элементе как депозит на будущее переливание в $S_{\text{out}}$;
  - $1$ монета сохраняется как депозит на будущее финальное извлечение из $S_{\text{out}}$.
- При выполнении дорогого вызова `dequeue` с переливанием мы не тратим ни одной новой монеты пользователя: вся работа полностью оплачивается депозитами, накопленными на перемещаемых элементах!

Следовательно, последовательность из $m$ любых операций над очередью займёт не более $3m$ элементарных действий:
$$\sum_{i=1}^m c_i \le 3m = O(m)$$
Средняя (амортизированная) стоимость одной операции равна **строго $O(1)$**.

### Очередь на трёх стеках: достижение худшего времени $O(1)$

Хотя очередь на двух стеках обеспечивает прекрасную амортизированную сложность $O(1)$, у неё есть существенный недостаток для **систем реального времени (Real-Time Systems)**.

:::warning
В критических приложениях (высокочастотная биржевая торговля, бортовые компьютеры, управление робототехникой) недопустимы непредсказуемые паузы. Если операция `dequeue` случайно вызовет переливание $10^6$ элементов, система «зависнет» на $O(n)$ миллисекунд.
:::

Чтобы гарантировать **худшее время $O(1)$** на каждую операцию (worst-case $O(1)$), очередь реализуют на **трёх стеках** (алгоритм очереди реального времени, родственный очереди Гуда — Мелхорна / Hood-Melville queue):

1. **Идея инкрементного разворота:** процесс переливания элементов не откладывается до момента полного исчерпания $S_{\text{out}}$.
2. Третий стек используется как **промежуточный рабочий буфер** (*copying stack*).
3. Перенос элементов дробится на небольшие порции: при каждом поступлении операций `enqueue` или `dequeue` алгоритм делает ровно константное число шагов (например, переносит $2$ элемента) из старого входного стека через вспомогательный третий стек в будущий выходной стек.
4. К тому моменту, когда текущий $S_{\text{out}}$ окончательно опустеет, фоновый процесс копирования на трёх стеках уже полностью завершает формирование нового выходного стека!

Таким образом, ни одна отдельная операция не испытывает задержки $O(n)$, и время отклика каждой операции гарантированно ограничено **строгим $O(1)$ в худшем случае**.

explain: Переливание элементов из одного стека в другой полностью обращает их порядок, восстанавливая FIFO.

- [ ] $O(n)$ :: В худшем случае отдельная операция может занять O(n), но амортизированно — O(1).

- [x] $O(1)$ :: Каждый элемент перемещается между стеками строго фиксированное число раз (3 операции).
explain: По учетному методу каждый элемент требует ровно 3 базовых действия за всю жизнь в очереди.

? В чем главное преимущество очереди на трех стеках по сравнению с очередью на двух стеках?
- [ ] Она требует в три раза меньше оперативной памяти :: Памяти она требует не меньше.

- [ ] Она автоматически удаляет дубликаты элементов
