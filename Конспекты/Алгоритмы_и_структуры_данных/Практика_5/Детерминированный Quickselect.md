# Детерминированный Quickselect (медиана медиан)

## История создания и постановка задачи

Алгоритм детерминированного выбора $k$-го по порядку элемента был предложен в 1973 году Блюмом (Blum), Флойдом (Floyd), Праттом (Pratt), Ривестом (Rivest) и Тарьяном (Tarjan). По первым буквам фамилий его часто называют алгоритмом **BFPRT**, а по главной идее — **алгоритмом медианы медиан**.

:::meaning
**$k$-я порядковая статистика** массива — это элемент, который оказался бы на $k$-м месте (нумерация с единицы), если бы массив отсортировали по возрастанию.

- $k = 1$ — минимум;
- $k = n$ — максимум;
- $k = \lceil n/2 \rceil$ — медиана.
:::

Задача: найти $k$-ю порядковую статистику массива из $n$ элементов **без полной сортировки**, то есть быстрее, чем за $O(n \log n)$. Обычный (рандомизированный) Quickselect выбирает опорный элемент случайно и работает за $O(n)$ лишь *в среднем*, а в худшем случае — за $O(n^2)$. Детерминированный вариант выбирает опорный элемент так, чтобы он **гарантированно** был «достаточно хорошим», и поэтому работает за $O(n)$ **в худшем случае**.

:::note
Слово «детерминированный» означает, что в алгоритме нет случайности: на одних и тех же входных данных он всегда делает одни и те же действия.
:::

## Алгоритм: идея, шаги, псевдокод и проход по массиву

### Идея

Как и в обычном Quickselect, мы выбираем опорный элемент (*pivot*), разбиваем по нему массив на «меньше», «равно» и «больше», а затем продолжаем работать только с той частью, в которой лежит искомый $k$-й элемент. Вся новизна — в способе выбора pivot: он должен делить массив не слишком неравномерно. Его выбирают как **медиану медиан**.

### Шаги алгоритма

1. **Разбиение на группы.** Делим массив на подмассивы (группы) по 5 элементов. Последняя группа может оказаться короче.
2. **Медиана каждой группы.** В каждой группе находим медиану. Групп всего примерно $n/5$, поэтому получается $n/5$ медиан.
3. **Медиана медиан.** Из найденных медиан составляем новый массив и ищем медиану уже в нём. Поиск медианы — это снова задача о $k$-й порядковой статистике (с $k$, равным середине), поэтому здесь алгоритм вызывает **сам себя** на массиве размера $n/5$.
4. **Разбиение по pivot.** Найденную медиану медиан берём в качестве pivot и проходим по всему массиву, разделяя элементы на меньшие, равные и большие pivot. Предполагаем, что такой pivot достаточно хорош.
5. **Рекурсия в нужную часть.** Сравниваем $k$ с размерами частей и продолжаем поиск только в той части, где лежит искомый элемент. Её размер — **не более $\frac{7}{10}n$**.
6. Повторяем всё то же самое для оставшегося подмассива, пока он не станет совсем маленьким.

:::meaning
**Медиана медиан** — медиана массива, составленного из медиан всех пятёрок. Она служит опорным элементом, который по построению не может оказаться ни слишком маленьким, ни слишком большим.
:::

### Почему группы по 5 элементов

Размер группы — небольшая константа. Поэтому найти медиану в группе из 5 элементов можно за $O(1)$: например, отсортировать пять чисел простым перебором. Такие маленькие блоки целиком помещаются в кэш и регистры процессора, и работа с ними идёт быстро. Кроме того, именно размер 5 даёт нужную оценку размера оставшейся части: $\frac{7}{10}n$ (см. раздел «Почему остаётся не более $\frac{7}{10}n$ элементов»).

### Псевдокод

```python
def select(A, k):
    """Возвращает k-й по возрастанию элемент массива A (k от 1 до len(A))."""
    n = len(A)
    if n <= 5:
        return sorted(A)[k - 1]

    # 1-2. Делим на группы по 5 и находим медиану каждой группы
    groups = [A[i:i + 5] for i in range(0, n, 5)]
    medians = [sorted(g)[(len(g) - 1) // 2] for g in groups]

    # 3. Медиана медиан — тоже k-я порядковая статистика (рекурсивный вызов)
    pivot = select(medians, (len(medians) + 1) // 2)

    # 4. Разбиваем весь массив по pivot
    less    = [x for x in A if x < pivot]
    equal   = [x for x in A if x == pivot]
    greater = [x for x in A if x > pivot]

    # 5. Продолжаем только в той части, где лежит k-й элемент
    if k <= len(less):
        return select(less, k)
    elif k <= len(less) + len(equal):
        return pivot
    else:
        return select(greater, k - len(less) - len(equal))
```

:::warning
В алгоритме **две** рекурсии с разными целями:

- первая (`select(medians, ...)`) ищет pivot и работает на массиве из $\approx n/5$ элементов;
- вторая (`select(less, ...)` или `select(greater, ...)`) ищет сам ответ и работает на части массива, не превышающей $\frac{7}{10}n$.

Именно поэтому в рекуррентном соотношении ниже два слагаемых с $T$.
:::

:::note
Тройное разбиение (меньшие, равные, большие) нужно, чтобы алгоритм корректно работал, если в массиве есть одинаковые элементы: все элементы, равные pivot, сразу «выбывают» из дальнейшего поиска.
:::

### Проход по массиву

Ниже показано выполнение первых шагов алгоритма на массиве из 15 элементов (три группы по 5). Сначала каждая группа сортируется вставками, и её медиана (третий элемент) записывается в массив `med`. Затем медиана трёх медиан берётся как pivot, и массив разбивается вокруг него. В конце pivot оказывается на своём окончательном месте.

```array
title: Медиана медиан и разбиение на 15 элементах
[12, 3, 9, 1, 15, 7, 14, 2, 10, 5, 11, 4, 13, 6, 8]
pointers: i, j, p, st
buffers: med
print: last
code:
let n = a.length;
let med = new Array(3);
for (let g = 0; g < 3; g++) {
  let s = g * 5;
  for (let i = s + 1; i < s + 5; i++) {
    let j = i;
    while (j > s && a[j - 1] > a[j]) {
      swap(a, j - 1, j);
      j--;
    }
  }
  med[g] = a[s + 2];
}
say("Медианы групп найдены");
let pv = med[0] + med[1] + med[2] - Math.max(med[0], Math.max(med[1], med[2])) - Math.min(med[0], Math.min(med[1], med[2]));
say("pivot — медиана медиан");
let p = 0;
while (a[p] != pv) {
  p++;
}
swap(a, p, n - 1);
let st = 0;
for (let i = 0; i < n - 1; i++) {
  if (a[i] < pv) {
    swap(a, i, st);
    st++;
  }
}
swap(a, st, n - 1);
done(st, st);
```

:::example
Разберём этот проход по шагам.

1. Три группы по пять элементов: $(12, 3, 9, 1, 15)$, $(7, 14, 2, 10, 5)$, $(11, 4, 13, 6, 8)$.
2. После сортировки внутри групп: $(1, 3, 9, 12, 15)$, $(2, 5, 7, 10, 14)$, $(4, 6, 8, 11, 13)$. Медианы групп — третьи элементы: $9$, $7$ и $8$.
3. Медиана массива $(9, 7, 8)$ равна $8$ — это и есть медиана медиан, то есть pivot. (Здесь медиан всего три, поэтому их медиана находится сразу; для большого массива это был бы рекурсивный вызов `select`.)
4. Разбиваем массив по pivot $= 8$: все элементы меньше $8$ переносятся в левую часть, остальные остаются справа, и pivot встаёт между ними.
5. Слева от pivot оказывается $7$ элементов, поэтому pivot — 8-й по порядку элемент. Если искали именно $k = 8$, ответ найден; если $k < 8$, продолжаем в левой части, если $k > 8$ — в правой, сдвинув $k$ на $8$.
:::

### Почему остаётся не более $\frac{7}{10}n$ элементов

Пусть $m$ — медиана медиан. Рассмотрим группы по 5 элементов.

- Ровно половина медиан групп (примерно $\frac{n}{10}$ штук) не больше $m$.
- В каждой такой группе три элемента (сама медиана и два меньших элемента) не больше своей медианы, а значит и не больше $m$.
- Итого не меньше $3 \cdot \frac{n}{10} = \frac{3n}{10}$ элементов не больше $m$. Симметрично, не меньше $\frac{3n}{10}$ элементов не меньше $m$.

Значит, после разбиения по $m$ любая из двух частей содержит не более $n - \frac{3n}{10} = \frac{7n}{10}$ элементов. Именно поэтому pivot «достаточно хорош»: он гарантированно не отсекает слишком мало.

:::warning
Оценка $\frac{7}{10}n$ получена **приближённо**: мы не учитывали, что последняя группа может быть неполной, и что $\frac{n}{5}$, $\frac{n}{10}$ могут быть нецелыми. Такие поправки дают лишь прибавку в виде константы и не влияют на итоговую оценку $O(n)$.
:::

## Оценка времени работы

### Рекуррентное соотношение

Складываем время всех шагов алгоритма:

$$
T(n) = T\left(\frac{7}{10}n\right) + T\left(\frac{n}{5}\right) + \Theta(n)
$$

Откуда берётся каждое слагаемое:

- $T\left(\frac{7}{10}n\right)$ — рекурсивный поиск ответа в оставшейся части массива (не более $\frac{7}{10}n$ элементов);
- $T\left(\frac{n}{5}\right)$ — рекурсивный поиск медианы среди $\frac{n}{5}$ медиан групп;
- $\Theta(n)$ — линейная работа: найти медиану в каждой из $\frac{n}{5}$ групп (по $O(1)$ на группу) и разбить весь массив по pivot.

:::warning
Не путайте: слагаемое $T\left(\frac{n}{5}\right)$ в этом соотношении — **время рекурсивного вызова** для поиска медианы медиан, а не просто время обработки групп. Обработка групп входит в $\Theta(n)$.
:::

:::remember
Соотношение для доказательства записывается как неравенство с константой $c$:

$$
T(n) \le T\left(\frac{7}{10}n\right) + T\left(\frac{n}{5}\right) + cn
$$

Нужно показать, что $T(n) \le c_1 n$ для некоторой константы $c_1$, то есть $T(n) \in O(n)$.
:::

### Доказательство по индукции

Докажем по индукции, что существует константа $c_1$, для которой $T(n) \le c_1 n$.

:::example
**База индукции.** Для малых $n$ (когда алгоритм просто сортирует несколько элементов) время ограничено некоторой константой. Поэтому для малых $n$ можно выбрать $c_1$ достаточно большим, чтобы неравенство $T(n) \le c_1 n$ выполнялось.

**Предположение индукции.** Пусть для всех меньших значений аргумента $T(m) \le c_1 m$.

**Шаг индукции.** Подставляем предположение в рекуррентное неравенство, применяя его к $\frac{7}{10}n$ и $\frac{n}{5}$ (оба меньше $n$):

$$
T(n) \le c_1 \cdot \frac{7}{10}n + c_1 \cdot \frac{n}{5} + cn
$$

Складываем коэффициенты при $c_1 n$: $\frac{7}{10} + \frac{2}{10} = \frac{9}{10}$. Получаем:

$$
T(n) \le \frac{9}{10}c_1 n + cn = c_1 n - \left(\frac{c_1 n}{10} - cn\right)
$$

Выражение в скобках неотрицательно, если $\frac{c_1}{10} \ge c$, то есть $c_1 \ge 10c$. Тогда:

$$
T(n) \le c_1 n
$$

Итак, при $c_1 \ge 10c$ (и достаточно большом $c_1$ для базы) неравенство выполняется для любого $n$. Значит, $T(n) \in O(n)$.
:::

:::warning
Всё держится на том, что сумма долей двух рекурсивных вызовов **меньше единицы**: $\frac{7}{10} + \frac{1}{5} = \frac{9}{10} < 1$. Если бы эта сумма была равна 1 или больше, шаг индукции не сработал бы и оценка $O(n)$ не доказывалась бы. Именно поэтому размер группы подобран так, чтобы доля $\frac{7}{10}$ оказалась достаточно малой.
:::
