@@ id=sel-idea type=algo src="Сортировка выбором"
Q: Как работает сортировка выбором (вариант с максимумом): идея, инвариант и почему на каждом шаге один элемент встаёт на своё окончательное место?
A:
На каждом шаге ищется наибольший элемент среди ещё не отсортированных и обменивается с последней позицией неотсортированной части, после чего эта часть становится на один элемент короче.

```python
def selection_sort(a):
    n = len(a)
    for end in range(n - 1, 0, -1):
        max_i = 0
        for j in range(1, end + 1):
            if a[j] > a[max_i]:
                max_i = j
        a[max_i], a[end] = a[end], a[max_i]
```

**Инвариант:** перед шагом с границей `end` суффикс `a[end+1..n-1]` состоит из наибольших элементов массива в отсортированном порядке, а `a[0..end]` — остальные. Максимум префикса не меньше всего префикса и не больше элементов суффикса, поэтому после обмена с `a[end]` позиция `end` окончательна.

@@ id=sel-trace type=trace src="Сортировка выбором"
Q: Выполни сортировку выбором (максимум в конец) для $[5, 2, 9, 1, 7]$.
A:
```array
title: Сортировка выбором (максимум уходит в конец)
[5, 2, 9, 1, 7]
pointers: j, m
code:
for (let end = a.length - 1; end > 0; end--) {
  let m = 0;
  for (let j = 1; j <= end; j++) {
    if (a[j] > a[m]) m = j;
  }
  swap(a, m, end);
  done(end, a.length - 1);
}
done(0, a.length - 1);
```

- `end = 4`: максимум $9$ (индекс 2) ↔ `a[4]`: $[5, 2, 7, 1, 9]$;
- `end = 3`: максимум $7$ (индекс 2) ↔ `a[3]`: $[5, 2, 1, 7, 9]$;
- `end = 2`: максимум $5$ (индекс 0) ↔ `a[2]`: $[1, 2, 5, 7, 9]$;
- `end = 1`: максимум $2$ уже на месте: $[1, 2, 5, 7, 9]$.

@@ id=sel-time type=calc src="Сортировка выбором"
Q: Выведи число сравнений сортировки выбором и объясни, почему оно не зависит от входных данных.
A:
Первый проход просматривает $n$ элементов — $n - 1$ сравнение, второй — $n - 2$, …, последний — $1$:
$$(n-1) + (n-2) + \dots + 1 = \frac{n(n-1)}{2} = O(n^2).$$
Для $n = 5$ это $10$ сравнений. Число сравнений **одинаково для любого входа**, даже отсортированного: поиск максимума всегда просматривает всю неотсортированную часть, поэтому лучшего случая нет — $\Theta(n^2)$. Память $O(1)$ (на месте).

@@ id=sel-weak type=concept src="Сортировка выбором"
Q: В чём слабое место сортировки выбором и какая идея ведёт к пирамиде?
A:
Каждый новый максимум ищется «с нуля» полным просмотром: результаты сравнений предыдущих проходов нигде не сохраняются, и информация выбрасывается. Идея пирамиды — **сохранить результаты сравнений в структуре данных**, чтобы следующий максимум находился не за $O(n)$, а за $O(\log n)$ (как в кубковом турнире, где сетка хранит сыгранные матчи).

@@ id=sel-unstable type=pitfall src="Сортировка выбором"
Q: Устойчива ли приведённая сортировка выбором с обменом? Покажи на примере.
A:
Нет. Обмен `a[max_i] ↔ a[end]` переносит элемент через всех, кто между ними, и может перепрыгнуть через равный ему.

Пример: $[2_a, 2_b, 1]$. При `end = 2` максимум (первый наибольший при строгом `>`) — $2_a$ (индекс 0), обмен с `a[2]`: $[1, 2_b, 2_a]$. Дальше $2_b$ уже на месте. Результат $[1, 2_b, 2_a]$: равные ключи поменялись местами. Пирамидальная сортировка наследует эту неустойчивость.

@@ id=round-robin type=calc src="Круговая система"
Q: Сколько матчей в круговой системе при $n$ командах, если каждая пара играет дважды? Сколько при $n = 20$ и как это связано с сортировкой выбором?
A:
Каждая команда играет с каждой из остальных $n - 1$ дважды, а матч считается один раз для пары: $n(n-1)$ матчей (каждая из $\binom n2$ пар — по два матча). Это $\Theta(n^2)$; для $n = 20$ — $380$ матчей.

Матч — это сравнение двух элементов. Поиск победителя за $O(n^2)$ сравнений — тот же порядок, что у сортировки выбором: в обоих случаях результаты сравнений используются один раз и не переиспользуются.

@@ id=cup-n-1 type=proof src="Кубковая система"
Q: Докажи, что в кубковой системе победитель определяется ровно за $n - 1$ матч.
A:
Каждый матч выбивает **ровно одну** команду (проигравшую), и никто не возвращается. Нужно выбить $n - 1$ команду, чтобы осталась одна. Значит, матчей ровно $n - 1 = O(n)$ — это то же число сравнений, что нужно для поиска максимума просмотром, но результаты матчей теперь сохранены в сетке.

@@ id=cup-second type=concept src="Кубковая система"
Q: Как в кубковой системе найти вторую команду ещё за $O(\log n)$ матчей и почему нельзя просто взять финалиста-проигравшего?
A:
Вторая команда обязательно среди тех, кто проиграл победителю **напрямую**: любой другой проигравший проиграл не победителю, а кому-то, кто сам хуже победителя. Победитель сыграл по одному матчу в каждом туре, поэтому таких команд порядка $\log n$ (в примере из 8 команд — $B$, $C$, $E$). Среди них проводим ещё порядка $\log n$ матчей.

```tree
tree
Финал: A — E
  Полуфинал: A — C
    Четвертьфинал: A — B
    Четвертьфинал: C — D
  Полуфинал: E — G
    Четвертьфинал: E — F
    Четвертьфинал: G — H
```

Проигравший в финале ($E$) не обязательно второй: $B$ мог проиграть $A$ в четвертьфинале, но быть сильнее $E$. Поэтому сравниваются **все** проигравшие победителю напрямую.

@@ id=cup-total type=calc src="Кубковая система"
Q: Оцени общее число матчей, чтобы расставить по местам все $n$ команд кубковой системой, и сравни с круговой.
A:
Победитель — $n - 1 = O(n)$ матчей. Для каждого следующего места нужно порядка $\log n$ новых матчей (сетка уже хранит результаты), мест $n$:
$$O(n) + n\cdot O(\log n) = O(n\log n).$$
Для круговой системы — $\Theta(n^2)$. Выигрыш — потому что в сетке результаты матчей не забываются. Это ровно то же $O(n\log n)$, которое даст пирамидальная сортировка.

@@ id=cup-as-tree type=concept src="Причём здесь алгоритмы"
Q: Какую структуру данных напоминает кубковая сетка и что даёт она алгоритму?
A:
Сетка — **дерево**, в котором хранятся результаты уже сыгранных матчей (сравнений). Поэтому следующий «победитель» находится не полным перебором, а обновлением вдоль одного пути дерева за $O(\log n)$. Именно такую структуру представляет собой пирамида (куча): она хранит накопленную информацию о сравнениях и выдаёт максимум за $O(1)$ с восстановлением за $O(\log n)$.

@@ id=heap-synonyms type=term src="Терминология"
Q: Как соотносятся слова «пирамида», «куча», «heap» и что значит «бинарная»?
A:
«Пирамида», «куча» и «heap» — синонимы, одна и та же структура данных. Уточнение **бинарная** означает, что это *бинарное* дерево (у узла не более двух детей) с определёнными свойствами формы и порядка значений. Не путать с кучей как областью динамической памяти — это другое понятие.

@@ id=tree-basics type=term src="Дерево и родители"
Q: Что такое дерево, корень, лист и бинарное дерево? Сколько родителей у узла?
A:
В дереве **у каждого узла, кроме корня, ровно один родитель**; корень родителя не имеет. Детей у узла может быть $0$ или несколько; узел без детей — **лист**. В **бинарном** дереве у каждого узла не больше двух детей (левый и правый). Высота дерева — длина самого длинного пути от корня до листа.

@@ id=complete-tree type=term src="Завершённое бинарное дерево"
Q: Что такое завершённое бинарное дерево, зачем оно нужно куче и какова его высота?
A:
**Завершённое бинарное дерево** — бинарное дерево, в котором заполнены все слои, кроме, возможно, последнего; последний слой заполняется **слева направо без пропусков**.

Зачем: такое дерево хранится в массиве без «дыр» (слой за слоем), положение родителя и детей считается по индексу. Высота дерева из $n$ узлов равна $\lfloor\log_2 n\rfloor = O(\log n)$ — отсюда логарифмическое время операций на куче.

@@ id=max-min-heap type=term src="Макс-куча и мин-куча"
Q: Дай определения макс-кучи и мин-кучи. Где находится экстремум и какие два условия нужны (форма и порядок)?
A:
**Макс-куча** — завершённое бинарное дерево, где значение каждого узла **не меньше** значений его детей; наибольший элемент — в корне. **Мин-куча** — то же, но значение узла **не больше** значений детей; наименьший — в корне.

Условий два: *форма* (завершённое бинарное дерево) и *порядок* (между узлом и его детьми). Нарушение любого из них делает структуру не кучей.

@@ id=heap-examples type=pitfall src="Примеры куч и не куч"
Q: Какие из деревьев являются макс-кучей: (1) корень 9, дети 7 и 8, у 7 дети 3 и 5, у 8 дети 6 и 4; (2) корень 5, дети 9 и 3, у 9 дети 1 и 2; (3) корень 9, дети 7 и 8, у 8 один ребёнок 3, у 7 детей нет? Обоснуй.
A:
(1) **Макс-куча**: форма завершена, и каждый узел не меньше детей ($9 \ge 7, 8$; $7 \ge 3, 5$; $8 \ge 6, 4$).

(2) **Не куча — нарушен порядок**: узел $5$ меньше своего ребёнка $9$.

(3) **Не куча — не завершено**: порядок значений соблюдён, но последний слой заполнен не слева направо ($7$ без детей, а у $8$ есть ребёнок $3$).

```tree
tree
9
  7
    3
    5
  8
    6
    4
```

@@ id=heap-properties type=pitfall src="Свойства пирамиды"
Q: Какие свойства имеет куча и в каком смысле она *не* упорядочена? Где может находиться минимум макс-кучи?
A:
Свойства: максимум (в мин-куче минимум) всегда в корне; поддерево любого узла — тоже куча; высота $\Theta(\log n)$.

Но куча **не полностью упорядочена**: порядок гарантирован только между узлом и его детьми, между поддеревьями порядка нет. В макс-куче $9; 7(3, 5); 8(6, 4)$ элемент $7$ из левого поддерева больше $6$ из правого, а $5$ из левого поддерева — меньше того же $6$. Поэтому минимум макс-кучи лежит в каком-то **листе**, но не обязательно в последнем элементе массива; отсортированный вывод из кучи без извлечений получить нельзя.

@@ id=heap-indices type=theorem src="Формулы для узла с индексом i"
Q: Как хранится куча в массиве и какие формулы дают индексы детей и родителя при индексации с нуля? Когда ребёнок существует и как формулы меняются при индексации с единицы?
A:
Узлы записываются слой за слоем, слева направо. При индексации с нуля:

- левый ребёнок: $2i + 1$; правый ребёнок: $2i + 2$;
- родитель: $\left\lfloor \dfrac{i-1}{2} \right\rfloor$.

Ребёнок существует, только если его индекс $< n$. При индексации с единицы формулы другие: $2i$, $2i + 1$, $\lfloor i/2 \rfloor$ — путаница между ними частая ошибка.

Проверка на $[9, 7, 8, 3, 5, 6, 4]$ ($n = 7$), узел $i = 1$ (значение $7$): дети — индексы $3$ и $4$ (значения $3$ и $5$), родитель — $\lfloor 0/2 \rfloor = 0$ (значение $9$).

@@ id=heap-indices-why type=proof src="Формулы для узла с индексом i"
Q: Почему левый ребёнок узла $i$ имеет индекс $2i + 1$? Выведи из устройства слоёв.
A:
Слой $k$ (корень — слой $0$) содержит $2^k$ узлов и в массиве начинается с индекса $2^k - 1$ (до него $1 + 2 + \dots + 2^{k-1} = 2^k - 1$ узлов). Узел с номером $m$ в слое $k$ имеет индекс $i = 2^k - 1 + m$ ($m = 0, 1, \dots$). Его дети — узлы $2m$ и $2m + 1$ в слое $k + 1$, начало которого $2^{k+1} - 1$. Значит, левый ребёнок:
$$2^{k+1} - 1 + 2m = 2(2^k - 1 + m) + 1 = 2i + 1,$$
правый — на единицу больше, $2i + 2$. Родитель получается обращением формулы: $\lfloor (i - 1)/2 \rfloor$.

@@ id=heap-leaves type=calc src="Сколько листьев, если известно общее число узлов"
Q: Какие индексы у листьев кучи из $n$ элементов и сколько их? Посчитай для $n = 7$, $n = 6$, $n = 11$.
A:
Узел $i$ имеет детей, только если $2i + 1 < n$, то есть $i < \tfrac{n-1}{2}$. Внутренние узлы — индексы $0, \dots, \lfloor n/2 \rfloor - 1$, их $\lfloor n/2 \rfloor$; **листья** — индексы от $\lfloor n/2 \rfloor$ до $n - 1$, их $\lceil n/2 \rceil$.

- $n = 7$: внутренние $0, 1, 2$; листья $3, 4, 5, 6$ — четыре.
- $n = 6$: внутренние $0, 1, 2$; листья $3, 4, 5$ — три.
- $n = 11$: листья с $5$ по $10$ — шесть.

Листьев примерно половина всех узлов.

@@ id=heapsort-idea type=algo src="Идея: сортировка выбором на максимальной куче"
Q: В чём идея пирамидальной сортировки как сортировки выбором на максимальной куче? Какие шаги и почему следующий максимум не надо искать заново?
A:
В макс-куче максимум — в корне, найти его можно сразу. Алгоритм:

1. Превратить массив в макс-кучу.
2. Обменять корень (максимум) с последним элементом кучи — максимум встал на итоговое место.
3. Считать кучу короче на один элемент.
4. Восстановить свойство кучи, «просеяв» новый корень вниз.
5. Повторять 2–4, пока в куче не остался один элемент.

Следующий максимум снова в корне: информация о сравнениях хранится в структуре кучи, как в кубковой сетке.

@@ id=siftdown-def type=algo src="Просеивание вниз (siftdown)"
Q: Что делает `siftdown`, при каком условии он корректен и как выбирается ребёнок для обмена?
A:
`siftdown(i)` восстанавливает свойство кучи, если оно нарушено **только в узле $i$** (его значение может быть меньше значений детей), а оба поддерева уже являются кучами. Пока у узла есть дети: выбираем **большего** из детей; если узел меньше этого ребёнка — обмениваем и идём вниз к ребёнку; иначе останавливаемся.

```diagram
A: round "Узел i"
B: diamond "Есть дети?"
C: box "Выбрать большего ребёнка"
D: diamond "Узел меньше ребёнка?"
E: box "Обменять с ребёнком, перейти к нему"
F: round "Конец"
A -> B
B -> F : Нет
B -> C : Да
C -> D
D -> E : Да
D -> F : Нет
E -> B
```

@@ id=siftdown-code type=code src="Просеивание вниз (siftdown)"
Q: Разбери код `sift_down`: что делают `left`, `right`, `largest`, зачем параметр `n` и почему проверки `left < n`, `right < n` идут перед сравнением?
A:
```python
def sift_down(a, i, n):
    while True:
        left = 2 * i + 1
        right = 2 * i + 2
        largest = i
        if left < n and a[left] > a[largest]:
            largest = left
        if right < n and a[right] > a[largest]:
            largest = right
        if largest == i:
            break
        a[i], a[largest] = a[largest], a[i]
        i = largest
```

`largest` ищет максимум среди узла и его существующих детей: сначала сравниваем с левым, затем с правым — выбирается именно **больший** ребёнок, и только если он больше узла. `n` — **текущий размер кучи**: при сортировке отсортированный суффикс остаётся в массиве, но в кучу уже не входит, поэтому индексы $\ge n$ — не дети. Проверки границ идут первыми, иначе `a[left]` выйдет за пределы кучи/массива. Если `largest == i` — узел не меньше детей, спуск закончен.

@@ id=siftdown-bigger type=pitfall src="Просеивание вниз (siftdown)"
Q: Что нарушится, если при просеивании обменять узел с меньшим ребёнком? Покажи на примере.
A:
Пример: корень $1$, дети $5$ и $9$. Если обменять с меньшим ($5$), получится корень $5$ с детьми $1$ и $9$: ребёнок $9$ **больше** своего родителя $5$ — свойство кучи нарушено. Обмен с большим ($9$) даёт корень $9$ и детей $5$, $1$ — порядок верен: поднявшийся больший ребёнок не меньше второго. Поэтому всегда выбирают большего ребёнка.

@@ id=siftdown-cost type=proof src="Просеивание вниз (siftdown)"
Q: Почему одно просеивание стоит $O(\log n)$, а на какую величину оно ограничено точнее?
A:
Каждый обмен опускает элемент ровно на один уровень вниз; на каждом уровне — $O(1)$ работы (два сравнения и обмен). Глубина дерева — $\lfloor\log_2 n\rfloor$, значит не более $\log_2 n$ шагов: $O(\log n)$. Точнее, стоимость просеивания узла ограничена его **высотой** $h$ (расстоянием до самого дальнего листа), на этом факте держится оценка построения кучи за $O(n)$.

@@ id=heapsort-algo type=algo src="Алгоритм целиком"
Q: Запиши пирамидальную сортировку целиком, укажи инвариант второй фазы и память алгоритма.
A:
```python
def heap_sort(a):
    n = len(a)
    for i in range(n // 2 - 1, -1, -1):   # 1. построение кучи
        sift_down(a, i, n)
    for end in range(n - 1, 0, -1):       # 2. извлечение максимумов
        a[0], a[end] = a[end], a[0]
        sift_down(a, 0, end)
```

**Инвариант** второй фазы: перед шагом `end` префикс `a[0..end]` — макс-куча, а суффикс `a[end+1..]` — самые большие элементы в отсортированном порядке. Обмен ставит текущий максимум на `end`; размер кучи теперь `end`, и просеивание возвращает кучу.

Всё делается в самом массиве: память $O(1)$ (сортировка на месте). Сортировка не устойчива.

@@ id=heapsort-trace type=trace src="Алгоритм целиком"
Q: Выполни пирамидальную сортировку $[5, 2, 9, 1, 7, 3]$: построение кучи и извлечение максимумов.
A:
```array
title: Пирамидальная сортировка
[5, 2, 9, 1, 7, 3]
pointers: i, big
print: last
code:
function siftDown(i, n) {
  while (2 * i + 1 < n) {
    let big = 2 * i + 1;
    if (big + 1 < n && a[big + 1] > a[big]) big = big + 1;
    if (a[i] >= a[big]) return;
    swap(a, i, big);
    i = big;
  }
}
let n = a.length;
for (let s = Math.floor(n / 2) - 1; s >= 0; s--) siftDown(s, n);
for (let end = n - 1; end > 0; end--) {
  swap(a, 0, end);
  siftDown(0, end);
  done(end, n - 1);
}
done(0, n - 1);
```

**Построение** ($n = 6$, индексы $2, 1, 0$): $i = 2$: $9 \ge 3$, обмена нет; $i = 1$: $2$ и дети $1, 7$ → обмен с $7$: $[5, 7, 9, 1, 2, 3]$; $i = 0$: $5$ и дети $7, 9$ → обмен с $9$: $[9, 7, 5, 1, 2, 3]$, дальше $5 \ge 3$ — стоп.

**Извлечение** (| отделяет отсортированную часть):

| Шаг | После обмена | После просеивания |
|---|---|---|
| 1 | $[3, 7, 5, 1, 2 \mid 9]$ | $[7, 3, 5, 1, 2 \mid 9]$ |
| 2 | $[2, 3, 5, 1 \mid 7, 9]$ | $[5, 3, 2, 1 \mid 7, 9]$ |
| 3 | $[1, 3, 2 \mid 5, 7, 9]$ | $[3, 1, 2 \mid 5, 7, 9]$ |
| 4 | $[2, 1 \mid 3, 5, 7, 9]$ | без изменений ($2 \ge 1$) |
| 5 | $[1 \mid 2, 3, 5, 7, 9]$ | — |

Результат: $[1, 2, 3, 5, 7, 9]$.

@@ id=build-bottom-up type=algo src="Эффективное построение"
Q: Как строится куча из произвольного массива, почему порядок обхода «снизу вверх» корректен и почему цикл начинается с $n/2 - 1$?
A:
```python
for i in range(n // 2 - 1, -1, -1):
    sift_down(a, i, n)
```

Идём по узлам от последнего внутреннего к корню и для каждого запускаем `siftdown`. Корректность: в момент просеивания узла $i$ оба его поддерева (узлы с большими индексами) уже кучи — то есть выполнены условия, для которых `siftdown` написан.

Начинаем с $n/2 - 1$, потому что узлы с индексами от $\lfloor n/2 \rfloor$ — листья: у них нет детей, каждый лист уже куча из одного элемента, просеивать их не нужно.

@@ id=build-wrong-order type=pitfall src="Эффективное построение"
Q: Почему нельзя строить кучу, запуская `siftdown` сверху вниз (от корня к листьям)? Покажи на $[1, 2, 3, 4, 5, 6, 7]$.
A:
При обходе от корня условие `siftdown` (поддеревья уже кучи) не выполнено: нижние узлы ещё не упорядочены, и более поздние просеивания не исправят корень.

Пример: $i = 0$: $1$ спускается — обмен с $3$, затем (у позиции 2 дети $6, 7$) с $7$: $[3, 2, 7, 4, 5, 6, 1]$. $i = 1$: $2$ и дети $4, 5$ → обмен с $5$: $[3, 5, 7, 4, 2, 6, 1]$. $i = 2$: $7 \ge 6, 1$ — без изменений. Корень $3$ меньше своих детей $5$ и $7$ — это **не куча**: просеивание корня шло, когда нижние поддеревья ещё не были кучами. Снизу вверх: $i = 2$ → $[1,2,7,4,5,6,3]$, $i = 1$ → $[1,5,7,4,2,6,3]$, $i = 0$ → $[7,5,6,4,2,1,3]$ — куча.

@@ id=build-linear type=proof src="Почему это O(n), а не O(n log n)"
Q: Докажи, что построение кучи снизу вверх занимает $O(n)$, а не $O(n\log n)$.
A:
Оценка «$n/2$ узлов по $O(\log n)$» верна, но слишком грубая: просеивание узла стоит порядка его **высоты** $h$ (расстояния до самого дальнего листа), а не $\log n$.

1. Узлов высоты $h$ не более $\lceil n/2^{h+1} \rceil$: у листьев ($h = 0$) их больше всего, у корня — один.
2. Суммарная стоимость:
$$\sum_{h=0}^{\log n} \frac{n}{2^{h+1}}\cdot O(h) = O\!\left(n \sum_{h=0}^{\infty}\frac{h}{2^h}\right).$$
3. Ряд $\sum_{h\ge 0} h/2^h$ сходится к $2$ — константа.

Итого $O(n)$. Основная масса узлов лежит у листьев, где просеивание дёшево; только единицы узлов вблизи корня спускаются на полную глубину.

@@ id=build-calc type=calc src="Почему это O(n), а не O(n log n)"
Q: Оцени максимальное число обменов при построении кучи из $n = 15$ элементов (полное бинарное дерево) и сравни с $n\log_2 n$.
A:
Высоты узлов полного дерева из $15$ узлов: $8$ листьев ($h = 0$, просеивать не нужно), $4$ узла высоты $1$ (не более $1$ обмена), $2$ узла высоты $2$ (не более $2$), $1$ корень высоты $3$ (не более $3$):
$$4\cdot 1 + 2\cdot 2 + 1\cdot 3 = 11 \text{ обменов.}$$
Это меньше $n = 15$, тогда как $n\log_2 n \approx 58$ — линейность видна уже на малом примере.

@@ id=heap-complexity type=calc src="Асимптотики"
Q: Выведи итоговую асимптотику пирамидальной сортировки по фазам и скажи, какая фаза определяет ответ.
A:
| Действие | Время |
|---|---|
| Построение кучи из массива | $O(n)$ |
| Одно просеивание вниз | $O(\log n)$ |
| Извлечение всех $n$ максимумов | $n\cdot O(\log n) = O(n\log n)$ |
| Сортировка целиком | $O(n) + O(n\log n) = O(n\log n)$ |

Ответ определяет вторая фаза; линейное построение на её фоне незаметно. В отличие от сортировки выбором ($O(n^2)$), следующий максимум стоит $O(\log n)$, а не $O(n)$. Худший, средний и лучший случаи у heapsort по порядку совпадают — $\Theta(n\log n)$.

@@ id=heapsort-compare type=compare src="Асимптотики"
Q: Сравни пирамидальную сортировку с сортировкой выбором и сортировкой слиянием по времени, памяти и устойчивости. Когда выбирать heapsort?
A:
| | Выбором | Пирамидальная | Слиянием |
|---|---|---|---|
| Время (худшее) | $\Theta(n^2)$ | $\Theta(n\log n)$ | $\Theta(n\log n)$ |
| Доп. память | $O(1)$ | $O(1)$ | $O(n)$ |
| Устойчивость | нет (с обменом) | нет | да |

Heapsort — когда нужна **гарантия** $O(n\log n)$ в худшем случае и память $O(1)$ (на месте), а устойчивость не нужна. Если нужна устойчивость — слиянием (ценой $O(n)$ памяти). Выбором — только для малых $n$ (и когда важно минимизировать число обменов: их не более $n - 1$).
