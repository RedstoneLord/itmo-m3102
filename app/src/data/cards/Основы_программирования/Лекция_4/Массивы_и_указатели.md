@@ id=array-def type=term src="3. Массивы и адресная арифметика"
Q: Что такое встроенный массив в C++, какие индексы для него допустимы и как посчитать его размер в байтах?
A:
Массив — последовательность элементов **одного типа**, лежащих в памяти **подряд**, без промежутков. Размер задаётся при создании и **не меняется**.

- Индексация с нуля: для `N` элементов допустимо $0 \le i \le N - 1$; индекс `N` и больше — за границей массива.
- Размер в байтах: $N \cdot \mathrm{sizeof}(T)$. Для `int[5]` при `sizeof(int) == 4` это $5 \cdot 4 = 20$ байт, а адреса соседних элементов отличаются на 4.

@@ id=array-bounds-bug type=pitfall src="3. Массивы и адресная арифметика"
Q: Найди ошибку и объясни, что будет, когда её не заметит компилятор:
```cpp
int a[5] = {1, 2, 3, 4, 5};
for (int i = 0; i <= 5; ++i) {
    std::cout << a[i] << ' ';
}
```
A:
Условие `i <= 5` пускает цикл и на `i == 5`, а допустимы индексы `0…4`. Обращение `a[5]` — **неопределённое поведение**: язык не проверяет границы, поэтому программа может напечатать мусор, испортить соседнюю переменную или упасть — и «работать» на другом запуске.

Исправление: `i < 5` (лучше — `i < sizeof(a) / sizeof(a[0])`). Типичная «ошибка на единицу» (off-by-one): чаще всего путают `<` и `<=`.

@@ id=array-declare-sizes type=calc src="Объявление массивов"
Q: Чему равны размеры (при `sizeof(int) == 4`, `sizeof(double) == 8`): (а) `int u[10];` (б) `int w[] = {1, 2, 3, 4, 5};` (в) `double d[7];` (г) `int m[2][3];` — а также `sizeof(m[0])` и число строк и столбцов в `m`, посчитанные через `sizeof`?
A:
- (а) `sizeof(u) = 10 · 4 = 40`.
- (б) размер выводится из списка: 5 элементов, `sizeof(w) = 20`.
- (в) `sizeof(d) = 7 · 8 = 56`.
- (г) `sizeof(m) = 2 · 3 · 4 = 24`; `m[0]` — это целая строка `int[3]`, `sizeof(m[0]) = 12`.
- Строк: `sizeof(m) / sizeof(m[0]) = 24 / 12 = 2`; столбцов: `sizeof(m[0]) / sizeof(m[0][0]) = 12 / 4 = 3`.

@@ id=array-init-forms type=code src="Объявление массивов"
Q: Что выведет программа и почему?
```cpp
int a[5] = {1, 2};
int b[] = {7, 8, 9};
int c[2][3] = {{1, 2, 3}, {4}};
std::cout << sizeof(b) / sizeof(b[0]) << ' ' << a[1] << a[4] << ' ' << c[1][0] << c[1][2] << '\n';
```
A:
Вывод: `3 20 40`.

- `b` без размера: компилятор берёт его из списка — 3 элемента.
- `a` объявлен на 5, в списке 2 значения: остальные элементы **обнуляются** (`a = {1, 2, 0, 0, 0}`), поэтому `a[1] = 2`, `a[4] = 0` — печатается `20`.
- В `c` во второй строке задан только `4`, остальное — нули: `c[1] = {4, 0, 0}`, поэтому `c[1][0] = 4`, `c[1][2] = 0` — `40`.

Это работает, когда есть хотя бы один инициализатор. Массив **без** инициализатора (`int u[10];` в функции) содержит неопределённые значения — читать их нельзя.

@@ id=array-matrix-layout type=concept src="Объявление массивов"
Q: Как двумерный массив `int matrix[2][3] = {{1, 2, 3}, {4, 5, 6}};` лежит в памяти и что такое `matrix[1]`?
A:
`matrix` — массив из **2 элементов**, каждый из которых сам массив `int[3]`. Строки лежат в памяти **подряд**: сначала вся строка `0`, сразу за ней строка `1`.

```array
title: matrix[2][3] в памяти по возрастанию адресов
[1, 2, 3, 4, 5, 6] highlight: 5
```

`matrix[1]` — вторая строка целиком (тип `int[3]`), `matrix[1][2]` — её третий элемент, `6`. Индексы с нуля по каждому измерению.

@@ id=decay-term type=term src="Преобразование массива в указатель"
Q: Что такое array-to-pointer decay, в каких ситуациях он происходит и что при нём теряется?
A:
**Decay** — неявное преобразование массива `T[N]` в указатель `T*` на его **первый элемент** (`values` → `&values[0]`; для `const`-массива получается `const T*`). Происходит:

- при инициализации и присваивании указателя: `int* first = values;`;
- при передаче в функцию с параметром-указателем;
- в адресной арифметике: `values + 1`.

Элементы **не копируются**, и информация о длине **теряется**: указатель хранит только адрес первого элемента.

@@ id=decay-copy type=pitfall src="Преобразование массива в указатель"
Q: Копирует ли `int* first = values;` массив? Почему не компилируются `int b[3] = values;` и `b = values;`?
A:
Нет, копируется только адрес первого элемента: `first[1] = 5;` изменит `values[1]`, это тот же массив.

Массив нельзя инициализировать или присвоить другим массивом: справа `values` превращается в указатель, а массив из 3 `int` из указателя не построить, и встроенного копирующего присваивания у массивов нет. Чтобы скопировать — цикл, `std::copy`/`std::memcpy` или `std::array` (его копировать можно).

@@ id=decay-trace type=code src="Преобразование массива в указатель"
Q: Что выведет программа и в каких местах массив превращается в указатель?
```cpp
void PrintFirst(const int* pointer) { std::cout << *pointer << '\n'; }

int main() {
    int values[] = {10, 20, 30};
    int* first = values;
    PrintFirst(values);
    std::cout << *(values + 1) << '\n';
    std::cout << values[0] << ' ' << *values << ' ' << *first << '\n';
}
```
A:
Вывод:
```text
10
20
10 10 10
```
- `int* first = values;` — decay при инициализации, `first == &values[0]`.
- `PrintFirst(values)` — decay при передаче аргумента; функция печатает `*pointer == 10`.
- `values + 1` — decay в арифметике, прибавляется **один элемент** (4 байта), получаем `&values[1]`, разыменование — `20`.
- `values[0]`, `*values`, `*first` — один и тот же первый элемент.

@@ id=no-decay-cases type=concept src="Когда массив остаётся массивом"
Q: В каких четырёх случаях массив НЕ превращается в указатель и почему именно там?
A:
Массив остаётся массивом, когда выражению нужен **сам массив**, а не адрес первого элемента:

1. `sizeof(values)` — размер всего массива (`N · sizeof(T)`);
2. `&values` — адрес **всего** массива, тип `int(*)[3]`;
3. `decltype(values)` — объявленный тип `int[3]`;
4. связывание со **ссылкой на массив**: `int (&reference)[3] = values;`.

Во всех остальных выражениях (инициализация указателя, аргумент функции, `values + 1`) массив уступает место указателю.

@@ id=no-decay-code type=code src="Когда массив остаётся массивом"
Q: Что выведет программа (`sizeof(int) == 4`, указатель — 8 байт) и почему `a + 1` и `&a + 1` сдвигаются по-разному?
```cpp
int a[3] = {10, 20, 30};
std::cout << sizeof(a) << ' ' << sizeof(&a) << ' ' << sizeof(a + 0) << '\n';
std::cout << reinterpret_cast<char*>(a + 1) - reinterpret_cast<char*>(a) << ' '
          << reinterpret_cast<char*>(&a + 1) - reinterpret_cast<char*>(&a) << '\n';
```
A:
Вывод:
```text
12 8 8
4 12
```
- `sizeof(a)` — массив не распался: `3 · 4 = 12`.
- `sizeof(&a)` — это указатель (на массив), 8 байт.
- `sizeof(a + 0)` — в арифметике массив распался в `int*`, значит 8.
- `a + 1` имеет тип `int*`: шаг — один `int`, **4 байта**.
- `&a + 1` имеет тип `int(*)[3]`: шаг — целый массив, **12 байт** (адрес сразу за массивом). Численно `a` и `&a` равны, но это разные типы, поэтому и арифметика с ними разная.

@@ id=array-pointer-types type=compare src="Когда массив остаётся массивом"
Q: Сравни `int* p[3]`, `int (*p)[3]`, `int (&p)[3] = values` и `int* p = values`: что это за объекты и сколько они занимают?
A:
| Объявление | Что это | `sizeof` |
| --- | --- | --- |
| `int* p[3]` | **массив** из 3 указателей на `int` | 24 |
| `int (*p)[3]` | **указатель** на массив из 3 `int` | 8 |
| `int (&p)[3] = values` | **ссылка** на весь массив (сам объект — `values`) | 12 (`sizeof` ссылки даёт размер массива) |
| `int* p = values` | указатель на первый `int` | 8 |

Скобки решают: `[]` связывается с именем сильнее `*`, поэтому `int* p[3]` — массив указателей, а чтобы получить указатель на массив, `*p` берут в скобки. Указатель на массив нужен, чтобы сохранить размер в типе: `(*p)[1]` — второй элемент, сначала разыменуем, потом индексируем.

@@ id=sizeof-param type=code src="sizeof массива и параметра функции"
Q: Что выведет программа и почему? Чему равно `sizeof(array) / sizeof(array[0])` внутри `PrintSize`?
```cpp
void PrintSize(int* array) { std::cout << sizeof(array) << '\n'; }

int main() {
    int values[10]{};
    std::cout << sizeof(values) << '\n';
    PrintSize(values);
}
```
A:
Вывод: `40` и `8`.

- В `main` `values` — настоящий массив: `10 · 4 = 40`.
- При вызове `PrintSize(values)` массив распался в указатель; внутри функции `array` — обычный `int*`, а `sizeof` указателя равен 8.
- `sizeof(array) / sizeof(array[0])` внутри функции даст `8 / 4 = 2` — **не** число элементов, а бессмыслица. Подсчёт «через `sizeof`» работает только там, где виден сам массив.

Параметр `int array[]` и даже `int array[10]` — это тоже `int*`: число в скобках игнорируется.

```diagram

A: box "values в main: int[10], 40 байт"
B: box "array в PrintSize: int*, 8 байт"
A -> B : передача в функцию (decay)
```

@@ id=pass-array-size type=concept src="sizeof массива и параметра функции"
Q: Как функция узнаёт, сколько элементов в переданном ей массиве, если параметр — указатель?
A:
Из указателя число элементов получить нельзя, поэтому размер передают **отдельно**:

- `void F(const int* data, std::size_t size)` — адрес и длина (самый частый вариант, как в `FindByOrder(array, size, …)`);
- пара указателей `[begin, end)`;
- ссылка на массив с размером в типе: `void F(int (&array)[3])` или шаблон `template <std::size_t N> void F(int (&array)[N])` — размер известен компилятору;
- `std::array`/`std::span`, которые хранят размер.

Ошибка — вычислять размер внутри функции через `sizeof(array)`.

@@ id=ptr-step-calc type=calc src="Арифметика указателей"
Q: Указатель `p` равен адресу `0x1000`. Чему равен `p + 3`, если `p` имеет тип (а) `char*`, (б) `int*`, (в) `double*` (`sizeof(double) == 8`)?
A:
К адресу прибавляется $n \cdot \mathrm{sizeof}(T)$:

- (а) `char*`: $0x1000 + 3 \cdot 1 = $ `0x1003`;
- (б) `int*`: $0x1000 + 3 \cdot 4 = $ `0x100C`;
- (в) `double*`: $0x1000 + 3 \cdot 8 = $ `0x1018`.

Смещение в адресной арифметике считается **в элементах** типа указателя, а не в байтах; компилятор сам умножает на `sizeof(T)`. Поэтому `p + 1` всегда «следующий элемент».

@@ id=ptr-ops type=concept src="Арифметика указателей"
Q: Какие операции допустимы над указателями на элементы одного массива и что они означают?
A:
- `p + n`, `p - n` — указатель, сдвинутый на `n` **элементов** вперёд/назад;
- `q - p` — **число элементов** между указателями (тип `std::ptrdiff_t`, знаковый); например, `end - begin` — длина диапазона;
- `p < q`, `p == q` и др. — сравнение позиций;
- `*p`, `p[i]` — доступ к элементу.

Всё это определено только для указателей **внутри одного массива** (плюс позиция сразу за последним элементом). Вычитать или сравнивать указатели на разные объекты — не имеет смысла и даёт неопределённый результат.

@@ id=index-equivalence type=concept src="Индексы и смещения"
Q: Почему `values[i]`, `*(values + i)`, `pointer[i]` и `*(pointer + i)` — одно и то же? Почему тогда компилируется даже `2[values]`?
A:
Индексирование — это сокращённая запись адресной арифметики: `a[i]` по определению означает `*(a + i)`. Если `values` — массив, он сначала превращается в указатель на первый элемент (decay), к нему прибавляется `i` **элементов**, и результат разыменовывается. Тот же смысл у `pointer[i]`.

Поскольку сложение коммутативно, `*(values + 2)` равно `*(2 + values)`, то есть `2[values]` — это `values[2]`. Так писать не нужно, но это хорошо показывает, что `[]` — просто сахар над `*(… + …)`. Всё сказанное верно только для **допустимых** индексов.

@@ id=index-pointer-code type=code src="Индексы и смещения"
Q: Что выведет программа и почему допустим отрицательный индекс?
```cpp
int v[] = {10, 20, 30, 40, 50};
int* p = v + 1;
std::cout << p[1] << ' ' << *(p + 2) << ' ' << p[-1] << ' ' << (p - v) << '\n';
```
A:
Вывод: `30 40 10 1`.

Указатель `p` смотрит на `v[1]` (значение `20`), поэтому `p[k]` — это `v[1 + k]`:

- `p[1]` → `v[2] = 30`;
- `*(p + 2)` → `v[3] = 40`;
- `p[-1]` → `v[0] = 10`: индекс `-1` законен, потому что `p - 1` по-прежнему указывает **внутри** массива `v`;
- `p - v = 1` — расстояние между указателями в элементах.

Отрицательный индекс допустим только для указателя, который не на начале массива; `v[-1]` — выход за границу.

@@ id=range-half-open type=concept src="Границы арифметики указателей"
Q: Что такое полуоткрытый диапазон $[begin, end)$ для массива и чем удобно, что `end` указывает за последний элемент?
A:
`begin` указывает на первый элемент, `end` — на позицию **сразу после** последнего (`values + N`); сам `end` в диапазон не входит. Цикл: `for (int* current = begin; current != end; ++current)`.

Удобства: длина диапазона — просто `end - begin`; пустой диапазон — `begin == end` (не нужно «последнего элемента» там, где его нет); граница одного диапазона служит началом соседнего; условие остановки — единое `!=`. Так устроены итераторы стандартной библиотеки.

@@ id=end-ub type=pitfall src="Границы арифметики указателей"
Q: Какие из выражений безопасны, а какие — неопределённое поведение (`int values[3]`)? (а) `int* e = values + 3;` (б) `e == values + 3` (в) `*e` (г) `values + 4` (д) `values - 1`
A:
- (а) безопасно: указатель на позицию сразу за последним элементом получать **можно**;
- (б) безопасно: его можно сравнивать с другими указателями на тот же массив;
- (в) **UB**: разыменовывать `end` нельзя — там нет объекта;
- (г) **UB**: уходить дальше `values + N` нельзя, даже если результат не разыменовывается;
- (д) **UB**: до начала массива тоже нельзя.

Арифметика указателей определена только внутри одного массива и для позиции сразу за ним. Без разыменования указатель за границей не «безопасен» — само его получение уже UB.

@@ id=literal-const type=concept src="Строковый литерал и изменяемый массив"
Q: Чем строковый литерал `"Hello world"` отличается от `char second[] = "Hello world";` и почему указатель на литерал должен быть `const char*`?
A:
- **Литерал** — безымянный массив **константных** `char`, живущий всё время работы программы. Менять его нельзя; указатель на него — `const char*`.
- **`char second[] = "..."`** — здесь литерал лишь инициализатор: создаётся **отдельный изменяемый массив** `second`, в него копируются символы (включая `'\0'`), размер выводится из литерала.

`const char*` нужен, чтобы компилятор не дал записать в литерал: изменение литерала — неопределённое поведение (он может лежать в памяти, защищённой от записи).

@@ id=literal-code type=code src="Строковый литерал и изменяемый массив"
Q: Что выведет программа и почему? Какая запись добавила бы неопределённое поведение?
```cpp
const char* first = "Hello world";
char second[] = "Hello world";
const char* third = second;

second[0] = 'h';
std::cout << first << '\n' << third << '\n';
```
A:
Вывод:
```text
Hello world
hello world
```
`first` указывает на неизменяемый литерал; `second` — собственная изменяемая копия, `second[0] = 'h'` меняет только её. `third` смотрит на `second` (через `const char*` читать можно, писать нельзя), поэтому печатает уже `hello world`.

Неопределённое поведение — писать в сам литерал: например, `const_cast<char*>(first)[0] = 'h';` (в C++ инициализировать обычный `char*` литералом без `const` вообще запрещено именно ради этого).

@@ id=cstring-def type=term src="4. C-строки"
Q: Что такое C-строка и чем длина строки отличается от размера занимаемого массива?
A:
**C-строка** — нуль-терминированная последовательность `char`: массив символов, заканчивающийся `'\0'`. Терминатор занимает отдельный элемент, но в **длину** не входит.

Размер массива на **единицу больше** длины. `"Hello world"`: 11 символов (с пробелом), `'\0'` — в ячейке с индексом `11`, массив из 12 элементов.

```array

["H","e","l","l","o"," ","w","o","r","l","d","\0"] highlight: 11
```

@@ id=cstring-size-calc type=calc src="4. C-строки"
Q: Чему равны `sizeof` и `strlen` для: (а) `"Hello"`; (б) `char s[10] = "Hi";` (в) `char t[] = "Hi";` (г) `char r[2] = "Hi";`?
A:
- (а) литерал — массив из 6 `char` (5 букв и `'\0'`): `sizeof("Hello") = 6`, `strlen("Hello") = 5`;
- (б) `sizeof(s) = 10`, `strlen(s) = 2`: после `"Hi"` в оставшиеся ячейки записаны нули;
- (в) размер выводится: `sizeof(t) = 3`, `strlen(t) = 2`;
- (г) **ошибка компиляции**: литерал требует 3 ячейки, а в C++ место под `'\0'` обязательно (в C такое объявление было бы допустимо, но получилась бы не-строка).

Правило: для строки из $n$ символов нужен массив минимум на $n + 1$.

@@ id=strlen-pointer type=code src="Длина строки"
Q: Допиши функцию длины строки так, чтобы вместо счётчика использовалась разность указателей, и проследи её для `""` и `"Hello"`:
```cpp
std::size_t StringLength(const char* string) {
    const char* end = string;
    while (/* ... */) {
        /* ... */
    }
    return /* ... */;
}
```
A:
```cpp
std::size_t StringLength(const char* string) {
    const char* end = string;
    while (*end != '\0') {
        ++end;
    }
    return end - string;
}
```
`end` сдвигается, пока не встретит `'\0'`, а длина — это расстояние от начала в элементах (`end - string`).

- `""`: `*end` сразу `'\0'`, цикл не выполняется, `end - string = 0`.
- `"Hello"`: цикл делает 5 шагов, `end` останавливается на `'\0'` (индекс 5), результат `5`.

@@ id=strlen-precondition type=pitfall src="Длина строки"
Q: Каково предусловие функции длины строки и почему цикл `for (std::size_t i = 0; i < std::strlen(s); ++i)` плох?
A:
**Предусловие:** передан ненулевой указатель на корректную C-строку с завершающим `'\0'`. Для `nullptr` или массива без терминатора функция читает память за границей — **неопределённое поведение**: проверить это сама она не может.

`strlen` проходит строку целиком, то есть $O(n)$. Вызванная в условии цикла, она выполняется на **каждой** итерации, и обход строки из $n$ символов занимает $O(n^2)$. Длину нужно посчитать один раз до цикла (или остановиться по `s[i] != '\0'`).

@@ id=strcmp-equals type=pitfall src="Сравнение строк"
Q: Что выведет программа и почему сравнение через `==` — ошибка?
```cpp
const char* a = "cat";
char b[] = "cat";
std::cout << (a == b) << (std::strcmp(a, b) == 0) << '\n';
```
A:
Вывод: `01`.

`a == b` сравнивает **адреса**: `b` — отдельный массив (после decay `&b[0]`), его адрес не совпадает с адресом литерала, поэтому `0`, хотя тексты одинаковы. `std::strcmp(a, b)` сравнивает **содержимое** посимвольно и возвращает `0` для равных строк — проверка `== 0` даёт `1`.

Равенство двух литералов `"cat" == "cat"` тоже ненадёжно: компилятор вправе как слить их в один объект, так и нет — результат не определён. Для содержимого — только `strcmp` или ручной цикл.

@@ id=strcmp-algo type=algo src="Сравнение строк"
Q: Как работает `StringCompare` с индексами (`while (first[index] != '\0' && first[index] == second[index]) ++index; return … разность …;`)? Что значит результат?
A:
Идея: идём по обеим строкам, пока символы совпадают и первая строка не кончилась. **Инвариант:** все символы до `index` у строк одинаковы.

Остановка — первое различие либо конец первой строки (`'\0'`). Тогда возвращаем разность символов на этой позиции (как `unsigned char`):

- `0` — строки равны (дошли до общего `'\0'`, разность `0 - 0`);
- `< 0` — первая строка раньше второй в лексикографическом порядке;
- `> 0` — первая позже.

Если одна строка — префикс другой, у неё на позиции `'\0'`, код которого меньше любой буквы, так что более короткая строка идёт раньше. Время $O(\min(n, m))$, память $O(1)$.

@@ id=strcmp-trace type=trace src="Сравнение строк"
Q: Вычисли `StringCompare` для пар (`"cat"`, `"cat"`), (`"cat"`, `"car"`), (`"cat"`, `"cats"`), (`""`, `"a"`). Коды: `'t'` = 116, `'r'` = 114, `'s'` = 115, `'a'` = 97.
A:
| Пара | Где остановился цикл | Разность | Итог |
| --- | --- | --- | --- |
| `"cat"`, `"cat"` | `index = 3`, оба `'\0'` | $0 - 0 = 0$ | равны |
| `"cat"`, `"car"` | `index = 2`: `'t'` ≠ `'r'` | $116 - 114 = 2$ | $> 0$, первая позже |
| `"cat"`, `"cats"` | `index = 3`: `'\0'` и `'s'` | $0 - 115 = -115$ | $< 0$, первая раньше |
| `""`, `"a"` | `index = 0`: `'\0'` и `'a'` | $0 - 97 = -97$ | $< 0$ |

Сравнивать по числу надо **знак**, а не конкретное значение: стандартный `strcmp` обещает только знак результата.

@@ id=strcmp-unsigned type=concept src="Сравнение строк"
Q: Зачем символы в `StringCompare` приводятся к `unsigned char` и почему нельзя сравнивать их как `char` при `char` со знаком?
A:
`char` может быть знаковым (`-128…127`). Тогда байты с кодом $\ge 128$ (например, часть UTF-8-текста) получаются **отрицательными**, и порядок сравнения зависит от платформы и расходится с `std::strcmp`, который сравнивает символы как `unsigned char`. Пример: `"\xC3"` против `"a"` — как `unsigned char` $195 > 97$, а как знаковый `char` $-61 < 97$.

Приведение к `unsigned char` даёт одинаковый результат на всех платформах и совпадает со стандартной функцией. (В конспекте приведение объяснено «неопределённым поведением» — на деле неопределённости нет: просто разный порядок.)

@@ id=strcmp-pointers type=code src="Сравнение строк через указатели"
Q: Перепиши цикл сравнения без индекса, через сдвиг указателей. Почему при этом `++first` не портит строки, которые передал вызывающий?
A:
```cpp
int StringCompare(const char* first, const char* second) {
    while (*first != '\0' && *first == *second) {
        ++first;
        ++second;
    }
    return static_cast<unsigned char>(*first)
         - static_cast<unsigned char>(*second);
}
```
`first[index]` заменено на `*first`, а `++index` — на сдвиг обоих указателей.

Параметры `first` и `second` — **копии** указателей, локальные для функции: сдвиг меняет только копии, а сами строки (и указатели у вызывающего) остаются прежними. `const` относится к символам (`const char`), а не к указателю, поэтому двигать указатель можно, а писать через него — нет.

@@ id=cstring-danger type=pitfall src="Почему C-строки опасны"
Q: Что выведут `sizeof` и `strlen` и какая из строк опасна? Почему функция не может защитить себя сама?
```cpp
const char raw[3] = {'C', '+', '+'};
const char text[4] = "C++";
std::cout << sizeof(raw) << sizeof(text) << std::strlen(text) << '\n';
// std::strlen(raw);
```
A:
Вывод: `343`.

- `raw` — три символа без `'\0'`: формально **не C-строка**; `sizeof(raw) = 3`.
- `text` — три буквы и добавленный компилятором `'\0'`: `sizeof(text) = 4`, `strlen(text) = 3`.
- `strlen(raw)` — **UB**: функция ищет нулевой байт, а его нет, и читает память за границей массива.

`strlen` получает только адрес и не знает ни размера буфера, ни того, есть ли терминатор: проверить это она не может. Границы обязан контролировать программист — отсюда переполнения буфера.

@@ id=buffer-overflow type=code src="Почему C-строки опасны"
Q: Найди ошибку и скажи, сколько ячеек нужно на самом деле:
```cpp
char buffer[5];
std::strcpy(buffer, "Hello");
```
A:
Литерал `"Hello"` — 5 букв и `'\0'`, то есть **6** байт, а в `buffer` только 5. `strcpy` не знает размера приёмника и запишет шестой байт за границей массива — **переполнение буфера, неопределённое поведение** (порча соседней памяти, падение, уязвимость).

Нужно минимум `char buffer[6]`: для строки из $n$ символов — $n + 1$ ячеек. Размер приёмника надо учитывать самому (ограниченное копирование, `std::string`).

@@ id=argc-argv type=code src="Аргументы командной строки"
Q: Что значат `argc` и `argv`? Что выведет программа при запуске `./app one two` и чему равен `argv[argc]`?
```cpp
int main(int argc, char* argv[]) {
    for (int index = 0; index < argc; ++index) {
        std::cout << argv[index] << '\n';
    }
}
```
A:
- `argc` — число аргументов **включая имя программы**; `argv` — массив из указателей на C-строки, `argv[i]` — строка `i`-го аргумента.
- Запуск `./app one two`: `argc = 3`, печатается
```text
./app
one
two
```
(`argv[0]` — обычно путь/имя запуска программы).
- По стандарту `argv[argc] == nullptr` — массив завершается нулевым указателем, поэтому его можно обходить и без `argc`.

В параметре `char* argv[]` — это то же, что `char** argv`; `argv[1][0]` — первый символ первого аргумента. Числа приходят **строками**, их нужно разбирать самим.

@@ id=void-pointer-term type=term src="5. Универсальный указатель void*"
Q: Что такое `void*`, что с ним можно и нельзя делать?
A:
`void*` хранит адрес объекта **любого** типа, но «забывает» тип.

- Можно: неявно присвоить любой `T*`; передавать как «адрес чего-то»; вернуть тип явным `static_cast<T*>(…)`.
- Нельзя: разыменовать (`*p` — неизвестны размер и устройство объекта) и делать арифметику (`p + 1` — у `void` нет размера; компиляторы с расширением это допускают, но стандарт — нет).
- Обратно в `T*` — только **явно** (в C++ неявно нельзя, в отличие от C).

Это инструмент для кода, которому важен адрес, а не тип: `PrintBytes(const void*, size)`, `memcpy`, `malloc`.

@@ id=void-pointer-ub type=pitfall src="5. Универсальный указатель void*"
Q: Что не так с этим кодом и когда «забытый» тип можно безопасно восстановить?
```cpp
double value = 1.5;
void* untyped = &value;
int* wrong = static_cast<int*>(untyped);
std::cout << *wrong << '\n';
```
A:
Объект имеет тип `double`, а прочитан как `int` — это чтение объекта **через указатель несовместимого типа**: неопределённое поведение (нарушение правил доступа по типу; результат — мусор или поломка оптимизации). Компилятор ошибки не покажет: `static_cast` из `void*` не проверяет.

Безопасно восстанавливать **только тот тип, каким адрес был получен** (`double*` из `&value`) — так в конспекте `239` возвращается через `int*`. Единственное исключение для побайтового просмотра — `unsigned char`/`char` (см. `PrintBytes`).

@@ id=void-pointer-diagram type=concept src="void*: адрес без типа"
Q: Что хранит указатель `void*` на схеме и какой информации в нём нет?
A:
Только **адрес** — ячейка памяти. Из него нельзя узнать, что лежит по этому адресу: какой тип, сколько байтов, где конец объекта. Эти знания должен хранить программист (в соседнем параметре, в теге, в соглашении).

```diagram
diagram
A: box "untyped_pointer (void*)"
B: db "Объект в памяти (тип неизвестен)"
A -> B : хранит адрес
```

Поэтому функции с `void*` почти всегда принимают ещё и размер или тип: `PrintBytes(const void* object, std::size_t size)`.

@@ id=printbytes-concept type=concept src="Просмотр объекта как последовательности байтов"
Q: Как `PrintBytes(const void*, std::size_t)` показывает байты объекта любого типа? Почему индекс `bytes[index]` шагает ровно на один байт и зачем тут `const`?
A:
Адрес принимается как `const void*` (подойдёт любой объект), внутри приводится к `const unsigned char*` и проходится циклом по `size` байтам; каждый байт печатается в двоичном виде (`{:08b}` — 8 бит с ведущими нулями; `std::format` — C++20).

- Шаг ровно в один байт: тип `bytes` — указатель на `unsigned char`, а `sizeof(unsigned char) == 1`.
- `const` — функция только **читает**; через `const unsigned char*` менять объект нельзя.
- Смотреть на объект как на `unsigned char[]` можно законно: правила доступа по типу разрешают читать представление любого объекта через `unsigned char`.

@@ id=printbytes-trace type=trace src="Просмотр объекта как последовательности байтов"
Q: Что напечатает `PrintBytes` на little-endian для `int value = 2 << 10;` и для `value = 239;` (`sizeof(int) == 4`)?
A:
Значения: $2 \ll 10 = 2^{11} = 2048 = \texttt{0x00000800}$ и $239 = \texttt{0xEF}$. Байты выводятся от младшего адреса к старшему; на little-endian первым лежит **младший** байт.

```text
00000000 00001000 00000000 00000000    // 2048: байты 00, 08, 00, 00
11101111 00000000 00000000 00000000    // 239:  байты EF, 00, 00, 00
```
Для 2048 единственный ненулевой байт `0x08 = 00001000` — второй (индекс 1), потому что $2048 = 8 \cdot 256$. На big-endian те же числа выглядели бы зеркально: `00000000 00000000 00001000 00000000` и `00000000 00000000 00000000 11101111`.

@@ id=endian-def type=term src="Порядок байтов"
Q: Что такое little-endian и big-endian? Как лежит в памяти `0x12345678` в каждом из порядков?
A:
- **Little-endian** — **младший** байт числа лежит по **младшему** адресу.
- **Big-endian** — **старший** байт по младшему адресу (обратный порядок).

Байты `0x12345678` по возрастанию адресов (адрес $+0, +1, +2, +3$):

```array
title: Little-endian
["0x78", "0x56", "0x34", "0x12"] highlight: 0
```

```array
title: Big-endian
["0x12", "0x34", "0x56", "0x78"] highlight: 0
```

Порядок зависит от платформы (x86 и ARM в обычном режиме — little-endian), поэтому код, зависящий от байтового представления, непереносим.

@@ id=endian-detect type=code src="Порядок байтов"
Q: Как программно определить порядок байтов платформы? Допиши условие:
```cpp
unsigned int value = 1;
const unsigned char* first_byte = reinterpret_cast<const unsigned char*>(&value);
bool little_endian = /* ... */;
```
A:
```cpp
bool little_endian = (*first_byte == 1);
```
Число `1` — это один ненулевой младший байт и нули. По младшему адресу (`first_byte` — адрес первого байта `value`) на little-endian лежит этот младший байт, то есть `1`; на big-endian там старший байт, то есть `0`.

Читать представление объекта через `unsigned char*` законно (исключение из правил доступа по типу). Берётся только первый байт, поэтому размер числа неважен.

@@ id=endian-where type=concept src="Порядок байтов"
Q: Когда порядок байтов становится проблемой и когда о нём можно не думать?
A:
Не нужно думать, пока число используется **как число** внутри программы (`+`, `<<`, `==` работают одинаково на любой платформе). Проблема возникает, когда число **превращается в байты и обратно**:

- сериализация в файл, который читают на другой платформе;
- сетевой обмен (в протоколах принят big-endian — «сетевой порядок байтов»);
- побайтовый просмотр объекта (`PrintBytes`, `memcpy` в массив байтов).

В таких местах порядок задают явно — договором формата или сдвигами (`(x >> 8) & 0xFF`), а не копированием памяти `int`.

@@ id=funcptr-term type=term src="6. Указатели на функции"
Q: Что такое указатель на функцию и из чего состоит его тип? Как его получить и вызвать?
A:
Переменная, хранящая **адрес функции**. Тип включает **возвращаемый тип и типы параметров**: `int (*)(int)` — указатель на функцию из `int` в `int`.

```cpp
int same(int value) { return value; }

int (*function)(int) = same;         // имя функции -> указатель
int (*same_function)(int) = &same;   // то же самое
int result = function(2);            // вызов; (*function)(2) тоже
```
`&` перед именем функции необязателен — по аналогии с decay массива. Присвоить можно только функцию с **совпадающей** сигнатурой. Указатель можно переназначить на другую функцию.

@@ id=funcptr-parens type=pitfall src="6. Указатели на функции"
Q: Чем отличаются `int (*f)(int)` и `int* f(int)`? Что произойдёт, если забыть скобки?
A:
- `int (*f)(int)` — `f` — **указатель на функцию**, принимающую `int` и возвращающую `int`.
- `int* f(int)` — **объявление функции** `f`, которая принимает `int` и возвращает `int*`.

Скобки вокруг `*f` нужны потому, что `()` (функция) связывается с именем сильнее `*`. Без них вместо переменной получится объявление функции, и присвоение `f = same;` не скомпилируется.

@@ id=findbyorder-algo type=algo src="Функция как параметр алгоритма"
Q: Как работает `FindByOrder(int* array, std::size_t size, bool (*comes_before)(int, int))`, что она возвращает и какая у неё сложность?
A:
Идея: поиск «лучшего» элемента, где «лучший» определяет переданная функция. Хранится `result` — адрес лучшего на данный момент.

1. `size == 0` → `nullptr` (нечего сравнивать).
2. `result = array` (первый элемент), затем для `index = 1…size-1`: если `comes_before(*result, array[index])` истинна — текущий результат «уступает» новому элементу, и `result = &array[index]`.
3. Возвращается **указатель на элемент**, а не значение.

Сравнений `size - 1`, время $O(n)$, память $O(1)$. Возвращать указатель удобно: он отличает «не найдено» (`nullptr`) от любого значения и позволяет менять элемент.

@@ id=findbyorder-trace type=trace src="Функция как параметр алгоритма"
Q: Проследи `FindByOrder` для `{3, 1, 4}` с функцией `Less` (`left < right`): значения `*result` и условие на каждом шаге. Что вернётся для `size == 0`?
A:
| `index` | `*result` | `array[index]` | `Less(*result, array[index])` | `result` после шага |
| --- | --- | --- | --- | --- |
| старт | `3` | | | `&array[0]` |
| 1 | `3` | `1` | `3 < 1` — нет | `&array[0]` |
| 2 | `3` | `4` | `3 < 4` — да | `&array[2]` |

Возвращается указатель на `4`, `*FindByOrder(...)` печатает `4`. Для `size == 0` цикл не выполняется, возвращается `nullptr`, и `(FindByOrder(values, 0, Less) == nullptr)` — `true`, при выводе `1`. Разыменовывать такой результат нельзя.

@@ id=findbyorder-ties type=pitfall src="Функция как параметр алгоритма"
Q: В массиве `{4, 4}` `FindByOrder(values, 2, Less)` возвращает адрес первой или второй четвёрки? Что изменится, если вместо `Less` взять функцию `left <= right`?
A:
С `Less` (`left < right`): `Less(4, 4)` ложно, `result` не заменяется, возвращается `&array[0]` — **первая** четвёрка. Строгое сравнение оставляет первый из равных.

С `<=`: `4 <= 4` истинно, результат переезжает на `&array[1]` — вернётся **последняя** из равных.

Вывод: функция сравнения задаёт ещё и поведение на равных. Для порядка берут **строгое** сравнение (`<`, `>`): «нестрогое» делает ответ при равенстве неожиданным.

@@ id=comparison-switch type=code src="Выбор порядка сравнения"
Q: Что выведет программа и почему один и тот же указатель ведёт себя по-разному?
```cpp
bool Less(int left, int right) { return left < right; }
bool Greater(int left, int right) { return left > right; }

int main() {
    bool (*comes_before)(int, int) = Less;
    std::cout << comes_before(1, 2) << '\n';
    comes_before = Greater;
    std::cout << comes_before(1, 2) << '\n';
}
```
A:
Вывод: `1` и `0`.

Первый вызов — `Less(1, 2)`, то есть `1 < 2` — `true`, печатается `1`. После `comes_before = Greater;` тот же вызов `comes_before(1, 2)` означает `Greater(1, 2)`, то есть `1 > 2` — `false`, печатается `0`.

Вызов через указатель идёт туда, куда указывает **сейчас** указатель: переменную можно переназначить, и поведение изменится без правки кода, который её вызывает.

@@ id=less-greater-extremes type=concept src="Выбор порядка сравнения"
Q: Почему `FindByOrder` с `Less` находит максимум, а с `Greater` — минимум?
A:
Результат заменяется новым элементом, когда `comes_before(*result, x)` истинно — то есть когда текущий результат «стоит раньше» нового в заданном порядке.

- `Less`: заменяем, когда `*result < x`, — результат только растёт, в итоге **максимум**.
- `Greater`: заменяем, когда `*result > x`, — результат только убывает, в итоге **минимум**.

То есть алгоритм находит элемент, «стоящий последним» в порядке, который задаёт функция.

@@ id=extremes-code type=code src="Поиск максимума и минимума"
Q: Что выведет программа?
```cpp
int values[] = {5, 2, 9, 2};
std::cout << *FindByOrder(values, 4, Less) << ' '
          << FindByOrder(values, 4, Greater) - values << '\n';
```
(`FindByOrder`, `Less`, `Greater` — как в конспекте.)
A:
Вывод: `9 1`.

- С `Less` ищется максимум: результат проходит `5 → 9`, `*…` — `9`.
- С `Greater` ищется минимум: `5 → 2 (индекс 1)`; на `9` и на второй `2` замены нет (`2 > 9` и `2 > 2` ложны), результат — `&values[1]`. Разность указателей `&values[1] - values = 1`: вернулся адрес **первого** из равных минимумов.

@@ id=funcptr-why type=concept src="Поиск максимума и минимума"
Q: В чём главная идея передачи функции в алгоритм и какие есть современные альтернативы указателю на функцию?
A:
Алгоритм (`FindByOrder`) пишется **один раз**, а то, что в нём меняется (порядок сравнения), отдаётся параметром. Без правки кода алгоритма получаем и максимум, и минимум, и поиск по любому другому признаку. Так же устроены `qsort` и `std::sort`, которым передают компаратор.

Указатель на функцию — самый простой способ, но у него нет «состояния» (нельзя захватить данные). В современном C++ для тех же целей используют функциональные объекты, лямбда-выражения и `std::function`.

@@ id=signal-read type=code src="Как прочитать объявление signal"
Q: Как читать объявление `void (*signal(int number, void (*handler)(int)))(int);`? Что принимает и что возвращает `signal`? Как записать его проще?
A:
Читаем **изнутри наружу**: `signal(int number, void (*handler)(int))` — функция с параметрами `number` (`int`) и `handler` (указатель на функцию `void(int)`). Всё это обёрнуто в `void (*…)(int)`: **результат** — указатель на функцию `void(int)`.

Итого: `signal` принимает номер и указатель на обработчик, возвращает указатель на функцию того же типа, что `handler`. С псевдонимом читается проще — тот же тип, та же сигнатура:

```cpp
using Handler = void (*)(int);
Handler signal(int number, Handler handler);
```

@@ id=signal-write type=code src="Как прочитать объявление signal"
Q: Объяви функцию `GetOperation`, которая принимает `char symbol` и возвращает указатель на функцию `int (int, int)`. Дай запись «сырую» и через `using`.
A:
Через псевдоним (читается легко):

```cpp
using BinaryOperation = int (*)(int, int);
BinaryOperation GetOperation(char symbol);
```

«Сырая» запись — тип результата «обёрнут» вокруг имени и параметров:

```cpp
int (*GetOperation(char symbol))(int, int);
```
Порядок тот же, что у `signal`: имя с параметрами `GetOperation(char symbol)` стоит внутри `(* … )`, а за скобками — параметры возвращаемого указателя `(int, int)`; слева — его возвращаемый тип `int`.
