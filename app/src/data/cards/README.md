# Карточки для самопроверки: как их писать

Карточки к конспектам М3102 — это проверка понимания, а не «найди слово в тексте». Если человек ответил верно на **все** карточки конспекта, он должен
понимать весь его материал: определения, теоремы с условиями, алгоритмы с обоснованием, умеет считать и видит типичные ловушки. Поэтому карточек
должно хватать на **всю теорию** конспекта, и каждая — осмысленная. Образец уровня: `Алгоритмы_и_структуры_данных/Практика_3/Мастер-Теорема.md`
(17 карточек на конспект в 8 тысяч знаков) — открой его первым.

Читай только то, что нужно для работы: этот файл, конспект (или PDF) своего предмета и образец. Остальной проект читать не нужно.

## Где лежит файл

`app/src/data/cards/<путь конспекта без «Конспекты/»>.md` — тот же путь, что у конспекта, и то же имя:

| Конспект                                                                | Файл карточек                                                                           |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `Конспекты/Алгоритмы_и_структуры_данных/Лекция_3/Быстрая_сортировка.md` | `app/src/data/cards/Алгоритмы_и_структуры_данных/Лекция_3/Быстрая_сортировка.md`        |
| `Конспекты/ДМ/Коллоквиум/Банк_вопросов.pdf` (PDF)                       | `app/src/data/cards/ДМ/Коллоквиум/Банк_вопросов.pdf.md` (к имени PDF добавляется `.md`) |

PDF, у которого в той же папке есть `.md` (дубль), карточек не получает — они делаются по `.md`. PDF без текста (скан) пропускаем.
`npm run cards:todo -- <часть пути>` показывает, куда класть файл и по каким разделам нужны карточки.

## Формат

```text
@@ id=scheme type=concept src="Общий вид рекурсивного алгоритма"
Q: Что описывает рекуррентность $T(n) = a\,T(n/b) + f(n)$?
A:
Ответ в Markdown: абзацы, списки, таблицы, формулы $...$ и $$...$$, блоки кода и схемы.

@@ id=next-card type=calc src="Дерево рекурсии"
Q: …
A:
…

@@skip src="Список литературы" reason="только ссылки, учебного материала нет"
```

- Карточка начинается строкой `@@` в начале строки: `id` (латиница, цифры, дефис; уникален в файле; **не меняй id у готовых карточек** — по нему хранится прогресс),
  `type` (ниже), `src`. Дальше `Q:` (вопрос может занимать несколько строк) и `A:` (ответ до следующей карточки).
- `src` — **заголовок раздела конспекта** (текст заголовка, оформление и регистр не важны) или у PDF `Стр. 5` / `Стр. 5–7`. По `src` карточка привязана к месту
  в конспекте: после занятия человеку предлагают перечитать именно эти разделы. Нужен любой заголовок, под которым материал, — хоть `###`, хоть `####`.
  Если одинаковые заголовки повторяются («Пример»), пиши `Родитель :: Пример`.
- `@@skip` — раздел, где учебного материала нет (титул, литература, организационное). Причина обязательна; пропусков должно быть мало.
  `@@skip src="*" reason="…"` — весь конспект без карточек, если он дубль другого (например, второй вариант того же PDF); файл тогда состоит только из этой строки.
- Внутри блоков кода (```) строки `@@`, `Q:`, `A:` ничего не значат.
- Файл начинается либо с карточки, либо с комментария `<!-- … -->`. Любой другой текст вне карточки — ошибка.

## Типы карточек (`type`)

| type      | Что спрашиваем                                                     | Хороший вопрос                                                               |
| --------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `term`    | термин и его определение, чем отличается от соседнего              | «Что такое устойчивая сортировка и чем она отличается от inplace?»           |
| `concept` | идея, смысл, «зачем», «почему так»                                 | «Зачем нужен опорный элемент и что будет, если он всегда минимальный?»       |
| `theorem` | формулировка с **условиями** и выводом, смысл условий              | «Сформулируй мастер-теорему: при каких условиях применима и три случая»      |
| `proof`   | ключевые шаги доказательства, на чём оно держится                  | «Докажи, что сравнения не могут сортировать быстрее $\Omega(n\log n)$»       |
| `algo`    | как работает алгоритм: идея, инвариант, шаги, сложность и почему   | «Как работает разбиение Хоара, какой у него инвариант?»                      |
| `trace`   | прогон на конкретных данных по шагам                               | «Выполни сортировку подсчётом для $[3,1,3,0]$: массивы $C$ и результат»      |
| `calc`    | вычислить / оценить / решить, ответ с полным ходом решения         | «Оцени $T(n)=7T(n/2)+n^2$»                                                   |
| `compare` | сравнить два-три объекта по осям, выбрать подходящий               | «Сравни Merge/Quick/Heap sort: время, память, устойчивость, когда что брать» |
| `code`    | код: что выведет, найти ошибку, дописать, объяснить строку         | «Что выведет программа и почему?»                                            |
| `pitfall` | типичная ошибка, граничный случай, контрпример, когда не применимо | «В каком случае мастер-теорема неприменима и что делать?»                    |

## Что делает карточку хорошей

1. **Одна карточка — один вопрос.** Не «расскажи всё про сортировки», а «какой инвариант у разбиения Ломуто». Большая тема — набор карточек.
2. **Спрашиваем понимание.** Плохо: «Закончи фразу: Quick Sort — это …», «Что написано в конспекте про кучу?», «Как называется …?» без содержания. Хорошо: «Почему куча
   строится за $O(n)$, а не за $O(n\log n)$?», «Что нарушится, если в LSD-сортировке подсортировка неустойчива?».
3. **Ответ самодостаточен:** можно сверить свой ответ, не открывая конспект. Формулировка с условиями, формула с пояснением обозначений, вывод по шагам, ответ в числах.
   Развёрнуто, но по делу: ориентир 3–12 строк, сложное — до 40.
4. **Условия и границы.** У теоремы — когда она применима и что без условия ломается; у алгоритма — когда не работает; у формулы — область применения.
5. **Алгоритм — это набор карточек** (шаблон «досье»): идея и зачем; инвариант / корректность; шаги или псевдокод; прогон на маленьком примере; сложность по времени и памяти **с
   выводом**; когда применять и чем заменить; типичные ошибки и граничные случаи. Для каждого алгоритма из конспекта.
6. **Теормины и определения:** определение → пример → **не-пример** → связь со смежным понятием. Не только «термин ↔ определение».
7. **Вычислительные карточки** (`calc`, `trace`) — с настоящими числами и полным ходом решения. Берём примеры и задачи из конспекта; можно добавить свои стандартные (они
   должны быть верны и проверяемы).
8. **Схемы в ответах там, где они объясняют:** дерево рекурсии, граф и обход, блок-схема, прогон массива, график. Не ради украшения.
9. **Факты — только из конспекта (или PDF)** и стандартная проверяемая математика/программирование. Не выдумывай ни определений, ни чисел. Если в конспекте ошибка или
   неясность — не копируй её: либо пропусти место, либо в ответе формулируй верно и коротко отметь «в конспекте иначе».
10. **Только учебное.** Без баллов, разбалловки, правил сдачи, фамилий преподавателей, дедлайнов. Организационные слова проверка подсвечивает предупреждением.
11. **Язык — русский,** термины и идентификаторы как в конспекте (`Quick Sort`, `std::vector`). Формулы — в `$…$`. Код — в блоках с языком.

## Схемы в ответах

Блоки те же, что в конспектах (README группы, раздел «Диаграммы»); проверка `cards:check` убеждается, что они **строятся**. Короткая шпаргалка:

````text
```tree
tree
Корень
  Левый
  Правый
```

```graph
graph directed
layout: circle
A -> B : 5
B -> C
```

```diagram
diagram
A: round "Старт"
B: diamond "x > 0?"
C: box "Действие"
D: note "Пояснение"
A -> B
B -> C : да
```

```array
title: Сортировка вставками
[6, 3, 8, 2, 5]
pointers: i, j
print: last
code:
for (let i = 1; i < a.length; i++) {
  let key = a[i];
  let j = i - 1;
  while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j = j - 1; }
  a[j + 1] = key;
  done(0, i);
}
```
````

`array` с `code:` показывает прогон алгоритма **по шагам** с кнопками — идеально для карточки `trace`/`algo` (примеры — в `Конспекты/Алгоритмы_и_структуры_данных/Лекция_2/…`, ищи `^code:`).
Ещё есть `plot` (графики функций), `chart`, `canvas`; `mermaid` тоже рисуется, но проверка его не разбирает — проверь синтаксис сам.

## Покрытие: «вся теория»

`npm run cards:todo -- <часть пути>` разбирает конспект на **единицы покрытия** — подразделы (`###`), а у раздела без подразделов — сам раздел (титул `#` не считается) — и показывает, по каким
из них карточек ещё нет. Цель — `покрыто N/N`. Покрытие — минимум: если в разделе три определения и две теоремы, карточек должно быть столько, чтобы спросить каждое. Для PDF единицы — страницы с текстом.

Не набивай карточки ради счётчика: раздел без нового материала лучше пропустить через `@@skip` с честной причиной, чем писать пустышку.

## Как работать

1. `npm run cards:todo -- <предмет или часть пути>` — что осталось (таблица по конспектам; с узким фильтром — ещё и список разделов).
2. Прочитай конспект целиком (`.md`) или `npm run cards:pdf -- <часть имени PDF> [--pages 3-6]` — текст PDF по страницам.
3. Создай файл карточек по этому формату. Один конспект — один файл. Пиши по разделам в порядке конспекта.
4. `npm run cards:todo -- <часть пути>` — должно быть `покрыто N/N`, ни одной `ОШИБКИ`; предупреждения («внимание») прочитай и исправь, если они по делу.
5. `npm run cards:check` — проверка форматов и схем по всем файлам (тот же прогон ловит CI). Должен проходить без ошибок.
6. Не запускай сборку, сайт, e2e и весь набор тестов: для карточек они не нужны и дорогие.

## Перед тем как сдать файл

- [ ] каждая карточка отвечает на вопрос «а что именно проверяем?» — не пересказ абзаца, а понимание;
- [ ] у теорем есть условия, у алгоритмов — обоснование сложности, у формул — обозначения;
- [ ] вычисления доведены до числа/вывода; примеры проверены вручную;
- [ ] нет организационного, нет выдумок, нет копирования ошибок конспекта;
- [ ] схемы строятся, формулы в `$…$`, блоки кода закрыты;
- [ ] `cards:todo` — `покрыто N/N`, `cards:check` — зелёный.
